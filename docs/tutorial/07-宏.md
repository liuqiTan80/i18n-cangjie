# 07 宏

目标：定义与调用过程宏，理解宏包、`引用`（quote）插值与两步编译。

> 宏是仓颉 1.0 的进阶特性。本章示例需要**宏包**目录结构，建议先 `zhc init` 建项目再操作。

## 7.1 宏是什么

宏在**编译期**执行：接收代码片段（`Tokens`），产出新的代码。zhc 方言中宏调用写作 `@宏名(...)`，
宏名可以是母语名（语言包「宏」节映射，如 `@调试日志`）。

## 7.2 定义一个宏：宏包

宏必须定义在**宏包**中（源码首行 `宏 包 <名>`）：

```cangjie
// define/define.cj —— 宏包（注意：这是官方仓颉文件，宏包内写官方语法）
宏 包 define

公开 宏 调试日志(input: Tokens): Tokens {
    让 名字 = 输入.toString()
    引用(打印行($(名字)))
}
```

要点（仓颉 1.0 宏规则）：

- 首行 `宏 包 <包名>` 声明宏包；宏包只暴露宏；
- `公开 宏 名字(输入: Tokens): Tokens` ——参数与返回都必须是 `Tokens`；
- `引用(...)`（quote）构造输出代码；`$(表达式)` **只在代码位置插值**：
  - 字符串等基本类型 → 插入为字面量 token；
  - `Tokens` 变量 → 直接嵌入代码；
- 注意 `$(输入.toString())` 插进字符串字面量**不会**被替换——插值只发生在代码位置。

## 7.3 两步编译

宏包与主程序分两步编译（zhc 的 `expand` 教学视图会自动完成这两步）：

```bash
cjc define/define.cj --compile-macro     # ① 编译宏包 → define.cjo + lib-macro_define.so
cjc main.cj -o main                      # ② 编译主程序（import define.* 自动展开）
```

主程序先 `导入 define.*` 再调用宏：

```cangjie
导入 define.*;

主函数() {
    让 x = 3
    让 y = 4
    @调试日志(x + y)          // 编译期展开为：打印行("x + y")
}
```

运行输出：`x + y`（宏展开后字符串里是表达式的**文本**，不是值）。

## 7.4 宏展开教学视图：zhc expand

用 `zhc expand` 查看展开前/后对照（官方 + 反向母语三栏视图，位置映射回方言坐标）：

```bash
zhc expand main.zc --macro-pkg define/
```

输出示意：

```
┌ 展开前（main.zc:6）      │ 展开后（官方）              │ 展开后（方言）
│ @调试日志(x + y)         │ /* ===== Emitted by ... */ │ /* ===== Emitted ... */
│                          │ println("x + y")           │ 打印行("x + y")
```

`--debug-macro` 生成的 `.macrocall` 文件里有每个展开区的行:列标记，expand 据此定位。

## 7.5 引用插值进阶

`$(输入)` 嵌入调用者的完整表达式（`Tokens` 直接进代码）：

```cangjie
// define/define.cj
公开 宏 断言非零(输入: Tokens): Tokens {
    引用(
        如果 ($(输入) == 0) {
            抛出 异常("表达式为零")
        }
    )
}
```

```cangjie
导入 define.*;

主函数() {
    @断言非零(1 + 1)      // 展开为：如果 (1 + 1 == 0) { 抛出 异常("表达式为零") }
}
```

> 注意：`$(表达式)` 只作用于**代码位置**。写在字符串字面量里（如 `"${$(名字)}"`）不会插值，而是原样输出文本。

## 7.6 系统宏：@测试 与 @期望

仓颉标准库自带测试框架（`std.unittest`），用 `@测试` 标记测试函数、`@期望` 断言：

```cangjie
导入 标准测试宏.*
导入 标准测试.*

@测试
公开 函数 加法正确() {
    @期望(加法(2, 3), 5)   // 期望表达式的结果为 5
}
```

要点：

- **两个通配符导入都要写**：`标准测试宏`（测试框架宏本体）与 `标准测试`（断言等运行时类型），缺一不可（1.0.5 实测）；
- `@期望(实际值, 期望值)` 宏展开为完整断言代码，失败时给出两侧值；
- `@测试` 标记的函数由框架自动收集执行，无需手动调用。

`zhc test` 在项目根一键运行全部方言测试（转译 → `cjpm test` → 母语化输出）：

```bash
zhc test
```

```
[ 通过 ] 用例： 加法正确
汇总：共 2；通过： 2, 跳过： 0, 错误： 0, 失败： 0
```

## 练习

1. 写一个 `@打印表达式` 宏：展开为 `打印行("<表达式文本> = " + <表达式值>)`；
2. 用 `zhc expand` 查看自己宏的展开视图，确认位置映射；
3. 在语言包 `crates/<库>.toml` 的「宏」节给宏加母语名（如 `调试日志` → `@调试日志`）。

## 小结

- 宏包首行 `宏 包 <名>`，宏签名 `(Tokens) -> Tokens`，调用 `@宏名(...)`；
- 两步编译：`cjc 宏包 --compile-macro` → `cjc 主程序`；
- `引用()` 构造代码，`$(...)` 只在代码位置插值；
- `zhc expand` 提供展开教学视图（含反向母语）。
