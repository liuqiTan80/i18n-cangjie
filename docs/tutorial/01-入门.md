# 01 入门：环境搭建与第一个程序

> 本章目标：从**零环境**开始，一步步搭好 zhc 方言开发环境，写出并运行第一个中文程序。
> 读完本章你能回答：zhc 是什么？依赖什么？怎么装？报错了怎么办？

## 1.1 zhc 是什么：先看全貌

zhc（中文仓颉）是官方仓颉语言的**转译代理**。方言代码（`.zc` 文件，全中文关键字）先被转译成官方仓颉（`.cj`），再交给官方编译器 `cjc` 编译运行：

```
你的方言源码 hello.zc
        │  zhc 转译（查语言包词表，逐词替换）
        ▼
官方仓颉源码 .zhc/hello.cj
        │  cjc 编译（官方编译器，报错被 zhc 翻译成中文）
        ▼
可执行程序（运行输出中文结果）
```

三个关键部件：

| 部件 | 作用 | 谁提供 |
|---|---|---|
| **语言包**（lang-packs） | 方言词表：`函数`→`func`、`打印行`→`println`…… | zhc 仓库自带（`zhc/lang-packs/zh/`） |
| **转译器**（zhc 本体） | 查表替换 + 上下文保护 + 诊断翻译 | 本项目（需构建） |
| **官方编译器**（cjc/cjpm） | 把转译结果编译成可执行程序 | 华为仓颉官方 SDK |

**所以装 zhc 需要两样东西**：① 官方仓颉 SDK（cjc/cjpm）；② zhc 本体（源码构建或离线包）。本章 1.4 节把这两步写到「照着敲就能成功」的粒度。

## 1.2 前置知识（零基础友好）

- **命令行**：Linux 的「终端」（Terminal）里输入命令、按回车执行。本教程所有 `代码块` 都在终端里输入。
- **环境变量**：给程序传配置的「全局便签」。`export 名字=值` 设置后，本终端（及它启动的程序）都能读到。写进 `~/.bashrc` 则每次开终端自动生效。
- **PATH**：告诉系统「命令去哪找」。敲 `cjc` 时系统按 PATH 里列出的目录逐个找。
- **LD_LIBRARY_PATH**：告诉系统「动态库去哪找」。仓颉程序运行时需要 `libcangjie-runtime.so`，找不到就报 `error while loading shared libraries`。

> 💡 这些概念不用背——本章 1.4 会把要敲的命令全部给出，你只需要**复制 → 回车 → 看结果**。

## 1.3 两种安装方式，怎么选

| 方式 | 适合 | 前提 |
|---|---|---|
| **A. 源码构建**（1.4 节，推荐） | 想自己动手、了解工具链、跟随本项目开发 | 已装官方 SDK + git，有网络 |
| **B. 离线发布包**（1.5 节） | 快速上手、无网络教学环境 | 有发布包（`scripts/release.sh` 可自产） |

两种方式最终效果一样：得到一个 `zhc` 命令。建议按 A 走一遍——它顺带教会你「仓颉项目是怎么构建的」，这正是本章「细而全」的意义。

## 1.4 方式 A：本地源码构建（逐步操作）

> 本节按「本机实测通过」的真实步骤编写（环境：Linux x86_64 + 仓颉 SDK 1.0.5）。
> 每一步都给出**验证方法**：跑完能看见什么。任何一步的输出对不上，去 1.6 排查表找答案。

### 步骤 0：检查本地环境（3 分钟）

打开终端，逐条输入并核对：

```bash
uname -m          # 期望输出 x86_64（zhc 当前支持 64 位 Linux）
bash --version | head -1   # 期望输出 GNU bash，版本 ≥ 4
git --version     # 期望输出 git version 2.x（没有则：sudo apt install git）
```

缺什么装什么（Ubuntu/Debian 示例；其他发行版用对应包管理器）：

```bash
sudo apt update && sudo apt install -y git
```

> **设计思想：环境可复现**——软件工程第一课：构建环境是「文档化的」。把环境要求写下来（版本、路径、变量），换台机器也能照着重现，这就是可复现构建的起点（详见第 11 章）。

### 步骤 1：安装官方仓颉 SDK（10 分钟）

从华为仓颉官方渠道下载 Linux x86_64 的 SDK 压缩包（含 cjc 编译器、cjpm 包管理器、运行时库、标准库）。解压到任意目录，本教程统一用 `~/ruanj/cangjie`：

```bash
mkdir -p ~/ruanj
tar -xzf 下载的仓颉SDK压缩包.tar.gz -C ~/ruanj
mv ~/ruanj/解压出的目录名 ~/ruanj/cangjie    # 统一目录名，方便后面写路径
```

解压后确认 SDK 布局（**后面的路径全靠它**）：

```
~/ruanj/cangjie/
├── bin/                        # 编译器
│   └── cjc                     # 仓颉编译器（zhc 靠它编译）
├── tools/
│   └── bin/
│       └── cjpm                # 包管理器（构建 zhc 本体、管理项目依赖）
├── runtime/
│   └── lib/linux_x86_64_cjnative/
│       └── libcangjie-runtime.so   # 运行时动态库（运行任何仓颉程序都要）
└── tools/lib/                  # 构建期库（编译时需要）
```

> ⚠️ 常见误区：SDK 里 `bin/` 只有 `cjc`，`cjpm` 在 `tools/bin/` 下——两个都要进 PATH（下一步）。

### 步骤 2：配置环境变量（3 分钟）

把下面三段追加到 `~/.bashrc`（用你喜欢的编辑器打开，或 `cat >>` 追加）：

```bash
# ---- 仓颉 SDK ----
export CANGJIE_HOME="$HOME/ruanj/cangjie"
export PATH="$CANGJIE_HOME/bin:$CANGJIE_HOME/tools/bin:$PATH"
export LD_LIBRARY_PATH="$CANGJIE_HOME/runtime/lib/linux_x86_64_cjnative:$CANGJIE_HOME/tools/lib:${LD_LIBRARY_PATH:-}"
```

逐条解释（**为什么这么写**）：

| 变量 | 作用 | 不设会怎样 |
|---|---|---|
| `CANGJIE_HOME` | SDK 根目录的「约定俗成」路径（release 脚本等用它定位） | 部分工具找不到 SDK |
| `PATH` | 让 `cjc`、`cjpm` 命令可直接敲 | 报 `cjc: command not found` |
| `LD_LIBRARY_PATH` | 让运行时找到 `libcangjie-runtime.so` | 报 `error while loading shared libraries: libcangjie-runtime.so` |

让配置立即生效：

```bash
source ~/.bashrc
```

### 步骤 3：验证 SDK（1 分钟）

```bash
cjc --version
# 期望输出：Cangjie Compiler: 1.0.5 (cjnative)

cjpm --version
# 期望输出：Cangjie Package Manager: 1.0.5
```

> 版本号 ≥ 1.0.5 即可（zhc 按 1.0.5 实测适配）。看到版本号 = SDK 就绪。

### 步骤 4：获取 zhc 源码（2 分钟）

```bash
git clone <本项目仓库地址> ~/code/zwCangjie
cd ~/code/zwCangjie/zhc
```

源码结构（后面会用到）：

```
zhc/
├── cjpm.toml          # 包配置（版本、依赖）
├── src/               # zhc 本体源码（仓颉写的！）
├── lang-packs/zh/     # 中文语言包（方言词表本体）
│   ├── keywords.toml      # 关键字：函数→func
│   ├── stdlib.toml        # 标准库别名：打印行→println
│   ├── module_paths.toml  # 模块路径：标准集合→std.collection
│   ├── errors.toml        # 错误消息：645 条诊断码中文模板
│   └── stdlib_meta.toml   # 标准库元数据
├── examples/          # 示例程序
└── target/            # 构建产物（第 5 步生成）
```

> **设计思想：方言即配置**——注意语言包是**数据文件**不是代码。换一套词表就是一门新方言（比如换英文词表就是「English dialect」）。转译引擎与词表解耦，这是 zhc 的架构核心（第 10 章详述）。

### 步骤 5：构建 zhc 本体（3~10 分钟）

```bash
cjpm build
```

首次构建会下载/编译依赖，耐心等。成功标志：产物出现且可执行——

```bash
ls -l target/release/bin/main
# 期望输出：-rwxr-xr-x ... target/release/bin/main
```

**构建产物叫 `main`**（仓颉包构建的默认产物名），它就是 zhc 本体。先给它起个好听的名字并放进 PATH：

```bash
mkdir -p ~/.local/bin
cp target/release/bin/main ~/.local/bin/zhc
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

> 不复制也行：以后用绝对路径 `/你的路径/zwCangjie/zhc/target/release/bin/main`，或设别名。复制到 `~/.local/bin` 是最省心的做法。

### 步骤 6：让 zhc 找到语言包（2 分钟）

zhc 按以下顺序找语言包（**任中一个成立即可**）：

1. 环境变量 `ZHC_LANG_PACKS`（指向**含 lang-packs/ 的目录**，即仓库根 `~/code/zwCangjie/zhc`）；
2. 当前目录下的 `./lang-packs/`；
3. 可执行文件旁的 `lang-packs/`（离线包就是利用这一条，见 1.5）；
4. 用户目录 `~/.zhc/lang-packs/`。

给源码构建的 zhc 装语言包，推荐第 1 条（显式、不依赖运行目录）：

```bash
echo 'export ZHC_LANG_PACKS="$HOME/code/zwCangjie/zhc"' >> ~/.bashrc
source ~/.bashrc
```

或者把语言包复制到 `~/.zhc/lang-packs/`（第 4 条，全局生效）：

```bash
mkdir -p ~/.zhc
cp -r ~/code/zwCangjie/zhc/lang-packs ~/.zhc/
```

### 步骤 7：验证安装（1 分钟）

```bash
zhc --help
```

看到中文帮助（`zhc init 生成项目骨架`、`zhc run 转译并运行`……）即安装成功。再跑一个真实程序：

```bash
cd ~/code/zwCangjie/zhc/examples
zhc run hello.zc
```

期望输出：

```
✅ 编译成功：替换方言标识符 2 处。
你好，仓颉！
```

> 到这里，你的「本地源码构建」全流程走通了：SDK → 环境变量 → 源码 → 构建 → 部署 → 运行。
> 每一步都可在 1.6 排查表里找到失败对策。

## 1.5 方式 B：离线发布包（解压即用）

发布包是「自包含」的：二进制 + 运行时库 + 语言包打成一个压缩包，**不需要**单独装 SDK 环境变量：

```
zhc-0.1.0-linux-x86_64/
├── bin/
│   ├── zhc          # 启动脚本（自动设置 LD_LIBRARY_PATH → 运行 zhc-core）
│   └── zhc-core     # zhc 主程序
├── lib/             # 仓颉运行时动态库（随包携带）
├── lang-packs/      # zh + en 语言包（exe 旁，定位链第 3 条自动命中）
└── README.md
```

```bash
tar -xzf zhc-0.1.0-linux-x86_64.tar.gz
export PATH="$PWD/zhc-0.1.0-linux-x86_64/bin:$PATH"
zhc --help        # 立即可用
```

自产发布包（项目维护者视角，第 8 章还会讲）：

```bash
cd ~/code/zwCangjie && bash scripts/release.sh   # 产物：zhc/dist/zhc-0.1.0-linux-x86_64.tar.gz
```

## 1.6 常见问题排查表（照着查）

| 症状（看到的报错） | 原因 | 解决 |
|---|---|---|
| `cjc: command not found` | SDK 的 `bin/` 没进 PATH | 检查 `~/.bashrc` 的 PATH 行；`source ~/.bashrc` 后重试 |
| `cjpm: command not found` | SDK 的 `tools/bin/` 没进 PATH（cjpm 不在 bin/！） | 同上，确认两段都加了 |
| `error while loading shared libraries: libcangjie-runtime.so` | `LD_LIBRARY_PATH` 没设 | 补上 `runtime/lib/linux_x86_64_cjnative`（步骤 2 第三行） |
| `未找到语言包 zh：请设置 ZHC_LANG_PACKS……` | 语言包四位置都没命中 | 步骤 6 任选一种（推荐 `ZHC_LANG_PACKS` 或 `~/.zhc/lang-packs`） |
| `An exception has occurred: ProcessException: Created process failed` | cjc 不在 PATH（zhc 调 cjc 走 PATH） | 确认 `cjc --version` 能跑通 |
| `bash: zhc: command not found` | `~/.local/bin` 没进 PATH | 检查步骤 5 的 PATH 追加是否执行、`ls ~/.local/bin/zhc` 是否存在 |
| 构建时报 `package xxx not found` | cjpm 依赖未下载/网络问题 | 检查网络；`cjpm update` 后重试 |

> **软工知识：报错三问**——① 完整读报错（前 3 行往往就是答案）；② 用搜索引擎/错误字典搜**报错原文**（见第 9 章，zhc 的错误已翻译成中文）；③ 确认「刚才改了什么」——90% 的环境问题出在最近一次改动。

## 1.7 第一个程序：逐行讲解

新建 `hello.zc`：

```cangjie
// hello.zc —— 第一个方言程序
主函数() {
    打印行("你好，仓颉！")
}
```

运行：

```bash
zhc run hello.zc
```

输出：

```
✅ 编译成功：替换方言标识符 2 处。
你好，仓颉！
```

逐行拆解：

| 代码 | 官方对应 | 说明 |
|---|---|---|
| `// hello.zc ...` | `// ...` | 行注释，**不参与转译**（内容原样保留） |
| `主函数() {` | `main() {` | 程序入口。**不带**「函数」前缀——官方 `func main` 是语法错误，方言 `函数 主函数` 同样错误 |
| `打印行("你好，仓颉！")` | `println("你好，仓颉！")` | 打印一行并换行。`打印` = `print`（不换行） |
| `}` | `}` | 函数体结束 |

`zhc run` 的输出第一行「替换方言标识符 2 处」是转译统计：`主函数`→`main`、`打印行`→`println`，正好 2 处。**转译是词法级查表**，不是 AI 翻译——每处替换都可预期、可核对。

## 1.8 字符串保护与插值

**字符串与注释里的中文不会被误改**（转译器的保护机制）：

```cangjie
主函数() {
    打印行("函数 让 可变 打印行 —— 这些只是文本")
}
```

输出原样：`函数 让 可变 打印行 —— 这些只是文本`——不会报错。

**字符串插值 `${表达式}`** 是仓颉独有能力，方言直接支持，且插值段内的别名**会**继续转译：

```cangjie
主函数() {
    让 问候 = "你好"
    让 名字 = "小明"
    打印行("${问候}，${名字}！")   // 你好，小明！
    打印行("1 + 2 = ${1 + 2}")    // 1 + 2 = 3（插值里能算表达式）
}
```

> **设计思想：保护 vs 转译的分界线**——为什么字符串里不转、插值里转？因为字符串是「给人看的文本」，插值是「代码上下文」。这条分界线让中文关键字既不会误伤文本，又能出现在代码里——「中文即代码」的前提是「文本即文本」。

## 1.9 转译原理（知其所以然）

- **是什么**：zhc = 词法级转译器 + 诊断翻译器。方言源码 → 查表替换 → 官方 `.cj` → `cjc` 编译。
- **为什么**：不直接教官方仓颉？因为官方关键字的英文门槛（`func`/`let`/`match`）对新手是第二道坎。方言把「语言门槛」移除，让初学者把全部注意力放在**算法思维**上——用中文思考，用中文表达。
- **怎么验证**：`zhc eject hello.zc` 导出官方源码，自己对比转译结果（输出前会有一批 `⚠ 反向映射碰撞` 提示——语言包一词多译的正常现象，可忽略；看最后一行「已导出」与生成的 `hello.cj` 即可）：

```bash
zhc eject hello.zc    # 生成 hello.cj（官方仓颉）
cat hello.cj
```

```cangjie
// 导出的官方源码（节选）
main() {
    println("你好，仓颉！")
}
```

- **注意**：zhc **不是**新语言——每个词条都对应官方写法（本教程全程双写，方便对照官方文档）。它也不改变语义：转译前后程序行为完全一致。

## ✳ 本章的设计思想

1. **术语母语化（中文即代码）**：编程的认知负担分两层——算法思维（本来就是中文思维）与语言门槛（英文关键字）。方言移除第二层，这是整套教程的地基。
2. **错误提示中文（诊断即教学）**：编译器错误是学习的第一现场。zhc 把英文报错翻译成「中文 + 💡 提示 + 修复示例」三段式（第 9 章专讲）。
3. **方言即配置**：语言包是数据文件——转译引擎与词表解耦，方言可演进、可校验、可再造。
4. **环境可复现**：构建环境写进文档（本章 1.4 即「可复现构建」的活教材）；环境变量用显式 `export` 而非碰运气。

## 练习

1. 按 1.4 全流程在**新目录**（如 `~/practice`）重新构建一遍 zhc，不看教程独立完成；
2. 修改 hello.zc 打印你的名字，再用 `打印`（不换行）连打两段文字，观察与 `打印行` 的区别；
3. 在字符串里写满关键字运行，确认不被误改；再试试把词表词写进插值（`打印行("${函数}")`）——它会被转译成 `${func}` 而编译报错：**插值里只放变量和表达式，别放关键字**；
4. 故意删掉 `ZHC_LANG_PACKS` 并换个目录运行 `zhc run`，观察报错并对照 1.6 排查表。

## 小结

- zhc = 转译器（语言包驱动）+ 官方 cjc 编译，装环境 = 装 SDK + 装 zhc 本体；
- 源码构建五步：SDK → 环境变量（PATH/LD_LIBRARY_PATH）→ 源码 → `cjpm build` → 语言包；
- 入口 `主函数()`、输出 `打印行()`；字符串与注释受保护、插值 `${}` 内继续转译；
- 环境报错用 1.6 排查表：先读报错、再查原因、后动手。
