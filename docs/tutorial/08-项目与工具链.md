# 08 项目与工具链

> 本章目标：掌握代码的组织（包/可见性/依赖）与 zhc 的全部子命令——从单文件走向工程化，理解语言包机制与构建流水线。
> 读完本章你能回答：`公开` 和 `内部` 有什么区别？方言代码是怎么变成可执行程序的？语言包有哪些文件？

## 8.1 模块与包：代码的归属

**包（包 / package）**：代码的归属单位——文件首行声明它属于哪个包：

```cangjie
包 学校.教务
导入 标准核心.*

// 本文件属于 学校.教务 包
```

- 包 = 命名空间 + 可见性边界：同包内互相可见；跨包要 `导入` + 对方 `公开`；
- 包名惯例：小写/点分（`学校.教务`）；入口文件（含 `主函数`）通常归默认包或项目包；
- **宏包**（`宏 包`）是另一回事（见第 7 章）。

**导入（导入 / import）**：把其他包的名字「把门打开」，三种形态：

```cangjie
导入 标准集合.{向量}              // 只引入指定名字
导入 标准集合.{向量, 哈希映射}    // 引入多个
导入 标准集合.*                   // 引入全部（通配）
导入 数学.*                       // std.math：开方等数学函数
```

**注意**：导入未安装的包 → zhc 报「找不到包」**方言错误**（这是 zhc 自定义的错误码）；未使用的导入是**警告**（`zhc check`/`lint` 会提示）；通配导入可能名字冲突（同名时用 `包.名字` 限定）。

**可见性四级**（官方 1.0.5 的完整封装阶梯）：

| 关键字 | 可见范围 | 典型用途 |
|---|---|---|
| `公开` | 所有包 | **API 面**：给别人用的，改动要谨慎 |
| `内部` | 本包内 | 包内各文件互用的协作 API（顶层声明**默认**就是包内可见） |
| `私有` | 本文件内 | 实现细节，最严格封装 |
| `受保护` | 子类（跨包继承时子类可访问） | 给子类扩展用的钩子，配合 `开放`/`重写` |

```cangjie
包 学校

公开 函数 计算总分(成绩: 数组<整数>): 整数 {
    可变 总和 = 0
    对于 (分 in 成绩) { 总和 += 分 }
    返回 总和
}

私有 函数 内部辅助() { /* 只有本文件能用 */ }

主函数() { 内部辅助() }
```

**设计思想**：**默认私有**的可见性哲学——暴露给外部的是「API 面」，必须显式声明。这迫使设计者思考「哪些是给别人用的」：未公开的都是实现细节（以后随便改，不破坏任何人）。

## 8.2 创建项目：zhc init

```bash
zhc init 我的项目
cd 我的项目
```

生成结构：

```
我的项目/
├── cjpm.toml          # 包配置（cjc-version 自动探测当前编译器）
├── src/
│   └── main.zc        # 方言入口（主函数）
└── .gitignore
```

`src/main.zc` 初始内容：

```cangjie
主函数() {
    打印行("你好，仓颉！")
}
```

想让 cjpm 直接驱动方言项目（`cjpm build/run/test` 前自动转译方言源码）？加 `--native`：

```bash
zhc init --native 我的项目   # 额外生成 build.cj 构建钩子
```

生成结构多出 `build.cj`（cjpm 构建钩子：pre-build 阶段自动把 `src/` 下 `.zc` 转译为同名 `.cj`）；`zhc native` 即该钩子调用的内部命令，通常无需手动执行。

> zhc 项目用 `zhc init` 创建（方言入口 `.zc`）；官方项目用 `cjpm init`（`src/main.cj` 官方语法）——两者都能被 `zhc run` 运行。

## 8.3 运行与检查

```bash
zhc run src/main.zc         # 项目模式：转译整个 src/ 并运行
zhc run 任意路径/文件.zc     # 单文件模式（自动探测所在项目/工作区）
zhc check src/main.zc       # 只编译检查，不运行（CI 常用）
zhc check .                # 目录参数：自动探测项目/工作区
```

**构建流水线**（理解这条链，就理解了 zhc 的一切）：

```
方言源码 .zc → zhc 转译（查语言包词表）→ 官方源码 .cj → cjc 编译 → 二进制
```

- `zhc run` 的输出会显示「替换方言标识符 N 处」——转译统计；纯官方语法文件（`.cj`）无需转译；
- `zhc check` 输出**中文教学诊断**：类型不匹配、空安全、可变性、未解析导入等，每条附 💡 提示与可粘贴修复示例（详解见第 9 章）。

## 8.4 代码风格：zhc lint

```bash
zhc lint src/main.zc          # 风格检查 + cjlint 静态分析（母语报告）
zhc lint --fix src/main.zc    # 自动修复风格问题（参数顺序任意）
```

检查项与修复能力：

| 检查项 | 说明 | `--fix` 修复 |
|---|---|---|
| 全角标点 | 字符串/注释内豁免 | ✅ |
| 尾随空白 / CRLF | 行尾杂讯 | ✅ |
| 重复空行 | 排版整洁 | ✅ |
| 行长度 | >120 只报告不修复 | — |
| cjlint 静态分析 | 未使用变量、命名规范等建议，位置映射回方言源码 | — |

## 8.5 添加依赖：zhc add

```bash
zhc add libdemo           # 编辑 cjpm.toml [dependencies]
```

依赖声明在 `cjpm.toml`（仓颉没有 cargo 式注册表，路径依赖为主）：

```toml
[dependencies]
libdemo = { path = "../libdemo" }
```

```bash
cjpm fetch      # 拉取声明的依赖
cjpm update     # 更新到最新兼容版本
```

**注意**：zhc 语言包的「找不到包」诊断（`package_search_error`）就是依赖缺失的友好提示；依赖版本用语义化版本（`0.1.0`、`^1.2`）；**可复现构建**——别人 clone 项目后 `cjpm fetch` 一条命令装齐依赖。

## 8.6 项目与工作区

- **项目**：`src/` 下有 `.zc` 文件的目录（`cjpm.toml` + `src/main.zc`）；
- **工作区**：根 `cjpm.toml` 含 `[workspace]` 节 → 多模块仓库，`zhc run/check` 自动转译全部成员并按模块输出诊断；
- **目录参数**：`zhc check .` 自动探测项目/工作区——不用记路径，交给工具。

## 8.7 方言测试：zhc test

```bash
zhc test                  # 项目根运行全部方言测试（workspace 成员根亦可）
```

流程：转译 `src/` 全部方言源码到 `.zhc-test/` → `cjpm test` → 输出母语化。测试函数用 `@测试` 标记、`@期望` 断言（见第 7 章 7.7 节）：

```cangjie
导入 标准测试宏.*
导入 标准测试.*

函数 加法(甲: 整数, 乙: 整数): 整数 { 返回 甲 + 乙 }

@测试
公开 函数 加法正确() {
    @期望(加法(2, 3), 5)
}
```

```
[ 通过 ] 用例： 加法正确
汇总：共 2；通过： 2, 跳过： 0, 错误： 0, 失败： 0
```

## 8.8 宏展开与导出：zhc expand / zhc eject

```bash
zhc expand src/main.zc --macro-pkg ../define   # 宏展开教学视图（三栏对照）
zhc eject src/main.zc                          # 导出官方 .cj 源码
```

- `expand`：展开前 / 展开后官方 / 展开后方言三栏，位置映射回 `.zc` 坐标，用于教学与调试宏；
- `eject`：导出纯官方仓颉代码——**可脱离方言独立编译**；输出一批「⚠ 反向映射碰撞」警告是语言包一词多译的正常现象，**可忽略**（看最后一行「已导出」与生成的 `.cj` 即可）。

## 8.9 LSP 与 IDE

```bash
zhc lsp                   # 启动 LSP 代理（行帧协议，供编辑器连接）
```

- 官方 LSPServer 可用：语言能力转发 + 自跑 cjc 诊断（混合档）；
- 官方不可用：自动降级为仅诊断档，不报错；
- VS Code 扩展（tools/vscode-extension/）提供高亮、右键运行/检查、全角转换。

## 8.10 语言包与映射：zhc lang / zhc mapping

**语言包机制**：方言词表按「语言包」组织——`zhc/lang-packs/zh/` 下 5 个 TOML：

| 文件 | 内容 |
|---|---|
| `keywords.toml` | 关键字映射（`"函数" = "func"`、`"让" = "let"`） |
| `stdlib.toml` | 标准库别名（`打印行` → `println`） |
| `module_paths.toml` | 模块路径（`标准集合` → `std.collection`） |
| `errors.toml` | 错误消息（645 条诊断码 = 官方 644 + 方言自定义 1） |
| `stdlib_meta.toml` | 标准库元数据 |

**为什么**：**转译即查表**——方言不是新语言，而是「词表驱动的重写规则」：查表替换 + 上下文保护（字符串不误改、声明名豁免、插值保护）。语言包可扩展意味着**新方言可以自己造**——换成别的语言词表就是另一种方言。

```bash
zhc lang list             # 列出可用语言包
zhc lang info zh          # 查看 zh 语言包信息
zhc mapping check         # 语言包质量门禁（五项检查）
zhc mapping auto 库目录    # 从库源码提取公开 API 生成 crates/<库>.toml
zhc mapping scaffold en zh # 以 en 为源生成 zh 翻译骨架
```

**注意**：`ZHC_LANG_PACKS` 环境变量指向语言包目录（默认查找链：`ZHC_LANG_PACKS` → `./lang-packs` → exe 旁 → `~/.zhc/lang-packs`，见第 1 章）；语言包是**双向映射**（转译 + 反向映射用于错误提示/expand 视图）；词表缺失时走「原文回退 + 记录」闭环（`zhc mapping check --missing` 可查）。

## 8.11 子命令总览

```bash
zhc init <目录>    创建项目          zhc run [文件|目录]   转译并运行
zhc check [文件]   检查（不运行）     zhc lint [--fix]     代码风格
zhc eject [文件]   导出官方 .cj      zhc add <库>         添加依赖
zhc lang list|info 语言包管理        zhc mapping check|auto|scaffold  映射工具链
zhc expand <文件>  宏展开教学视图     zhc test             方言测试
zhc native         构建钩子内部命令   zhc lsp             LSP 代理
```

## ✳ 设计思想

**① 可见性是封装阶梯**：`公开` → `内部` → `私有` → `受保护`，从「全开放」到「全隐藏」。设计 API 时从最严开始：先 `私有`，有需要再逐步开放——缩小「可破坏面」是长期可维护性的关键（信息隐藏原则，见第 11 章）。

**② 约定目录 + 声明配置**：项目 = `cjpm.toml` + `src/`。构建工具按**约定**找源码（不用告诉它目录），按**声明**拿配置（依赖、版本）。这就是工程化的起点：机器可复现，人可读。

**③ 可复现构建**：`cjpm.toml` 声明依赖与版本 + `cjpm fetch` 一键装齐——新成员/新机器 5 分钟进入开发状态。这是软件工程「环境可复现」（见第 1 章）在项目层面的落地。

**④ 词表驱动的方言哲学**：zhc 不是「翻译官方仓颉」，而是「用词表重新表述仓颉」——语言包可插拔，新方言 = 新词表。理解这个设计，你就理解了为什么改词表能造出新语言、为什么诊断能翻译、为什么 `.cj` 文件能原样通过。

## 练习

1. `zhc init` 建项目，写一个多文件程序：`包 工具` 声明一个 `公开` 工具函数，主文件 `导入` 它；
2. 验证可见性：把工具函数改成 `私有`，观察跨文件导入报什么错；
3. `zhc lint` 制造几个风格问题（全角标点、尾随空格）并 `--fix`；
4. `zhc mapping check` 验证当前语言包质量门禁；
5. `zhc eject` 导出项目源码，用 `cjc` 直接编译导出的 `.cj` 验证可脱离方言。

## 小结

- 包 = 命名空间 + 可见性边界；可见性四级：`公开`/`内部`/`私有`/`受保护`，顶层默认包内可见；
- `init`/`run`/`check`/`lint`/`eject`/`add`/`lang`/`mapping`/`expand`/`test`/`lsp`/`native` 十二个子命令覆盖全链路；
- 构建流水线：`.zc` → 转译 → `.cj` → cjc 编译 → 二进制；项目/工作区自动探测；
- 语言包 = 5 个 TOML 词表（关键字/标准库/模块路径/错误/元数据），双向映射、可扩展、可校验；
- 诊断全程中文 + 教学提示；`eject` 导出可独立编译；`ZHC_LANG_PACKS` 指定语言包目录。
