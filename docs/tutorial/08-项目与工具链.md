# 08 项目与工具链

目标：掌握 zhc 的项目模型与全部子命令，从单文件走向工程化。

## 8.1 创建项目：zhc init

```bash
zhc init 我的项目
cd 我的项目
```

生成结构：

```
我的项目/
├── cjpm.toml          # 包配置（cjc-version 自动探测当前编译器）
├── src/
│   └── main.zc        # 方言入口（主函数）
└── .gitignore
```

`src/main.zc` 初始内容：

```cangjie
主函数() {
    打印行("你好，仓颉！")
}
```

想让 cjpm 直接驱动方言项目（`cjpm build/run/test` 前自动转译方言源码）？加 `--native`：

```bash
zhc init --native 我的项目   # 额外生成 build.cj 构建钩子
```

生成结构多出 `build.cj`（cjpm 构建钩子：pre-build 阶段自动把 `src/` 下 `.zc` 转译为同名 `.cj`）；`zhc native` 即该钩子调用的内部命令，通常无需手动执行。

## 8.2 运行与检查

```bash
zhc run src/main.zc         # 项目模式：转译整个 src/ 并运行
zhc run 任意路径/文件.zc     # 单文件模式（自动探测所在项目/工作区）
zhc check src/main.zc       # 只编译检查，不运行（CI 常用）
zhc check .                # 目录参数：自动探测项目/工作区
```

检查输出会给出**中文教学诊断**：类型不匹配、空安全、可变性、未解析导入等，
每条附 💡 提示与可粘贴修复示例。

## 8.3 代码风格：zhc lint

```bash
zhc lint src/main.zc          # 风格检查 + cjlint 静态分析（母语报告）
zhc lint --fix src/main.zc    # 自动修复风格问题（参数顺序任意）
```

检查项：全角标点（字符串/注释内豁免）、尾随空白、CRLF、行长度（>120 只报告）、
重复空行；`--fix` 自动修复全角标点/尾随空白/CRLF/重复空行，另附 cjlint 静态分析
（未使用变量、命名规范等建议，位置映射回方言源码）。

## 8.4 添加依赖：zhc add

```bash
zhc add libdemo           # 编辑 cjpm.toml [dependencies]
```

依赖声明在 `cjpm.toml`（仓颉没有 cargo 式注册表，路径依赖为主）：

```toml
[dependencies]
libdemo = { path = "../libdemo" }
```

## 8.5 语言包与映射：zhc lang / zhc mapping

```bash
zhc lang list             # 列出可用语言包
zhc lang info zh          # 查看 zh 语言包信息
zhc mapping check         # 语言包质量门禁（五项检查）
zhc mapping auto 库目录    # 从库源码提取公开 API 生成 crates/<库>.toml
zhc mapping scaffold en zh # 以 en 为源生成 zh 翻译骨架
```

`ZHC_LANG_PACKS` 环境变量指向语言包目录（默认 ~/.zhc/lang-packs + 当前目录）。

## 8.6 项目与工作区

- **项目**：`src/` 下有 .zc 文件的目录（cjpm.toml + src/main.zc）；
- **工作区**：根 cjpm.toml 含 `[workspace]` 节 → 多模块仓库，`zhc run/check` 自动转译全部成员并按模块输出诊断；
- **目录参数**：`zhc check .` 自动探测项目/工作区。

## 8.7 宏展开视图：zhc expand

```bash
zhc expand src/main.zc --macro-pkg ../define
```

三栏对照（展开前 / 展开后官方 / 展开后方言），位置映射回 .zc 坐标，用于教学与调试宏。

## 8.8 LSP 与 IDE

```bash
zhc lsp                   # 启动 LSP 代理（行帧协议，供编辑器连接）
```

- 官方 LSPServer 可用：语言能力转发 + 自跑 cjc 诊断（混合档）；
- 官方不可用：自动降级为仅诊断档，不报错；
- VS Code 扩展（tools/vscode-extension/）提供高亮、右键运行/检查、全角转换。

## 8.9 方言测试：zhc test

```bash
zhc test                  # 项目根运行全部方言测试（workspace 成员根亦可）
```

流程：转译 `src/` 全部方言源码到 `.zhc-test/` → `cjpm test` → 输出母语化。
测试函数用 `@测试` 标记、`@期望` 断言（见 07 章 7.6 节）：

```cangjie
导入 标准测试宏.*
导入 标准测试.*

@测试
公开 函数 加法正确() {
    @期望(加法(2, 3), 5)
}
```

```
[ 通过 ] 用例： 加法正确
汇总：共 2；通过： 2, 跳过： 0, 错误： 0, 失败： 0
```

## 子命令总览

```bash
zhc init <目录>    创建项目          zhc run [文件|目录]   转译并运行
zhc check [文件]   检查（不运行）     zhc lint [--fix]     代码风格
zhc eject [文件]   导出官方 .cj      zhc add <库>         添加依赖
zhc lang list|info 语言包管理        zhc mapping check|auto|scaffold  映射工具链
zhc expand <文件>  宏展开教学视图     zhc test             方言测试
zhc native         构建钩子内部命令   zhc lsp             LSP 代理
```

## 练习

1. `zhc init` 建项目，写一个多文件程序（`导入` 同包模块）；
2. `zhc lint` 制造几个风格问题并 `--fix`；
3. `zhc mapping check` 验证当前语言包质量门禁。

## 小结

- `init`/`run`/`check`/`lint`/`eject`/`add`/`lang`/`mapping`/`expand`/`test`/`lsp`/`native` 十二个子命令覆盖全链路；
- 项目/工作区自动探测；诊断全程中文 + 教学提示；
- 语言包可扩展、可校验、可脚手架生成。
