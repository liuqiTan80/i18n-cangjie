# 09 诊断与错误字典

目标：读懂 zhc 的中文教学诊断，会用错误字典反查，成为「错误的朋友」。

## 9.1 诊断长什么样

`zhc check` 编译失败时输出结构化的中文诊断：

```
[错误] 类型不匹配  src/main.zc:3:14
  · 期望 整数，实际 文本（类型名本地化：Int64 → 整数）
  💡 检查声明与赋值两侧类型是否一致。需要转换时使用 `作为`（as），
     仓颉不会自动做类型转换。
  修复示例：
    可变 整数变量: 整数 = 1
    可变 文本变量: 字符串 = "1"
    // 声明与赋值两侧类型必须一致
```

组成：

| 部分 | 来源 |
|---|---|
| `[错误]/[警告]` + 中文消息 | 错误码表（errors.toml 诊断码 → 消息模板 + {q0} 占位） |
| `文件:行:列` | cjc JSON 诊断位置（方言文件坐标，与源码严格对齐） |
| 💡 教学提示 | 仓颉三主题：类型不匹配 / 空安全 / 可变性 |
| 修复示例 | 可直接粘贴的方言代码块 |

## 9.2 常见诊断速查

| 场景 | 你会看到 | 怎么办 |
|---|---|---|
| 类型不匹配 | `类型不匹配` | 对齐两侧类型，或 `作为` 转换 |
| 未使用变量 | `变量 x 从未被使用` | 删除，或确认拼写 |
| 给不可变赋值 | `不能给不可变值赋值` | `让` → `可变` |
| 缺少符号 | `缺少 {q0}` | 检查括号/分号/关键字 |
| 未解析导入 | 中文导入提示 | 添加依赖（zhc add） |

## 9.3 错误字典附录

完整条目见 [错误字典](../errors-dictionary.md)：

- **按官方错误码排序**（如 `sema_mismatched_types`），每条约含：官方码、中文消息模板、触发场景、教学提示、修复示例；
- 未收录的消息**原样回退**（不崩溃、不瞎译）——这是设计约束，保证任何错误都能看到；
- 消息翻译表（精确 / 最长前缀 / `~` 后缀三级匹配）覆盖官方消息变体。

## 9.4 学习策略

1. **故意写错**：每种错误亲手触发一次，读提示，粘贴修复示例，再故意犯一次确认理解；
2. **先读码后读文**：诊断码（如 `sema_mismatched_types`）是稳定标识，字典里按它查；
3. **活用 lint**：全角标点等风格问题用 `zhc lint --fix` 一键修复；
4. **宏报错用 expand**：宏展开后的错误位置经源映射还原到宏调用处。

## 9.5 官方对照

官方错误长这样（对照 9.1）：

```
error: mismatched types
 --> src/main.cj:3:14
```

zhc 把它翻译为中文 + 教学提示，位置仍指向你的 `.zc` 源码。

## 练习

1. 写五种错误各一个（类型不匹配/未使用/不可变赋值/缺括号/未解析导入），观察每种诊断；
2. 在错误字典里按诊断码找到对应条目，对照阅读；
3. 造一个「消息翻译」覆盖不到的错误，确认优雅回退不崩溃。

## 小结

- 诊断 = 中文消息 + 精确位置 + 💡 教学提示 + 可粘贴修复示例；
- 错误字典按官方错误码反查；未收录消息安全回退原文；
- 教学理念：错误不是障碍，是带答案的练习题。
