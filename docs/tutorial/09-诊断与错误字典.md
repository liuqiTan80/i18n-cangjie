# 09 诊断与错误字典

> 本章目标：读懂 zhc 的中文教学诊断（四段式结构），会用错误字典反查官方错误码，把「报错」变成「带答案的练习题」。
> 读完本章你能回答：诊断由哪四部分组成？`类型不匹配` 对应官方哪个错误码？消息翻译的三级匹配是什么？

## 9.1 诊断长什么样：四段式结构

`zhc check` 编译失败时输出结构化的中文诊断：

```
[错误] 类型不匹配  src/main.zc:3:14
  · 期望 整数，实际 文本（类型名本地化：Int64 → 整数）
  💡 检查声明与赋值两侧类型是否一致。需要转换时使用 `作为`（as），
     仓颉不会自动做类型转换。
  修复示例：
    可变 整数变量: 整数 = 1
    可变 文本变量: 字符串 = "1"
    // 声明与赋值两侧类型必须一致
```

四段拆解：

| 部分 | 内容 | 来源 |
|---|---|---|
| **① 级别 + 消息** | `[错误]/[警告]` + 中文消息 | errors.toml 诊断码 → 消息模板（{q0} 占位符） |
| **② 位置** | `文件:行:列` | cjc JSON 诊断位置，**映射回方言文件坐标**（与 `.zc` 源码严格对齐） |
| **③ 💡 教学提示** | 仓颉三主题：类型不匹配 / 空安全 / 可变性 | 语言包教学知识库 |
| **④ 修复示例** | 可直接粘贴的方言代码块 | 语言包教学知识库 |

## 9.2 错误按阶段分类

诊断码前缀透露错误发生在编译的哪个阶段（读码先看前缀）：

| 前缀 | 阶段 | 含义 | 例子 |
|---|---|---|---|
| `lex_*` | 词法 | 字符流不成词 | 非法字符、未闭合字符串 |
| `parse_*` | 语法 | 词不达意 | 缺括号、缺少关键字 |
| `name_*` | 名称解析 | 名字找不到 | 未解析的标识符、导入错误 |
| `sema_*` | 语义 | 类型/声明规则 | `sema_mismatched_types` 类型不匹配 |
| `pkg_*` | 包管理 | 工程结构 | 找不到包、依赖缺失 |

**教学三主题**（zhc 的 💡 提示聚焦三类高频新手错误）：

| 主题 | 典型场景 | 修复方向 |
|---|---|---|
| **类型不匹配** | `整数` 变量赋 `字符串` | 对齐类型或用 `作为`（仓颉不自动转换） |
| **空安全** | 对 `选项` 值直接运算 | 先 `匹配` 解包或 `获取或默认` |
| **可变性** | 给 `让` 绑定赋值 | `让` → `可变` |

## 9.3 常见诊断速查

| 场景 | 你会看到 | 怎么办 |
|---|---|---|
| 类型不匹配 | `类型不匹配` | 对齐两侧类型，或 `作为` 转换 |
| 未使用变量 | `变量 x 从未被使用` | 删除，或确认拼写 |
| 给不可变赋值 | `不能给不可变值赋值` | `让` → `可变` |
| 缺少符号 | `缺少 {q0}` | 检查括号/分号/关键字 |
| 未解析导入 | 中文导入提示 | 添加依赖（`zhc add`） |
| 找不到包 | `找不到包 {q0}`（方言自定义码） | 检查 `cjpm.toml` 依赖声明 |
| 可空值误用 | 空安全教学提示 | 先 `匹配` 再取值（见第 6 章） |
| 非开放类型被继承 | 开放性错误 | 父类加 `开放`（见第 5 章） |

## 9.4 错误字典：按官方错误码反查

完整条目见 [错误字典](../errors-dictionary.md)，**按官方错误码排序**（如 `sema_mismatched_types`）：

- 每条约含：**官方码、中文消息模板、触发场景、教学提示、修复示例**；
- 覆盖规模：645 条诊断码 = 官方 644 条 + 方言自定义 1 条（找不到包 `package_search_error`）；
- **三级消息匹配**：精确匹配 → 最长前缀匹配 → `~` 后缀匹配，逐级降级覆盖官方消息变体；
- **优雅回退**：未收录的消息**原样回退**（不崩溃、不瞎译）——这是设计约束，保证任何错误都能看到原文。

**为什么按官方码查**：诊断码（如 `sema_mismatched_types`）是**稳定标识**，中文消息可能随版本变化——码不变。先读码后读文。

## 9.5 修复演练：从报错到修好

以最常见的「类型不匹配」走一遍完整流程：

**① 写错**：

```cangjie
主函数() {
    可变 数量: 整数 = "12"      // 故意的错误
    打印行(数量)
}
```

**② 看诊断**（`zhc check 文件`）：

```
[错误] 类型不匹配  main.zc:2:22
  · 期望 整数，实际 字符串
  💡 检查声明与赋值两侧类型是否一致。需要转换时使用 `作为`（as），
     仓颉不会自动做类型转换。
  修复示例：……
```

**③ 选修复方案**：

```cangjie
导入 转换.*

主函数() {
    可变 数量: 整数 = 整数.解析("12")     // 方案一：把字符串解析成整数（见 2.10）
    打印行(数量)
}
```

**④ 再故意犯一次**（换一种错误方式，确认理解而非死记）。

> 教学理念：**错误不是障碍，是带答案的练习题**——每条诊断都自带 💡 与修复示例，犯错成本趋近于零。

## 9.6 学习策略

1. **故意写错**：每种错误亲手触发一次，读提示，粘贴修复示例，再故意犯一次确认理解；
2. **先读码后读文**：诊断码是稳定标识，字典里按它查；
3. **活用 lint**：全角标点等风格问题用 `zhc lint --fix` 一键修复；
4. **宏报错用 expand**：宏展开后的错误位置经源映射还原到宏调用处（见第 7 章）；
5. **类型名本地化**：诊断里 `整数`/`文本`/`布尔` 是 `Int64`/`String`/`Bool` 的本地名——读诊断时先习惯这层映射。

## 9.7 官方对照

官方错误长这样（对照 9.1）：

```
error: mismatched types
 --> src/main.cj:3:14
```

zhc 把它翻译为中文 + 教学提示，位置仍指向你的 `.zc` 源码——**转译层 + 诊断层双母语**：代码是中文的，错误也是中文的。

## ✳ 设计思想

**① 诊断是产品不是附属品**。zhc 把错误消息做成「四段式产品」：位置精确到列、消息模板参数化（{q0}）、附教学提示与可粘贴修复——这是「新手友好」工程理念的体现：让工具自己教自己。

**② 稳定标识 + 可回退的翻译**。诊断码永远不变（稳定标识），消息可以翻译（三级匹配），翻译不到就回退原文（优雅降级）——软件国际化的经典架构：**核心不变，表现层可替换，失败永远可见**。

**③ Fail fast，教得早**：编译错误发生在运行之前——这是最便宜的错误修复时机（比线上崩溃便宜几个数量级，见第 11 章）；zhc 还把错误从英文翻成中文、从冷冰冰变成带教程——把「尽早失败」和「失败得有意义」结合。

**④ 错误分类学**：lex → parse → name → sema → pkg 是编译器的阶段划分，也是排查问题的路线图——看到前缀就知道该查「拼写/结构/名字/类型/依赖」哪一类，先分类再动手。

## 练习

1. 写五种错误各一个（类型不匹配/未使用/不可变赋值/缺括号/未解析导入），观察每种诊断的四段结构；
2. 在错误字典里按诊断码找到对应条目，对照阅读；
3. 造一个「消息翻译」覆盖不到的错误，确认优雅回退不崩溃；
4. 制造一个 `让` 绑定赋值错误，按 9.5 的流程走完「写错 → 读诊断 → 修复 → 再犯」四步。

## 小结

- 诊断四段式：级别+消息 / 文件:行:列 / 💡 教学提示 / 修复示例；
- 错误分五类（lex/parse/name/sema/pkg），教学三主题（类型不匹配/空安全/可变性）；
- 错误字典按官方错误码反查（645 条 = 官方 644 + 方言 1）；三级消息匹配，未收录安全回退原文；
- 教学理念：错误不是障碍，是带答案的练习题。
