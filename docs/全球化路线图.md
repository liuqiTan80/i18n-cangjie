# zhc 全球化路线图

> 目标：让全球用户都能用母语编写仓颉。本文是四维度分析（易用性/易学性/可扩展性/
> 可推广性）的落地路线图，按优先级排序；完成项打 ✅ 并注明提交。

**总体判断**：核心创意（方言词法转译 + 母语诊断 + 语言包生态）有真实差异化价值。
但当前是"用中文搭建了全球产品的地基"——8 个语言包中 5 个无界面翻译、645 条教学
诊断仅中文、教程仅中文。全球化 = 把为中文做过的每一层，用可扩展的方式复制到每种语言。

## P1（下一迭代）

- 一行安装：短链壳 + Scoop manifest + Homebrew formula（离线包已具备条件）。
- 60 秒四语演示视频（同程序四种母语并排）——项目天生的传播素材。

- 指标埋点（lang install / share fetch / 教程页访问）+ 众包平台破冰活动。

## 语言包档位体系（schema 1）

| 档位 | 界面消息 | 错误表 | 当前语言包 |
|---|---|---|---|
| `full` | 100%（全量档） | 完整 | zh（645 条）、en（英文原文即母语） |
| `standard` | 100% | 部分 | ru（演示级错误表） |
| `demo` | 部分（缺键回退 EN） | 无 | ja/de/es/fr/ko（18%） |

档位写入各包 `lang_info.toml`（`"档位"`/`"界面覆盖率"`/`"错误表"`/`"维护者"`/
`"反馈"`/`"schema"`），诚实告知用户成熟度；升级路径：补翻 `ui_translations_<code>.py`
→ 重跑 `tools/gen_ui_packs.py` → 覆盖率与生成物同步更新。

## 共享源实测矩阵（share 默认源选型依据，2026-09-05）

| 通道 | 结果 |
|---|---|
| jsDelivr（`cdn.jsdelivr.net/gh/<owner>/<repo>@main/libs`） | ✅ 200 匿名可用（CDN 缓存数小时延迟） |
| `gitcode.com/.../raw/...` | ❌ 匿名返回 HTML 预览页 |
| `raw.gitcode.com/...` | ❌ 403 暂不支持预览 |
| `raw.githubusercontent.com` | ❌ 国内不可达（000） |
| 两平台 API contents 接口 | ⚠️ base64（非纯文本，暂不采用） |
