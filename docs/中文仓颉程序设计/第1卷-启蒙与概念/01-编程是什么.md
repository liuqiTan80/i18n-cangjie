# 第 1 章 编程是什么？

> **本章学习目标**
> - 知道「编程」到底在干什么——写菜谱；
> - 认识我们的工具：仓颉 + zhc，明白中文代码是怎么变成电脑能懂的东西的；
> - 亲手把环境搭好：装 SDK、配环境变量、构建 zhc，并**验证成功**。
>
> **读完本章你能回答**：电脑为什么「笨」？程序是什么？翻译官是谁？我的 `zhc` 是怎么一步步装好的？

---

## 1.1 电脑很聪明，也很笨

电脑能瞬间算出几亿次加减法，但它**听不懂人话**。你喊「帮我做个游戏」，它一头雾水。

电脑只听得懂一种特别简单的语言，里面只有两个符号：`0` 和 `1`。这就像古代打仗用的烽火台——**点着了（1）** 或者 **没点着（0）**，就靠这两个状态传递消息。

那么问题来了：我们怎么指挥这么笨的电脑？

## 1.2 编程 = 写菜谱

想象你在教一个从没做过饭的朋友做西红柿炒蛋。你会怎么写？

```
第一步：把两个鸡蛋打进碗里，搅匀
第二步：西红柿切块
第三步：锅里倒油，烧热
第四步：倒鸡蛋，炒熟盛出
第五步：倒西红柿，炒出汁，放鸡蛋，加盐
第六步：出锅
```

**编程就是干这个**：把你想让电脑做的事，一步一步写清楚，写成它看得懂的「菜谱」。这份菜谱，就叫**程序**（program）。写菜谱的人，叫**程序员**——对，就是你。

## 1.3 编程语言 = 翻译官

电脑只懂 `0` 和 `1`，我们直接用 `0` 和 `1` 写程序？那就像用摩斯密码写作文，太痛苦了。

于是聪明人发明了**编程语言**：一种接近人类语言的「中间话」。电脑通过**编译器**（相当于翻译官）把编程语言翻译成 `0` 和 `1`。

世界上有很多编程语言，英文的居多。但是——

## 1.4 中文也能编程

**仓颉**（Cangjie）是中国企业**华为**开发的一款面向全场景智能的新一代编程语言，主打原生智能化、天生全场景、高性能、强安全编程语言。而 **zhc**（仓颉方言框架）让它更进一步：关键字、函数名、报错提示，**全部可以用中文**！

| 别的语言要查词典 | 我们用 zhc 写 |
|---|---|
| 程序入口要背单词 | `主函数()` |
| 打印文字要背单词 | `打印行("你好")` |
| 声明一个不变的量要背单词 | `让 x = 1` |
| 判断要背单词 | `如果 ... 否则 ...` |

**你写代码的时候，不用查英文字典。** 电脑报错也是中文的，还带「💡 提示」和「修复示例」——这是这本书最大的底气。

> **术语小词典**
> - **程序**：写给电脑看的「菜谱」
> - **代码**：程序的另一个名字，像「作文」和「文章」的关系
> - **运行**：让电脑执行你的程序
> - **编译器**：把中文代码翻译成电脑能懂的 `0` 和 `1` 的翻译官
> - **zhc**：我们的方言工具——它负责把中文代码翻译成标准仓颉（交给编译器），再把英文报错翻译成中文（交给我们）

## 1.5 安装你的工具

我们要装两样东西：

1. **官方仓颉 SDK**：自带编译器 `cjc` 和包管理器 `cjpm`（翻译官本尊）；
2. **zhc**：中文方言工具（负责中文 ↔ 仓颉的来回翻译）。

下面 7 步全部按「本机实测通过」的流程编写，每一步都有**验证方法**（做完能看到什么）。跟着做，做完你的工具就齐了。

> 环境要求：Linux x86_64（64 位），能上网。Windows/macOS 的同学可以先看第 1.7 节排查表，或请老师/朋友帮忙。

### 步骤 0：检查环境（3 分钟）

打开**终端**（Linux 的 Terminal），逐条输入并核对：

```bash
uname -m          # 期望输出：x86_64
git --version     # 期望输出：git version 2.x（没有就装：sudo apt install -y git）
```

> 看不懂「终端」？它就是电脑的「命令行窗口」——一个能敲字让电脑干活的窗口。后面所有步骤都在这里完成。

### 步骤 1：安装官方仓颉 SDK（10 分钟）

从华为仓颉官方渠道下载 Linux x86_64 的 SDK 压缩包（里面有编译器、运行时、标准库，一共好几样，打包在一起）。

解压到 `~/ruanj` 目录，并统一改名为 `cangjie`（后面写路径全靠它，名字统一最省心）：

```bash
mkdir -p ~/ruanj
tar -xzf 你下载的仓颉SDK压缩包.tar.gz -C ~/ruanj
mv ~/ruanj/解压出的目录名 ~/ruanj/cangjie    # 把解压出的目录改名为 cangjie
```

解压后确认 SDK 长这样（**后面的路径全靠它**）：

```
~/ruanj/cangjie/
├── bin/
│   └── cjc                     # 编译器（翻译官）
├── tools/bin/
│   └── cjpm                    # 包管理器（装零件、构建项目）
├── runtime/lib/linux_x86_64_cjnative/
│   └── libcangjie-runtime.so   # 运行时库（跑任何仓颉程序都要）
└── tools/lib/                  # 构建期库（编译时需要）
```

> ⚠️ 常见误区：`cjc` 在 `bin/` 下，`cjpm` 在 `tools/bin/` 下——**两个都要**进 PATH（下一步一起加）。

### 步骤 2：配置环境变量（3 分钟）

环境变量就像电脑的「通讯录」——告诉电脑去哪找工具。把下面三行追加到 `~/.bashrc`（这是终端每次打开都会读的配置文件）：

```bash
cat >> ~/.bashrc <<'EOF'

# ---- 仓颉 SDK ----
export CANGJIE_HOME="$HOME/ruanj/cangjie"
export PATH="$CANGJIE_HOME/bin:$CANGJIE_HOME/tools/bin:$PATH"
export LD_LIBRARY_PATH="$CANGJIE_HOME/runtime/lib/linux_x86_64_cjnative:$CANGJIE_HOME/tools/lib:${LD_LIBRARY_PATH:-}"
EOF
source ~/.bashrc
```

这三行分别是干嘛的（**为什么这么写**）：

| 变量 | 作用 | 不设会怎样 |
|---|---|---|
| `CANGJIE_HOME` | 记住 SDK 在哪（其他工具会来问它） | 部分工具找不到 SDK |
| `PATH` | 让你能直接敲 `cjc`、`cjpm` 命令 | 报 `cjc: command not found`（找不到命令） |
| `LD_LIBRARY_PATH` | 让程序找到运行时库 `.so` 文件 | 报 `error while loading shared libraries` |

### 步骤 3：验证 SDK（1 分钟）

```bash
cjc --version
# 期望输出：Cangjie Compiler: 1.0.5 (cjnative)

cjpm --version
# 期望输出：Cangjie Package Manager: 1.0.5
```

看到版本号 = SDK 装好了！（版本 ≥ 1.0.5 即可）

### 步骤 4：获取 zhc 源码（2 分钟）

zhc 是开源项目，用 `git` 把它的源码下载到本地：

```bash
git clone <本项目仓库地址> ~/code/zwCangjie
cd ~/code/zwCangjie/zhc
```

源码里有个神奇的目录叫 `lang-packs/`——**中文词表本体**：

```
zhc/lang-packs/zh/
├── keywords.toml        # 关键字词表：每条一行「方言词 → 官方词」
├── stdlib.toml          # 标准库别名表：方言 API 名 → 官方 API 名
├── module_paths.toml    # 模块路径映射：方言路径名 → 官方路径
├── errors.toml          # 错误消息：645 条诊断码的中文模板
└── ui.toml              # 工具界面文案
```

> 💡 **小秘密**：zhc 的「中文能力」全在这些**数据文件**里，不是写死在代码里。换一套词表就是一门新方言——比如俄语词表就能写出俄语仓颉（项目里已有演示包）。你学的就是这门「中文方言」。

### 步骤 5：构建 zhc 本体（3~10 分钟）

在 `zhc/` 目录里执行（第一次会编译依赖，耐心等）：

```bash
cjpm build
```

成功标志——产物出现且可执行：

```bash
ls -l target/release/bin/main
# 期望输出：-rwxr-xr-x ... target/release/bin/main
```

构建产物名叫 `main`，它就是 zhc 本体。复制到 `~/.local/bin` 并起个正式名字 `zhc`，放进 PATH：

```bash
mkdir -p ~/.local/bin
cp target/release/bin/main ~/.local/bin/zhc
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### 步骤 6：让 zhc 找到语言包（2 分钟）

zhc 按顺序找语言包（任中一个成立即可）：环境变量 `ZHC_LANG_PACKS` → 当前目录 `./lang-packs/` → 可执行文件旁的 `lang-packs/` → 用户目录 `~/.zhc/lang-packs/`。

源码构建推荐用第 1 种（显式、不依赖运行目录）：

```bash
echo 'export ZHC_LANG_PACKS="$HOME/code/zwCangjie/zhc"' >> ~/.bashrc
source ~/.bashrc
```

### 步骤 7：验证安装（1 分钟）

```bash
zhc --help
```

看到中文帮助（`zhc init 生成项目骨架`、`zhc run 转译并运行`……）就成功了！再跑一个真程序试试：

```bash
cd ~/code/zwCangjie/zhc/examples
zhc run hello.zc
```

期望输出：

```
✅ 编译成功：替换方言标识符 2 处。
你好，仓颉！
```

🎉 **恭喜！你的中文仓颉环境搭好了！** 第 2 章开始，我们正式写程序。

> **卡住了？小排查表**（照着查）
>
> | 症状 | 原因 | 解决 |
> |---|---|---|
> | `cjc: command not found` | PATH 没配好 | 重做步骤 2，确认 `source ~/.bashrc` 执行了 |
> | `error while loading shared libraries` | LD_LIBRARY_PATH 没配好 | 检查步骤 2 第三行，SDK 路径是否正确 |
> | `uname -m` 不是 x86_64 | 架构不支持 | 换 64 位系统，或用离线发布包方式 |
> | `cjpm build` 报依赖错误 | 网络/版本问题 | 确认网络，重跑一次；还不行看项目 README 或提问 |
> | `zhc` 找不到语言包 | ZHC_LANG_PACKS 没设 | 重做步骤 6，确认路径指向含 `lang-packs/` 的目录 |

## 1.6 动手练一练

1. 打开终端，输入 `zhc --help`，把输出里你认识的子命令抄下来（比如 `run`、`check`）；
2. 打开 `~/code/zwCangjie/zhc/lang-packs/zh/keywords.toml`，看几行「方言词 → 官方词」的映射，感受一下词表长什么样；
3. 在 `examples` 目录里再跑一次 `zhc run hello.zc`，试试修改 `hello.zc` 里的中文（比如把「你好，仓颉！」改成你的名字），再跑一次——**第一次改代码，你已经是个程序员了**。

## ✳ 编程思想小贴士：把大问题拆成小步骤

「编程 = 写菜谱」这个比喻背后，是编程最重要的思想：**分解**。

- 不会做西红柿炒蛋？没关系，把它拆成 6 步，每一步都很简单；
- 不会写一个游戏？没关系，把它拆成「显示画面 → 接收按键 → 计算 → 更新画面」，每个小步再拆小。

**任何复杂问题，拆到每一步都简单得不会出错，就一定能做完。** 这是程序员解决一切问题的第一招——以后你写代码遇到难题，先问自己：能不能再拆小一点？

## 🍳 日常算法小例子：早晨上学 = 顺序执行

程序最基础的结构叫**顺序执行**：从上到下，一步做完做下一步。你每天早晨就是一段程序：

```
1. 起床
2. 刷牙
3. 吃早饭
4. 背上书包
5. 出门上学
```

这段「菜谱」里有几个特点——步骤有先后、不能颠倒、每步只做一件事。**电脑执行程序就是这样：一条一条，老老实实**。第 2 章我们会看到程序里的顺序执行长什么样。

## 小结

- 电脑很聪明也很笨：它只懂 `0` 和 `1`，需要「菜谱」才能干活；
- 程序 = 写给电脑的菜谱；编程语言 + 编译器（翻译官）让写菜谱变得像人话；
- 仓颉是中国人造的编程语言，**zhc 让它全程中文**：关键字、函数名、报错提示都是中文；
- 环境搭建 7 步：检查环境 → 装 SDK → 配环境变量 → 验证 SDK → 拿源码 → 构建 zhc → 验证运行；
- 编程第一思想：**把大问题拆成小步骤**（分解）。
