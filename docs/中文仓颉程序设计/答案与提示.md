## 第 1 章 编程是什么？

1. **电脑为什么听不懂「帮我做个游戏」？**
   电脑只会执行**精确、无歧义、可分解**的指令（最终是 0/1 的机器指令）。「帮我做个游戏」太模糊——什么游戏？怎么算赢？界面长什么样？它需要你把这句话拆成成千上万条一步一步的操作。编程的本质就是**把想法翻译成电脑能照做的精确步骤**。

2. **编译器、zhc、语言包的角色**
   - **编译器**（cjc）：把仓颉代码翻译成机器指令——电脑只听它；
   - **zhc**：方言转译器——把中文 `.zc` 源码翻译成官方仓颉 `.cj`，再交给编译器；
   - **语言包**：zhc 的「词典」——中文词 ↔ 官方词的对照表，词表里有的词才翻译。
   
   打个比方：编译器是翻译官（汉语→英语），zhc 是翻译官的小助手（先把你说的「方言」整理成标准汉语），语言包是小助手的词表。

3. **泡茶菜谱（示例）**
   ① 烧水 → ② 水开（听到哨响/看到冒泡）后关火 → ③ 把茶叶放进杯子 → ④ 倒水 → ⑤ 等 3 分钟 → ⑥ 喝。
   要点：每步**明确可执行**（「等 3 分钟」比「等一会儿」好）、**顺序清楚**、有**判断点**（怎么知道水开了？）——这就是程序的雏形。

4. **为什么写进 `~/.bashrc`？**
   打开终端时 `~/.bashrc` 会**自动执行一次**，里面的 `export` 每次都帮你配好环境。写进去 = 配一次、永久生效；不写 = 每次开终端都要手动敲一遍（菜谱重复执行时，把「固定准备动作」放进开机脚本）。

## 第 2 章 第一个程序：你好，世界！

1. **删掉 `{` `}` 还能运行吗？**
   不能。花括号**划定函数体的边界**——告诉编译器「主函数从哪开始、到哪结束」。没有它，编译器不知道 `打印行` 属于谁、函数到哪一行结束，直接语法报错。

2. **`打印行` 和 `打印` 的区别**
   两个都存在（语言包实测：`打印` = print、`打印行` = println）：`打印行` 输出后**自动换行**，`打印` 输出后**不换行**。试试 `打印("甲")` + `打印("乙")`，输出是 `甲乙` 挤在一行。

3. **`"你好"` 加引号、`主函数` 不加？**
   引号里是**文字数据**（字符串），不加引号的是**代码名字**（标识符）。编译器看到引号就知道「这是数据，别当代码执行」；看到 `主函数` 就知道「这是名字，去找它的定义」。引号是数据和代码的分界线。

4. **输出顺序**：从上到下执行，先输出「我是第一行」，再输出「你好」：

```cangjie
主函数() {
    打印行("我是第一行")
    打印行("你好")
}
```

## 第 3 章 记忆盒子：变量

1. **为什么默认用 `让`？**
   不可变默认原则：**盒子不会偷偷变化，读代码更安心**。看到 `让`，你就知道这个值从头到尾不会变——不用记着「它可能在哪被改过」。只有明确需要改的才声明 `可变`，把「会变」变成需要申请的例外，而不是默认状态。

2. **`计数 = 计数 + 1` 为什么合法？**
   程序里的 `=` 是**赋值**不是「等于」：先算**右边**（把旧值 5 取出来 +1 得 6），再把结果**装进左边盒子**。数学的 `=` 描述「两边恒等」；程序的 `=` 描述「把右边的结果放进去」——执行完这一刻，左边才变成新值。程序里没有「6 = 5+1 然后又 5 = 6-1」这种双向恒等，只有从左到右的「先算后装」。

3. **生活里的「让」与「可变」**
   `让`：身份证号、出生日期、血型——定了不改；`可变`：零花钱余额、游戏分数、微信步数——天天变。好代码的命名与选择，就是如实反映「这个东西该不该变」。

4. **`打印行("${12}")`**
   能打印出 `12`。说明 `${}` 插值里可以放**任何有值的表达式**——字面量 `12` 本身就是值，不需要先装进盒子：

```cangjie
主函数() {
    打印行("${12}")      // 12：字面量也是值
}
```

## 第 4 章 数字与文字

1. **`10 / 3` 和 `10 % 3`**
   `3` 和 `1`：整数除法**丢掉余数**（10 ÷ 3 = 3 余 1），`/` 得商、`%` 得余数：

```cangjie
主函数() {
    打印行(10 / 3)     // 3（商）
    打印行(10 % 3)     // 1（余数）
}
```

2. **`1 + "2"` 为什么报错？**
   整数和字符串是**两种类型**，仓颉不做隐式转换——`+` 没有定义「整数 + 字符串」该怎么算。如果允许：`"1" + "2"` 是字符串拼接得 `"12"`，那 `1 + "2"` 到底该得 `3` 还是 `"12"`？`+` 的含义会分裂成「看心情」，类型系统这道防线就崩塌了。**类型不匹配在编译期报错，是保护不是刁难**。

3. **`${}` 里能放 `打印行(...)` 吗？**
   不能。插值需要的是**值**（能产生结果的东西）；`打印行` 是**动作**（执行后返回「空」——空类型没有值）。动作不能当值用，就像你不能把「扫地」这个动作塞进「今天买了 X」的 X 里。

4. **判断 123 是不是偶数**：能被 2 整除（余数为 0）就是偶数：

```cangjie
主函数() {
    如果 (123 % 2 == 0) {
        打印行("123 是偶数")
    } 否则 {
        打印行("123 是奇数")
    }
}
```

## 第 5 章 电脑会思考：判断

1. **5.2 评级改成先写 `分数 >= 60`，85 分会输出什么？**
   输出「及格」。因为分支**从上到下只走第一条成立的路**：85 >= 60 先成立，直接走人，永远到不了后面的 `>= 90`。这就是「分支顺序 = 优先级」——评级要从**高分往低分**写（90 → 60），把最严格的放最前面。

2. **`如果 (分数 = 85)` 会报错吗？**
   会（实测编译报错）。`=` 是赋值不是比较，赋值表达式的类型是「空」，而 `如果` 的条件必须是**布尔**（真/假判断）。这保护了你：把「误写一个等号」的错误**拦在编译期**——如果语言偷偷把它当比较，你的程序就会「永远成立」地悄悄跑错。判断相等要写 `==`。

3. **下雨 + 低温提醒**：

```cangjie
主函数() {
    让 下雨 = 真
    让 气温 = 8          // 单位：度
    如果 (下雨 与 气温 < 10) {
        打印行("带伞，穿外套！")
    } 否则 {
        打印行("正常出门")
    }
}
```

4. **`非 (年龄 < 18)` 和 `年龄 >= 18` 是一回事吗？**
   是，逻辑上完全等价：把「小于 18」反过来，就是「大于等于 18」。`非` 会把真假对调——这题的核心是**取反时要小心边界**：`<` 的反面是 `>=`，不是 `>`（漏掉 18 本身）。

## 第 6 章 重复干活：循环

1. **循环次数**：`1..5` 是半开区间 [1, 5)，循环 **4 次**（1、2、3、4）；`1..=5` 含 5，循环 **5 次**：

```cangjie
主函数() {
    可变 次数 = 0
    对于 (i 在 1..5) { 次数 += 1 }
    打印行(次数)      // 4
    次数 = 0
    对于 (i 在 1..=5) { 次数 += 1 }
    打印行(次数)      // 5
}
```

2. **用 `当` 写死循环的正确姿势**：`当 (真) { ... }` + 内部的 `跳出` 作为出口。适合「**不知道要循环几次、由中途条件决定**」的场景——第 11 章猜数字、第 19 章游戏主循环都用它。死循环本身不可怕，可怕的是**没有出口**；写 `当 (真)` 时先想好「凭什么能跳出去」。

3. **电脑不怕笨办法**
   高斯用数学公式秒算 1+100；电脑的办法是老老实实加 100 次。各有优缺点：
   - 电脑法：笨，但**可靠、通用**（换个范围照样加，不用找规律），机器快、不累；
   - 数学法：聪明，但**需要人发现规律**，规律不适用就得换。
   
   程序里「笨办法」常常是更好的工程选择——先把功能做对，再想优化。

4. **打印三角形（挑战）**：外层控制行数，内层控制每行的星号数：

```cangjie
主函数() {
    对于 (行 在 1..=5) {
        可变 星 = ""
        对于 (列 在 1..=行) {
            星 = 星 + "*"     // 字符串 + 拼接
        }
        打印行(星)
    }
}
```

## 第 7 章 函数初体验

1. **`返回` 之后的代码会执行吗？**
   不会——`返回` 立即结束函数，后面的代码永远到不了。而且 zhc 实测：在 `返回 1` 后面写 `打印行`，**编译直接报错**（期望 `整数` 得到空类型）——编译器不让你写永远执行不到的代码。顺序写对就能执行：

```cangjie
函数 偷偷(): 整数 {
    打印行("执行了")    // 在返回之前：正常执行
    返回 1
}

主函数() {
    打印行(偷偷())      // 先打印 执行了，再打印 1
}
```

2. **`评级(85)` vs `评级(85.5)`**
   `评级(85)` 对——参数类型声明的是 `整数`；`85.5` 是浮点数，**类型不匹配，编译报错**（仓颉不做隐式转换）。想支持小数，就另写一个接收浮点的重载版本（第 8 章）。

3. **参数盒子和函数外的变量是同一个吗？**
   不是——传参是**拷贝**：函数拿到的是「值的一份复印件」，在函数里怎么改都不影响外面。这保护了调用方：**函数不能偷偷修改你的变量**。想要「函数能改外部数据」，得显式设计（返回新值、或传可变容器/对象——第 12 章）。

```cangjie
函数 翻倍(数: 整数): 整数 {
    返回 数 * 2
}

主函数() {
    让 原数 = 5
    打印行(翻倍(原数))    // 10
    打印行(原数)           // 5：原数没变（传的是拷贝）
}
```

4. **挑战：`最大` 函数**
   两个数比大小用 `如果`；三个数 = 先比两个，赢家再和第三个比（套两层）：

```cangjie
函数 最大(甲: 整数, 乙: 整数): 整数 {
    如果 (甲 > 乙) { 返回 甲 }
    返回 乙
}

主函数() {
    打印行(最大(3, 7))              // 7
    打印行(最大(最大(3, 7), 5))     // 7：三个数套两层
}
```

## 第 8 章 函数深入

1. **参数必须标注类型，局部变量可以推断？**
   参数是**接口契约**——函数和调用方之间的约定，必须写清楚「你要给我什么」；类型是契约的核心部分。局部变量是**实现细节**——函数内部怎么算，编译器从初始化就能推断，标出来反而是噪音。设计原则：**边界要显式，内部可自由**。

2. **`增量` 为什么没消失？**
   因为 lambda 是**闭包**——它不只是代码，还带着「定义处的环境」（捕获了 `增量` 变量）。函数结束后，普通局部变量确实销毁了，但被闭包捕获的变量会**跟着闭包一起存活**，直到闭包本身不再被使用。`造加法器(5)` 返回的不是「加 5 的函数」，而是「函数 + 它记得的 5」：

```cangjie
函数 造加法器(增量: 整数): (整数) -> 整数 {
    返回 { x => x + 增量 }       // 捕获 增量
}

主函数() {
    让 加5 = 造加法器(5)
    打印行(加5(10))              // 15：增量 5 被闭包随身携带
}
```

3. **`描述(1)` 为什么选整数版本？**
   重载决议按**精确匹配**：参数 `1` 是整数，就选参数为 `整数` 的版本，绝不自动转换去凑别的版本（隐式转换是仓颉明令禁止的）。多个重载同时「够得着」时会编译报错要求你消除歧义——类型系统宁可让你说清楚，也不猜。

4. **lambda 里能用 `返回` 吗？**
   不能（编译报错）。`返回` 属于**函数**——它会结束整个函数；lambda 只是表达式，它的「结果」是表达式自身的值，没有独立的返回语句。把 `返回` 写进 lambda，编译器不知道你要结束谁（见附录 C17）。lambda 想提前结束？没有这个概念——它是纯计算，算完自然结束。

## 第 9 章 类型系统

1. **`让 x: 浮点 = 1` 合法，`让 x: 整数 = 1.5` 不合法？**
   **字面量多态 vs 数值截断**：`1` 是没有「过去」的字面量，可以按上下文自适应成 `1.0`——放哪都能无损。`1.5` 装进整数盒子必须**截断**成 `1`，这是丢数据的操作，语言拒绝悄悄发生。字面量可以灵活，**变量之间的转换必须显式**（`整数(1.5)` 表示「我知道会截断，我负责」）。

2. **字符串长度是字节数，保护了什么？**
   程序最终要跟**文件、网络、二进制**打交道——它们处理的全是**字节流**。统一按字节计长，字符串和二进制世界就共用同一把尺子：往文件里写 `"你好"` 就是写 6 个字节，谁都能预期。如果长度按「字符数」算，字符和字节之间就多了一层需要时刻换算的迷雾——错位的 bug 源头。

3. **允许 `整数 + 字符串` 会带来什么 bug？**
   举例：用户输入年龄 `"18"`（字符串），程序想 `年龄 + 1` 判断成年——如果自动转成字符串得 `"181"`，静默错得离谱；或者 `"10" > "9"` 按字典序比较得假（字符串比较），跟数值直觉相反。**隐式转换把类型错误推迟到运行期**，变成难查的诡异行为；显式转换让每个转换点可见、可审。

4. **`(1,)` 和 `(1)` 的区别？**
   `(1)` 就是整数 `1`——括号只起分组作用；元组的标志是**逗号**。⚠️ 实测（官方 1.0.5）：**单元素元组的 `(1,)` 尾逗号写法编译报错**（「期望表达式」）——zhc 和官方编译器都不支持。想打包一个元素，用单元素数组 `[1]`（数组定长即可）；元组老老实实至少装两个元素，如 `(1, "小明")`。

## 第 10 章 字符串与文本处理

1. **`"你好"[0]` 得到什么？**
   **228**——第一个**字节**的数值，不是字符「你」！字符串下标按字节索引：UTF-8 里「你」占 3 字节（E4 BD A0），`[0]` 取到首字节 E4 = 228：

```cangjie
主函数() {
    打印行("你好"[0])       // 228：首字节数值（E4）
    打印行("你好"[0..3])    // 你：切片 3 字节 = 1 个汉字
}
```

2. **字符串为什么不可变？**
   共享安全：同一个字符串可能被传给十个函数、存进五个容器——如果谁都能原地改，一处修改处处遭殃（别名污染）。不可变意味着**传出去就放心**：没人能改坏你的数据。代价是拼接产生新串，所以批量拼接用 `收集字符串` 而不是循环 `+`。

3. **`"abc".大写()` 和 `"仓颉".大写()`**
   分别输出 `ABC` 和 `仓颉`（不变）。`大写` = 官方 `toAsciiUpper`——**纯 ASCII 转换**，只处理英文字母；中文在 Unicode 里没有「大写」概念，也就不在转换范围内。这也是它叫 `toAsciiUpper` 而不是 `toUpperCase` 的原因。

4. **`匹配正则` 是「包含」还是「完全等于」？**
   实测：**包含匹配**（匹配到任意子串就返回真）——`正则("\\d+").匹配正则("a1")` 是 `真`（匹配到了 `"1"`）：

```cangjie
导入 正则.*

主函数() {
    打印行(正则("\\d+").匹配正则("a1"))      // true：包含匹配
    打印行(正则("^\\d+$").匹配正则("a1"))    // false：加锚后整串判断
}
```

   要判断「整串都是数字」，必须加锚 `^`（开头）+ `$`（结尾）——这正是第 14/18/19 章解析函数统一锚定的原因（附录 C10 踩坑）。

## 第 11 章 集合与容器

1. **哈希为什么 O(1)？代价是什么？**
   数组找值要**逐个比较**（O(n)）；哈希映射用键算出**哈希值**直接跳转到对应桶——一步到位，不逐个比。代价：① **无序**——桶的顺序由哈希决定，不是插入顺序；② 键必须**可哈希**（不是任何类型都能当键）；③ **空间换时间**——桶数组有额外内存开销；④ 最坏情况（大量冲突）退化回 O(n)。

2. **`删除(1..2)` 删了几个？**
   半开区间 [1, 2)：**1 个**（下标 1）；`删除(1..3)` 删 **2 个**（下标 1、2）。含头不含尾——`1..3` 不删下标 3：

```cangjie
导入 标准集合.*

主函数() {
    可变 列表 = 向量<整数>()
    列表.添加(10)
    列表.添加(20)
    列表.添加(30)
    列表.添加(40)
    列表.删除(1..2)              // 半开区间：只删下标 1
    打印行(列表 |> 收集数组)     // [10, 30, 40]
}
```

3. **怎么避免依赖顺序的 bug？**
   三条路：① 输出前**排序**（依赖顺序的场景直接排序，别赌哈希顺序）；② 顺序本身就是需求 → 用数组/向量（保序容器）；③ 只关心「有没有/取某个键」，那就无所谓顺序。原则：**哈希映射只当字典用，别当列表用**。

4. **lambda 里为什么不能用 `跳出`/`继续`？**
   `跳出`/`继续` 属于**循环**；lambda 只是一个值（函数），它没有自己的循环上下文——你写 `跳出` 时编译器不知道要跳出哪个循环。想提前结束遍历：用普通 `对于` + `跳出`；或者干脆换声明式思路——「跳过不想要的」用 `过滤`、「找到就停」用 `任一满足`（附录 C17）。

## 第 12 章 结构体与类

1. **为什么父类 `开放` + 子类 `重写` 双声明？**
   双向确认，杜绝两类 bug：
   - 子类侧（`重写`）：**防拼错**——想重写 `叫声` 却拼成 `叫生`，如果不需要声明 `重写`，编译器会当成新方法悄悄通过，多态就悄悄失效；强制声明后拼错 = 编译报错；
   - 父类侧（`开放`）：**防意外继承**——默认封闭，类作者明确「这块可以被扩展」才开放，防止别人继承你根本没打算被继承的类。
   
   继承是**双方向的承诺**，两个声明缺一不可（附录 C14）。

2. **结构体赋值是拷贝还是共享？**
   **两块独立数据**——`让 乙 = 甲`（结构体）后，改 `乙` 的字段不影响 `甲`（附录 C15 有实测演示）。这就是「值语义 + 线程安全」：每个变量拿着自己的副本，线程间不共享就**不可能数据竞争**——不需要锁，天然安全。

3. **`作为` 向下转换为什么返回 `选项`？**
   因为「转不成功」是**预期中的失败**——父类引用不一定是那个子类（`狗 作为 猫` 就失败）。预期失败的正确表达是 `选项`（第 14 章分工）：调用方必须处理「可能没有」。如果直接返回对象，转失败只能崩溃或悄悄给空；抛异常又把轻量判断变成重量级流程。`选项` 让「可能失败」成为类型的一部分，编译器逼你面对。

4. **结构体为什么不能多态？**
   多态需要**动态绑定**——运行时根据对象的真实类型决定调用哪个方法，这要求变量持有的是「引用」（间接层：先找引用，再找真实对象）。结构体是**值语义**：变量里直接装着数据本体，拷贝时按**编译期的静态类型**复制，类型在编译时就定死了，没有「运行时再看真实类型」的机会。值类型没有动态绑定 = 结构体生来就是「确定的一块数据」。

## 第 13 章 枚举与模式匹配

1. **枚举漏分支报错，整数却要 `_` 兜底？**
   编译器对**封闭集合**全知：枚举的全部取值都写在定义里（`上|下|左|右`），编译器能检查你**是否覆盖了每一种**——漏一个就报错，这是特性不是刁难：改枚举加成员时，编译器会列出所有需要补分支的地方（穷尽性检查）。整数是**开放集合**（无限多个值），编译器不可能穷举，所以你必须写 `_` 兜底「剩下的我不管」。

2. **`情况 通知.文本(文字)` 里的 `文字` 哪来的？**
   **解构绑定**：`通知.文本(...)` 这个模式不仅匹配「是文本通知」，还把携带的数据**当场拆出来**绑定到新变量 `文字`——模式就是「形状 + 提取器」二合一。匹配成功的同时，数据已经在手，不用再手动取。

3. **魔法数字为什么是坏味道？**
   `如果 (状态 == 2)` 里的 `2` 是什么？没人知道。数字**没有名字、没有范围**——拼错成 `3` 编译器不拦你（任何整数都合法），改需求时不知道哪些 `2` 要一起改。用枚举：`如果 (状态 == 状态.完成)`——有名字、编译器检查取值合法性、新增成员时穷尽性检查帮你找全所有使用点。

4. **守卫和 `如果` 本质相同，`匹配` 的额外价值在哪？**
   单看一个守卫，确实和 `如果` 等价。但 `匹配` 把**判断、解构、穷尽性**收进一个结构：多个分支并列时谁是谁一目了然，模式自动拆数据，漏情况编译器报警。什么时候用哪个？**枚举/结构化数据**（形状各异、要拆包）用 `匹配`；**连续数值范围**（分数 >= 90 这种区间）用 `如果` 更直白——工具按场景选。

## 第 14 章 错误处理与并发

1. **`获取或抛出()` vs 解引用空指针**
   空指针是**忘了判空**的意外崩溃——错误在千里之外爆炸，你还不知道为什么。`获取或抛出()` 是**显式声明**：「这里必须有值，没有就是 bug，立刻失败！」——错误在**源头**大声暴露（Fail fast），栈信息直接指向出问题的值。它适合「逻辑上不可能为空，但类型上可能是选项」的场合：要么拿到值继续，要么立刻崩溃让我知道逻辑错了。

2. **为什么吞掉异常最危险？**
   `捕获 (e: 异常) { /* 什么都不做 */ }` 之后，程序**带病继续运行**——错误被藏起来，后续所有行为都可能在错误数据上展开：算错账、写错文件、发错消息，直到某天在完全不相干的地方爆炸，而真正的错误早已无法追溯。**静默失败是最难调试的失败**。吞异常 = 亲手把证据销毁。宁可让程序崩溃，也不要让它带着错误活下去。

3. **两个任务同时 `计数 += 1` 会发生什么？**
   `计数 += 1` 是**读-改-写三步**，不是原子操作：两个任务可能同时读到 `5`，各自 +1 再写回——两次自增只加了一次，结果 `6` 而不是 `7`（丢失更新）。`同步`/锁/原子把「读-改-写」变成不可分割的一步，任务排队执行，谁也不会读到半路状态。

```cangjie
导入 标准同步.*

主函数() {
    让 计数 = 原子整数(0)
    计数.原子加(1)     // 原子加 = fetchAdd：安全的 +=
    计数.原子加(1)
    打印行(计数.原子加载())    // 2
}
```

4. **`原子引用` 为什么只接受引用类型？**
   原子操作的本质是「多个任务操作**同一份**数据，且这份数据对所有人可见」。引用类型（对象）在堆上，大家通过引用看到**同一份**——原子性才有意义。字符串等值类型是**拷贝语义**：赋值/传参就复制一份，每个任务手里是自己的拷贝——各改各的副本，原子操作无处施展。原子 = 针对共享，值类型天生不共享。

## 第 15 章 泛型、接口与宏

1. **泛型 vs 宏：都能消除重复，区别在哪？**
   - **泛型**在**类型层**消除重复：一套代码服务多种类型（`取最大<T>` 对整数、字符串都能用）——编译后类型具体化，运行时的代码还是普通代码；
   - **宏**在**代码层**消除重复：编译期把「代码模板」展开成实际代码（`@测试` 展开成测试注册代码）——它操作的是**代码本身**（token），不是类型。
   
   一句话：泛型消「类型不同写法相同」，宏消「写法重复到要生成代码」。

2. **宏为什么不能做 IO？**
   可复现构建：宏在**编译期**执行——如果宏能读文件、访问网络，同一份源码在不同机器、不同时间编译会得到**不同的程序**（今天编译读到的配置、明天编译读到的就变了），构建结果不可复现、不可审计。把宏限制成「输入是代码、输出是代码」的纯变换，构建才可复现：谁编译、何时编译，产物都一样。

3. **`$(input)` 和 `$(input.toString())` 展开成什么？**
   `$(input)`：把 `input` 当**代码片段**（token）拼进宏输出——展开后出现的是标识符 `input`（如果它是变量名，展开结果里就是这个名字本身）；`$(input.toString())`：是**表达式求值**——编译期先算出 `input.toString()` 的结果（假设 `input = 3`，结果是字符串 `"3"`），把**字面量** `"3"` 拼进代码。`0.."3"` 类型错误：范围需要整数，字符串 `"3"` 不行。区别就是「拼接代码」vs「拼结果」。

4. **`@测试` 为什么需要两个导入？**
   展开分两层：`标准测试宏` 提供**宏本体**——`@测试`/`@期望` 要在编译期展开成什么代码，由它定义；展开后的代码会调用测试框架的**运行时类型**（注册用例、比较断言），这些在 `标准测试` 模块里。宏本体（编译期）和运行时类型（运行期）缺一不可——就像菜谱（宏）和食材（运行时）都要有，菜才做得出来。

## 第 16 章 程序设计思想

1. **「牺牲一点便利，换取一类 bug 绝迹」的例子**
   书里到处都是：`枚举` 匹配穷尽性检查（漏分支编译不过）；`选项` 消灭空指针（没有「忘了判空」）；`约束` 子句（泛型里乱调方法编译不过）；类型**全部显式转换**（隐式转换 bug 绝迹）；`让` 默认不可变（意外修改绝迹）。共同模式：**把一类错误从「运行期才发现」提前到「编译期就拒绝」**——代价是写代码时多写几个字，换来的是错误根本写不出来。

2. **吞掉错误怎么违背 Fail fast？**
   Fail fast 的核心是「错误越早暴露越好」：出错立刻大声说出来，错误就在**源头**、现场证据最全。吞掉错误 = 错误继续潜伏、程序带病运行，等到症状出现时，现场早已被后续几千行代码覆盖——**违背 Fail fast 等于放弃定位错误的最佳时机**。

3. **声明式和命令式各适合什么场景？**
   声明式（`映射`/`过滤`/`收集` 管道）：**数据处理**——「是什么」（选出及格、每人翻倍），管道直读，没有中间变量；
   命令式（循环 + 状态）：**流程控制**——有复杂的先后顺序、中途退出、多阶段状态（游戏主循环、交互流程），需要一步步「怎么做」。
   判断标准：描述「结果长什么样」用声明式，描述「过程怎么走」用命令式。

4. **「方言即配置」还暗示了什么？**
   整套系统的转译、诊断、错误消息全部由语言包数据驱动——**换一个语言包，整个工具链换一种语言**。这暗示：① **本地化（l10n）思想**：界面文案、术语、错误提示应该与逻辑分离，作为可替换的配置；② 「配置优于硬编码」：凡是可能随环境变化的，都抽成数据；③ 语言是「产品表面」，核心价值在逻辑与数据——所以支持新语言不是改代码，而是**加一份词表**。

## 第 17 章 算法与数据结构

1. **为什么二分查找要求有序？**
   二分每一步用「中间值 vs 目标」的比较结果**决定去哪一半**——比中间大去右半、小去左半。这个决策依赖「右半一定都比中间大」的**有序性**。无序时，比较结果没有任何方向信息（比中间大不代表在右边），二分就退化成瞎猜，还可能永远错过目标。

2. **栈和队列的生活例子；函数调用为什么用栈？**
   栈：叠盘子（后放上去的先拿）、浏览器后退历史、撤销操作；队列：食堂排队、打印机任务（先到先出）。函数调用天然是**后调用的先返回**——`甲()` 调 `乙()` 调 `丙()`，返回顺序必须是丙→乙→甲（丙的结果是乙需要的）——这正是栈的进出顺序，所以运行时用**调用栈**管理。

3. **`阶乘(10000)` 会怎样？**
   栈溢出崩溃——每层递归都要在调用栈上占一帧（记录参数、返回地址），一万层远超栈容量。深度限制保护了你：**无限递归（忘了出口）会在可控的地方停下来报错**，而不是悄悄把内存耗尽拖垮整个系统。递归前先问：深度会到多少？（尾递归/循环可化解，但 10000 层无论如何都不该用递归）

4. **哈希冲突时查找还是 O(1) 吗？**
   不是。冲突的元素会挂在同一个桶（链表/探测链），查找时要**逐个比**——退化到 O(n)。什么时候退化？① 哈希函数设计差（大量键算出同桶）；② 恶意构造同哈希的数据（攻击者可以让哈希映射变成链表）。工程对策：哈希函数要均匀，冲突过多时扩容重哈希——平均 O(1) 是「假设哈希均匀」的期望值，不是保证。

## 第 18 章 软件工程基础

1. **为什么测试比注释可信？**
   注释是**人写的愿望**：写的时候是真的，代码改版后没人同步更新，注释就静默过期——**过期的注释不会报错**，还会误导后来的读者。测试是**机器执行的检查**：代码一改，测试要么过要么红——**测试过期会红**，立刻暴露。一个会说谎（过期注释），一个不会（红了就是红了）——所以「测试即文档」。

2. **为什么「两次重复别急着抽象」？**
   第二次重复可能是**巧合**——两处只是碰巧长得像，背后的变化方向可能完全不同。这时候抽象 = **猜**它们的共同点，猜错就造出一个错误的抽象，比重复更糟（所有用它的地方都被错误设计绑架）。第三次重复出现时，共同模式才真正浮现，抽象的方向才可靠。工程谚语：**三振出局**——三次重复才该抽象。

3. **`1.2.0` 和 `1.2.3` 的区别？**
   语义化版本：`主.次.补丁`——`1.2.0` 是**次版本**：加了新功能但**向后兼容**（老代码照跑）；`1.2.3` 是**补丁**：只修 bug，不动行为。`2.0.0` 是**主版本**：允许破坏性变更（API 改了、老代码可能跑不了）——所以要谨慎：一旦发布 2.0.0，所有依赖方的升级都要跟着改代码，迁移成本高、生态会分裂成「用 1.x 的」和「用 2.x 的」。

4. **为什么先「最小复现」再「读错误全文」？**
   错误信息可能是**连锁反应**：真正的 bug 在第 1 步，报错却炸在第 10 步——直接读报错容易被带到沟里（修错地方）。最小复现先把噪音剥掉（去掉无关输入、无关代码），让 bug **稳定、独立**地出现：① 排除了「运气好才触发」的假象；② 修完能立刻验证「真的修好了」。先复现 = 先给 bug 拍照建档，再开始破案。

## 第 19 章 综合实战：完整项目

1. **`解析数字` 为什么返回 `选项` 而不是捕获异常？**
   用户输入乱码是**预期中的失败**——游戏必然遇到，不是 bug。预期失败的正确表达是 `选项`：调用方（主函数）用 `获取或默认` 兜底，流程清晰。如果用 `尝试/捕获` 包 `整数.解析`：① 异常是为「意外错误」设计的，用它做控制流会掩盖真正的 bug（分不清「输入乱」和「系统坏了」）；② 每处解析都要写 `尝试`/`捕获` 块，代码噪音大。分工原则：**预期失败走选项，意外错误走异常**（第 14 章）。

2. **嵌套循环的出口分别是什么？**
   内层（`玩一局` 的 `当 (真)`）：**两个 `返回`**——猜中时返回、输入「退出」时返回；返回会结束整个 `玩一局` 函数，内层循环自然结束。外层（主函数的 `当 (真)`）：`读取行() == "退出"` 时 **`跳出`** 跳出外层循环，打印「再见」。注意分工：内层用 `返回`（连函数一起退），外层用 `跳出`（只退循环）——它们退出的是**不同层级**。

3. **`检查猜测` 改成内部打印，测试会变难吗？**
   会变难。纯函数返回 `字符串`，测试直接断言返回值：`@期望(检查猜测(50, 30), "小了")`——干净利落。如果它内部直接打印，测试就得**捕获标准输出**再对比文本（多了 IO 依赖、换行格式敏感），而且函数「又计算又输出」，职责混在一起。**纯函数最好测**——这正是把核心逻辑拆成纯函数（19.2 设计）的原因：测试简单，重构才敢做。

4. **重构时为什么必须有测试保底？**
   重构 = 不改行为只改结构。没有测试，你怎么知道行为没变？「看起来跑得动」不是证据——边界情况（猜中边界 1、100，输入空串）可能已经悄悄坏了。测试是**安全网**：每次重构后跑一遍，全绿 = 行为确认没变，可以放心继续；没有安全网的走钢丝，改坏了没人知道，等用户发现时已经找不出是哪次改动引入的。

5. **终极挑战：枚举版漏分支会发生什么？**
   编译**直接报错**（穷尽性检查，第 13 章）：编译器检查 `匹配 (结果)` 是否覆盖了 `结果` 枚举的全部成员，漏写「大了」分支，编译器会列出你漏掉的那个成员。这正是枚举 + 匹配的价值——**错误在编译期现形**，而不是运行到某个输入时才崩溃。加新成员 = 编译器逼你把所有处理点补全。

## 第 20 章 扩展与运算符重载

1. **为什么扩展不能添加存储字段？**
   两个角度：
   - **类型布局**：类型的内存布局（每个字段的偏移、大小）在定义处就定死了。编译器给 `类` 分配空间时按定义时的字段清单算，扩展是「后到的代码」，改布局会让所有已编译调用方失效（A 模块扩展加了字段，B 模块按旧布局访问就错位）——所以只能加方法（方法不占实例空间）。
   - **多模块各自扩展**：如果扩展能加字段，两个模块各自给 `整数` 加一个字段，内存里该放谁的？冲突无解。限制「只加行为不加状态」后，扩展天然互不干扰——**每个模块的外挂只碰自己的方法表，不碰别人的数据**。

2. **给 `学生` 重载 `==` 与 `<`：**

```cangjie
// 学生类重载 ==（比较学号）与 <（按学号排序）
类 学生 {
    公开 让 学号: 整数
    公开 让 名字: 字符串
    初始化(学号: 整数, 名字: 字符串) {
        本对象.学号 = 学号
        本对象.名字 = 名字
    }
}
扩展 学生 {
    公开 运算符 函数 ==(其他: 学生): 布尔 { 返回 本对象.学号 == 其他.学号 }
    公开 运算符 函数 <(其他: 学生): 布尔 { 返回 本对象.学号 < 其他.学号 }
}
主函数() {
    让 甲 = 学生(1, "小明")
    让 乙 = 学生(1, "小明")     // 另一个对象，学号相同
    让 丙 = 学生(2, "小红")
    打印行("甲 == 乙？${甲 == 乙}")   // true：内容相等而非引用相等
    打印行("甲 < 丙？${甲 < 丙}")     // true
}
```
   要点：`==` 只比学号不比名字——「相等语义」由你定义：现实中两个学号相同的人就是同一个人，即使名字字段不同（数据录入差异）也应判等。实测输出：`甲 == 乙？true`、`甲 < 丙？true`。

3. **`@派生(相等)` 与手写 `==` 的分工？**
   - `派生` 是**逐字段比较**的机械实现：适合「字段就是相等性」的值类型（坐标、颜色）——一行生成 `==`/`!=`，零维护；
   - 手写是**自定义语义**：`分数` 的交叉相乘（`1/2 == 2/4` 为真）、`学生` 只比学号——相等性**不等于字段全等**时，派生会给出错误答案；
   - 场景选择：相等 = 逐字段相等 → 用 `派生`；相等 = 某种业务规则 → 手写。**手写时记得 `!=` 也要写**（`返回 !(本对象 == 其他)`）——`派生` 会生成一对，手写只写 `==` 的话 `!=` 不会自动取反。
