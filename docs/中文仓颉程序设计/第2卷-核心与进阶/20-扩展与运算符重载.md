# 第 20 章 扩展与运算符重载

> **本章学习目标**：掌握「不修改类型源码，也能给它添加行为」的两把钥匙——`扩展`（外挂方法/接口实现）与 `运算符` 重载（让自定义类型支持 `+`、`==`、`[]` 等原生写法）。理解它们与继承/重写（第 12 章）的分工，写出读起来像「语言原生类型」的自定义类型。
> **读完本章你能回答**：为什么说扩展是「外挂式」的？扩展能不能加存储字段？`+=` 能直接重载吗？给类型重载 `+` 之前要想清楚什么？

---

## 20.1 从思想到实操：为什么需要扩展

第 16 章 16.9 讲过扩展的思想：经典 OO 里「修改类」有两个痛点——**无权改**（标准库、别人写的类）与**改了影响所有人**（脆弱的基类）。`扩展` 把「添加行为」变成**外挂式**操作：每个模块只给自己关心的类型挂方法，互不干扰。

本章把思想变成肌肉记忆。先看一个最直接的例子——给官方整数类型挂方法：

```cangjie
// 扩展方法：给官方类型挂上「外挂方法」（不修改原类型）
扩展 整数 {
    公开 函数 加倍(): 整数 { 返回 本对象 * 2 }
    公开 函数 是偶数(): 布尔 { 返回 本对象 % 2 == 0 }
}

主函数() {
    让 数字 = 21
    打印行("${数字} 加倍 = ${数字.加倍()}")
    打印行("${数字} 是偶数？${数字.是偶数()}")
    打印行("100 加倍 = ${100.加倍()}")
}
```

运行结果：

```
21 加倍 = 42
21 是偶数？false
100 加倍 = 200
```

三个要点：

1. `扩展 类型 { ... }` 的写法与类体一模一样——方法、属性访问器都可以写；
2. 方法内部用 `本对象` 访问「被扩展的值」：`数字.加倍()` 里，`数字` 就是 `本对象`；
3. 字面量也能直接调：`100.加倍()`——因为扩展作用于**类型**，不作用于某个变量。

## 20.2 扩展的边界：能加行为，不能加家底

扩展能挂**方法**（函数/属性访问器），但不能给类型加**存储字段**——因为存储布局在类型定义时就定死了，外挂无法改变它。

| 能做什么 | 不能做什么 |
|---|---|
| 加函数（方法） | 加 `让`/`可变` 存储字段 |
| 加属性访问器（`获取`/`设置`） | 改变类型的继承关系（但可补接口实现，见 20.3） |
| 加运算符重载（见 20.4-20.6） | 访问原类型的私有成员（可见性规则不变） |

这条边界其实是**优点**：扩展只能「加行为」不能「加状态」，意味着扩展永远不会把两个模块的状态搞乱——它们各自挂方法，互不干扰。

## 20.3 扩展实现接口：让毫不相干的类型拥有共同行为

第 12 章讲过：接口是「能力契约」，`类 狗 <: 会叫` 在**定义类的时候**声明能力。但遇到「别人定义的类，我想让它们统一处理」怎么办？——`扩展 X <: 接口`：

```cangjie
// 扩展实现接口：让「毫不相干」的类型获得共同行为（外部实现接口）
接口 会叫 {
    函数 叫声(): 字符串
}

类 狗 {}
类 猫 {}
类 闹钟 {}

扩展 狗 <: 会叫 {
    公开 函数 叫声(): 字符串 { 返回 "汪汪" }
}
扩展 猫 <: 会叫 {
    公开 函数 叫声(): 字符串 { 返回 "喵喵" }
}
扩展 闹钟 <: 会叫 {
    公开 函数 叫声(): 字符串 { 返回 "叮铃铃" }
}

主函数() {
    让 伙伴们: 数组<会叫> = [狗(), 猫(), 闹钟()]
    对于 (伙伴 在 伙伴们) {
        打印行(伙伴.叫声())
    }
}
```

运行结果：

```
汪汪
喵喵
叮铃铃
```

教学重点：

- `狗`、`猫`、`闹钟` 定义时互不相干，**之后**通过三个 `扩展 … <: 会叫` 补上同一个能力；
- 补完能力后，它们就能被装进 `数组<会叫>` 统一调用——**多态不需要提前规划**；
- 适用范围：给自己的类补接口、给第三方库的类补接口（前提：接口与类型都在本模块可见）。

> **思想贴士**：扩展实现接口是「组合优于继承」的最强形态——继承要求你**预知未来**（写类时就想好一切子类），扩展允许你**随时补票**。标准库的很多「方言方法」（`修剪`/`分割` 等）正是通过扩展机制挂到字符串/集合上的。

## 20.4 运算符重载：让你的类型支持「+」

### 20.4.1 成员式重载

先看类内直接声明运算符——给向量类定义自己的 `+` 和 `==`：

```cangjie
// 类内声明运算符重载：给类定义自己的「+」
类 向量 {
    公开 让 横向: 整数
    公开 让 纵向: 整数
    初始化(横向: 整数, 纵向: 整数) {
        本对象.横向 = 横向
        本对象.纵向 = 纵向
    }

    公开 运算符 函数 +(其他: 向量): 向量 {
        返回 向量(本对象.横向 + 其他.横向, 本对象.纵向 + 其他.纵向)
    }
    公开 运算符 函数 ==(其他: 向量): 布尔 {
        返回 本对象.横向 == 其他.横向 && 本对象.纵向 == 其他.纵向
    }
}

主函数() {
    让 甲 = 向量(1, 2)
    让 乙 = 向量(3, 4)
    让 丙 = 甲 + 乙            // 你的类第一次支持「+」
    打印行("甲 + 乙 = (${丙.横向}, ${丙.纵向})")
    打印行("甲 == 乙？${甲 == 乙}")
    打印行("甲 == 向量(1, 2)？${甲 == 向量(1, 2)}")
}
```

运行结果：

```
甲 + 乙 = (4, 6)
甲 == 乙？false
甲 == 向量(1, 2)？true
```

语法解剖——`公开 运算符 函数 +(...)`：

| 片段 | 含义 |
|---|---|
| `公开` | 可省略（类内成员默认可见性规则同普通函数） |
| `运算符` | 声明这是运算符重载（写在函数名位置前） |
| `函数` | 与普通函数共用 `函数` 关键字 |
| `+` | 要重载的运算符符号，写在函数名位置 |
| `(其他: 向量)` | 参数：二元运算符右操作数（一元运算符无参数） |
| `: 向量` | 返回类型：`+` 通常返回新对象 |

`甲 + 乙` 会被编译器改写为调用 `甲.+(乙)`——注意**左操作数是接收者**，所以 `==` 重载里 `本对象` 就是左边的 `甲`。

### 20.4.2 不重载 `==` 会怎样？

默认 `==` 对类做**引用比较**（两个变量是否指向同一对象），而不是内容比较——两个内容相同的 `向量(1, 2)` 是不相等的。所以「值语义的类」几乎总要重载 `==`。这也解释了第 9 章「选项里的自定义类不能直接比相等」的坑：本质是那个类没有重载 `==`。

**注意：`!=` 不会自动取反**。只重载 `==` 后写 `甲 != 乙`，编译器会提示你补 `运算符 函数 !=`（或者用第 15 章的 `@派生(相等)` 一键生成完整相等性）。需要两个都写时，`!=` 的经典写法是 `返回 !(本对象 == 其他)`——只维护一处逻辑。

## 20.5 扩展式运算符：不修改类，行为照样外挂

运算符重载和扩展是**正交**的——可以组合：在 `扩展` 块里给别人的类加运算符。这是最常用的姿势：

```cangjie
// 扩展运算符：不修改类，行为照样外挂
类 点 {
    公开 让 横向: 整数
    公开 让 纵向: 整数
    初始化(横向: 整数, 纵向: 整数) {
        本对象.横向 = 横向
        本对象.纵向 = 纵向
    }
}

扩展 点 {
    公开 运算符 函数 +(其他: 点): 点 {
        返回 点(本对象.横向 + 其他.横向, 本对象.纵向 + 其他.纵向)
    }
    公开 运算符 函数 ==(其他: 点): 布尔 {
        返回 本对象.横向 == 其他.横向 && 本对象.纵向 == 其他.纵向
    }
    公开 运算符 函数 !(): 点 {        // 一元运算符：关于原点对称
        返回 点(-本对象.横向, -本对象.纵向)
    }
    公开 运算符 函数 <(其他: 点): 布尔 {   // 到原点距离比较（平方）
        返回 本对象.横向 * 本对象.横向 + 本对象.纵向 * 本对象.纵向
               < 其他.横向 * 其他.横向 + 其他.纵向 * 其他.纵向
    }
}

主函数() {
    让 甲 = 点(1, 2)
    让 乙 = 点(3, 4)
    让 丙 = 甲 + 乙
    打印行("甲 + 乙 = (${丙.横向}, ${丙.纵向})")
    打印行("!甲 = (${(!甲).横向}, ${(!甲).纵向})")
    打印行("甲 < 乙？${甲 < 乙}")
}
```

运行结果：

```
甲 + 乙 = (4, 6)
!甲 = (-1, -2)
甲 < 乙？true
```

注意一元运算符调用要加括号：`(!甲).横向`——因为 `!` 的优先级低于 `.`，`!甲.横向` 会被解析成 `!(甲.横向)`。

### 20.5.1 复合赋值 `+=`：不能重载，但自动展开

`+=`、`-=`、`*=` 这类复合赋值**不允许直接重载**。但好消息是：只要重载了 `+`，`a += b` 会自动展开成 `a = a + b`——前提是 `a` 是 `可变` 绑定：

```cangjie
// 复合赋值 +=：不能直接重载，但重载 + 后自动展开（a += b ⇒ a = a + b）
类 计数 {
    公开 可变 值: 整数
    初始化(值: 整数) { 本对象.值 = 值 }
}
扩展 计数 {
    公开 运算符 函数 +(其他: 计数): 计数 {
        返回 计数(本对象.值 + 其他.值)
    }
}
主函数() {
    可变 甲 = 计数(10)
    甲 += 计数(5)        // 等价于 甲 = 甲 + 计数(5)
    打印行("甲的值 = ${甲.值}")
}
```

运行结果：

```
甲的值 = 15
```

## 20.6 索引运算符：让自定义类型支持 `[]`

`[]` 是「按下标取元素」的运算符。集合有它（`数组[0]`），自定义类型也可以有：

```cangjie
// 索引运算符 []：让自定义类型支持「下标读写」
类 双人队 {
    公开 让 甲: 字符串
    公开 让 乙: 字符串
    初始化(甲: 字符串, 乙: 字符串) {
        本对象.甲 = 甲
        本对象.乙 = 乙
    }
}

扩展 双人队 {
    公开 运算符 函数 [](索引: 整数): 字符串 {
        如果 (索引 == 0) {
            返回 本对象.甲
        }
        返回 本对象.乙
    }
}

主函数() {
    让 队伍 = 双人队("阿明", "小美")
    打印行("第 1 名：${队伍[0]}")
    打印行("第 2 名：${队伍[1]}")
}
```

运行结果：

```
第 1 名：阿明
第 2 名：小美
```

`运算符 函数 []` 只读版即可让 `队伍[0]` 成立。真实容器（如第 11 章的集合）还会配合 `设置` 提供读写两版——但教学上记住：**先给只读版，够用且安全**。

## 20.7 运算符重载的纪律：能重载什么，不能乱来

### 能重载的运算符面（常用子集）

| 类别 | 运算符 | 参数 | 典型返回 |
|---|---|---|---|
| 四则 | `+` `-` `*` `/` `%` | 1 个（右操作数） | 新对象 |
| 比较 | `==` `!=` `<` `>` `<=` `>=` | 1 个 | `布尔` |
| 一元 | `!`（逻辑非/取反） | 0 个 | 同类对象或布尔 |
| 下标 | `[]` | 1 个（索引） | 元素类型 |

### 不能碰的底线

1. **不能创造新符号**：只能重载语言已有的运算符，`**`（幂）、`<>`（自己发明的尖括号）都不存在——重载不会增加语法；
2. **不能改变元数与优先级**：`+` 永远是二元、优先级永远不变——`甲 + 乙 * 丙` 仍然先算乘法；
3. **不能重载**：`=`（赋值）、`&&`/`||`（短路）、`?:`（三元，仓颉无）、复合赋值 `+=` 等（自动展开）；
4. **语义一致性**：`+` 应该可交换（`甲 + 乙 == 乙 + 甲`）、`==` 应该自反（`甲 == 甲`）且与 `!=` 互补——把 `+` 重载成「减法」编译器不管，但读你代码的人会疯掉；
5. **继承体系内慎用覆盖**：编译器对「子类重定义父类运算符」限制严格（签名必须完全一致且父类需 `开放`），想要差异化行为时**优先考虑扩展**而不是继承覆盖——这也符合 16.9「组合优于继承」。

> **对比记忆**：`重写` 是**继承体系内**改父类实现（第 12 章）；`运算符` 是**类型行为面**扩展语法。二者关键词不同、场景不同——运算符重载与 `重定义` 修饰符同时出现会报冲突，别混用。

## 20.8 综合案例：分数类

把本章两把钥匙合起来：一个「行为完整」的分数类（分子/分母），加减乘、相等比较全部支持原生写法：

```cangjie
// 综合案例：分数类（四则运算 + 相等比较）
类 分数 {
    公开 让 分子: 整数
    公开 让 分母: 整数
    初始化(分子: 整数, 分母: 整数) {
        本对象.分子 = 分子
        本对象.分母 = 分母
    }
}

扩展 分数 {
    公开 运算符 函数 +(其他: 分数): 分数 {
        返回 分数(本对象.分子 * 其他.分母 + 其他.分子 * 本对象.分母,
                    本对象.分母 * 其他.分母)
    }
    公开 运算符 函数 -(其他: 分数): 分数 {
        返回 分数(本对象.分子 * 其他.分母 - 其他.分子 * 本对象.分母,
                    本对象.分母 * 其他.分母)
    }
    公开 运算符 函数 *(其他: 分数): 分数 {
        返回 分数(本对象.分子 * 其他.分子, 本对象.分母 * 其他.分母)
    }
    公开 运算符 函数 ==(其他: 分数): 布尔 {
        返回 本对象.分子 * 其他.分母 == 其他.分子 * 本对象.分母
    }
}

主函数() {
    让 一半 = 分数(1, 2)
    让 三分一 = 分数(1, 3)
    让 和 = 一半 + 三分一
    让 差 = 一半 - 三分一
    让 积 = 一半 * 三分一
    打印行("1/2 + 1/3 = ${和.分子}/${和.分母}")
    打印行("1/2 - 1/3 = ${差.分子}/${差.分母}")
    打印行("1/2 × 1/3 = ${积.分子}/${积.分母}")
    打印行("1/2 == 2/4？${一半 == 分数(2, 4)}")
}
```

运行结果：

```
1/2 + 1/3 = 5/6
1/2 - 1/3 = 1/6
1/2 × 1/3 = 1/6
1/2 == 2/4？true
```

注意 `==` 的实现用**交叉相乘**（`分子1 × 分母2 == 分子2 × 分母1`）而不是逐字段比较——`1/2` 与 `2/4` 存储不同但数值相等，这正体现了「重载 `==` 是在定义你的类型的相等语义」。

> **真实感**：上面所有代码块都经过 `zhc run` 实测（输出见各段）。扩展 + 运算符是「自定义类型体验」的分水岭——做完分数类，你的类型用起来就和 `整数`、`字符串` 一样自然。

## 小结

- `扩展` = 不给类型加存储、只加行为的**外挂**；`扩展 X <: 接口` 可让已有类型事后获得接口能力；
- `运算符 函数 +` 等 = 让自定义类型支持原生运算符写法，写在类内或 `扩展` 块内皆可；
- `+=` 不可直接重载但 `+` 重载后自动展开（需 `可变` 绑定）；`[]` 提供下标读取；
- 纪律：不造新符号、不改优先级/元数、保持语义一致、继承覆盖受限时优先扩展；
- 与第 12 章 `重写` 分工：`重写` 管继承体系内的方法覆盖，`运算符` 管类型的行为面。
