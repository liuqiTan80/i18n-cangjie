# 第 15 章 泛型、接口与宏

> **本章学习目标**：掌握「写通用代码」的两大机制——泛型（类型参数化 + 约束）与宏（编译期代码变换），会用 `@测试`/`@期望` 写单元测试，用 `zhc expand` 观察宏展开。
> **读完本章你能回答**：泛型和宏解决什么问题？`$(...)` 和 `${...}` 有什么不同？为什么要两步编译？

## 15.1 泛型函数：一个函数，所有类型

**定义**：泛型 = **类型参数化**——写一个函数，让它对任何类型都适用（不用为每种类型复制一份）。`<T>` 是类型参数，调用时自动实例化。

**中文语法**：

```cangjie
函数 取第一个<T>(列表: 数组<T>): T {
    返回 列表[0]
}

主函数() {
    打印行(取第一个([1, 2, 3]))          // 1（推断 T = 整数）
    打印行(取第一个(["甲", "乙"]))       // 甲（推断 T = 字符串）
}
```

**注意事项**：

- 类型参数写在函数名后 `<T>`，**大写开头**是惯例（`T`、`K`、`V`）；
- 调用时通常不用写类型参数——编译器从实参**自动推断**（`取第一个([1,2,3])`）；
- 泛型是**编译期**机制：运行时没有泛型（每个具体类型生成一份代码）——零运行时开销。

## 15.2 泛型类型：容器的基础

**定义**：泛型不只是函数——**类型**也可以参数化：`向量<T>`、`哈希映射<K, V>`、`选项<T>` 都是泛型类型。你已经在用了！

**中文语法**：

```cangjie
导入 标准集合.{向量}

结构体 盒子<T> {
    公开 可变 内容: T
    初始化(内容: T) { 本对象.内容 = 内容 }
}

主函数() {
    让 整数盒 = 盒子<整数>(42)
    让 文字盒 = 盒子<字符串>("仓颉")
    打印行(整数盒.内容)    // 42
    打印行(文字盒.内容)    // 仓颉

    可变 名单 = 向量<字符串>()
    名单.添加("甲")
    打印行(名单[0])        // 甲
}
```

**注意事项**：空容器**必须标注类型参数**（`向量<字符串>()`——不标编译器不知道装什么）；泛型类型名用大写（`盒子` 是中文无大小写之分，但内容约定写清）。

## 15.3 约束：泛型的边界

**定义**：泛型太自由也不行——`<T>` 上调用 `.比较` 方法编译器不认（T 可能是任何类型）。**约束**限定 T 必须满足什么条件：`约束 T <: 可比较<T>`。

**中文语法**：

```cangjie
函数 取最大<T>(列表: 数组<T>): T 约束 T <: 可比较<T> {
    可变 最大 = 列表[0]
    对于 (项 in 列表) {
        如果 (项 > 最大) { 最大 = 项 }
    }
    返回 最大
}

主函数() {
    打印行(取最大([3, 7, 2, 9]))          // 9
    打印行(取最大(["甲", "乙", "丙"]))    // 丙（字符串也可比较）
}
```

**注意事项**：

- `约束 T <: 可比较<T>`——T 必须是实现了 `可比较` 接口的类型；**泛型接口做约束要带类型参数**（写 `可比较<T>`，不能只写 `可比较`）；
- 约束写在**返回类型之后、函数体之前**：`函数 名<T>(参数): 返回类型 约束 T <: 可比较 { ... }`——返回类型在前；
- 没有约束的泛型只能做「放进去、取出来」——想调用方法必须有约束（约束是「能力清单」，第 12 章接口思想在泛型里的延伸）。

> 💡 实测提示：`约束` 子句形如 `约束 T <: 可比较<T>`；`可比较` 是 zh 语言包收录的类型词，必须写成 `可比较<T>` 形式约束才生效，`>` 等比较运算符才会被允许。

## 15.4 宏是什么：编译期执行的代码变换器

**定义**：宏是**编译期代码变换器**——吃代码 token，吐代码 token。调用写作 `@宏名(参数)`。普通函数只能操作**值**（运行时）；宏能操作**代码本身**（编译期）。

**宏能做函数做不到的三件事**：

1. **语法糖再造**：把重复模式（记录日志、测量耗时）打包成宏调用；
2. **编译期检查**：在编译期验证模式（如 DSL 语法校验）；
3. **性能**：展开在编译期完成，**运行时零开销**。

**注意事项**：仓颉的宏是**卫生宏**（不会意外捕获调用方变量）+ **类型化**（输入输出都是代码 token 流）——比 C 预处理器的文本替换安全得多；宏调用以 `@` 开头；宏名可用**中文**；宏展开错误在编译期报告。

## 15.5 宏包与宏定义

> ⚠️ **全书唯一的官方语法区**：宏包源码（本节与 15.6-15.8 里的 `macro package` 代码）**必须写官方仓颉语法**——宏包 `.cj` 文件不经方言转译，这是仓颉编译器的硬约束，其中的英文词（`macro package`/`import`/`Tokens` 等）不是漏网。**方言侧（`.zc`）代码全书依然全中文**，只有宏包这一处例外。

**定义**：宏必须定义在**宏包**中——源码**首行** `macro package 包名`。宏包只暴露宏。宏包内写**官方仓颉语法**（`.cj` 文件不经方言转译）。

**中文语法**（宏包文件 `define/define.cj`）：

```cangjie
// define/define.cj —— 宏包源码（宏包内写官方仓颉语法，不经方言转译）
macro package define
import std.ast.*

public macro 调试日志(input: Tokens): Tokens {
    let 名字 = input.toString()
    return quote(
        println($(名字))
    )
}
```

**要点（仓颉 1.0 宏规则，1.0.5 实测）**：

- 首行 `macro package <包名>`（**官方语法**——宏包 `.cj` 文件不经方言转译，写 `宏包`/`引用` 会编译报错）；
- 必须 `import std.ast.*`——`Tokens` 类型来自 `std.ast` 包（`std.macro` 不存在）；
- `public macro 名字(input: Tokens): Tokens`——参数与返回都必须是 `Tokens`；宏名可用**中文**；
- 宏包是**独立编译单元**：先被编译成宏库，主程序编译时展开——宏可以跨项目分发。

## 15.6 quote 与插值：用写代码的方式写代码

**定义**：`quote(...)`（引用）让你用**写代码的方式写代码**；`$(表达式)` 是**代码位置的插值**——把变量值/子代码 token 嵌入模板。

**两种插值的效果完全不同**：

| 写法 | 效果 | 例子 |
|---|---|---|
| `$(input.toString())` | 插入**字符串字面量** | `println("x + 1")`——打印表达式的**文本** |
| `$(input)` | 直接嵌入**代码 token** | `if ($(input) == 0)`——保持为**表达式** |

**注意事项**：`$()` 只在**代码位置**有效——字符串字面量里不会替换；`$(input.toString())` 插进字符串字面量同样不会替换——插值只发生在代码位置。注意区分：**`$()` 是代码插值（宏），`${}` 是字符串插值（第 10 章）**——两回事。

## 15.7 两步编译与 zhc expand

**定义**：宏包与主程序分两步编译——这是宏的「独立编译单元」设计在构建时的体现。

**两步编译流程（1.0.5 实测）**：

```bash
zhc eject main.zc                           # ① 方言 → 官方源码（main.cj）
cjc define/define.cj --compile-macro       # ② 编译宏包 → define.cjo + lib-macro_define.so
cjc main.cj -o main                        # ③ 编译主程序（import define.* 自动展开宏）
./main                                     # 运行
```

> 实测（1.0.5）：`zhc run` **不支持**宏包——日常验证展开用 `zhc expand main.zc --macro-pkg define/`（自动完成两步编译，见 15.8），或按上面三步手动编译运行。

## 15.8 宏展开教学视图：zhc expand

**定义**：`zhc expand` 查看展开前/后对照（官方 + 反向母语视图，位置映射回方言坐标）——学习宏行为的最佳工具：**先猜展开结果，再看视图验证**。

**中文语法**：

```bash
zhc expand main.zc --macro-pkg define/
```

## 15.9 派生宏：自动生成样板实现

**定义**：给类型标 `@派生(相等, 比较)`，编译器自动生成 `相等`/`比较`/`哈希` 等方法——结构体的这些实现**机械重复**（按字段逐个比较），手写又臭又容易错，派生宏是「约定优于配置」的典范。

**中文语法**：

```cangjie
// 语法示意（@派生 为系统宏，使用时宏库需先编译好）
结构体 学生 @派生(相等) {
    公开 可变 名字: 字符串
}
```

**注意事项**：派生条件——字段类型必须支持被派生的操作（派生 `比较` 要求字段都可比较）；方言 `派生` → 官方 `Derive`；派生宏与手写实现**二选一**（都写了报冲突）；派生宏要求宏库先编译好（两步编译）。

## 15.10 系统宏：@测试 与 @期望

**定义**：仓颉标准库自带测试框架（`std.unittest`）——`@测试` 标记测试函数、`@期望` 断言。

**中文语法**：

```cangjie
导入 标准测试宏.*
导入 标准测试.*

函数 加法(甲: 整数, 乙: 整数): 整数 { 返回 甲 + 乙 }

@测试
公开 函数 加法正确() {
    @期望(加法(2, 3), 5)   // 期望表达式的结果为 5
}
```

**要点（1.0.5 实测）**：

- **两个通配符导入都要写**：`标准测试宏`（测试框架宏本体）与 `标准测试`（断言等运行时类型），缺一不可；
- `@期望(实际值, 期望值)` 宏展开为完整断言代码，失败时给出两侧值；
- `@测试` 标记的函数由框架自动收集执行，无需手动调用。

项目根一键运行全部方言测试：

```bash
zhc test
```

## ✳ 设计思想

**① 元编程的时机：先函数，后泛型，最后宏**。90% 的「重复代码」用函数/泛型就能消除；只有当你需要**操作代码本身**（拿到表达式文本、生成语法结构）时，才轮到宏。宏是最后手段，不是第一选择——它牺牲可读性换取表达能力。

**② 编译期 vs 运行期**：宏把「每次运行都做的重复工作」提前到「编译时做一次」——运行时零开销。能编译期决定的，绝不拖到运行期；宏崩溃 = 编译错误（好事）——错误在最早时刻暴露。

**③ 约束即契约**：`约束 T <: 可比较` 是泛型的「能力清单」——泛型代码能调用什么方法，由约束说了算。这与接口（第 12 章）是同一思想的两面：**面向抽象编程，边界显式化**。

**④ 约定优于配置**：`@派生(相等)` 一行代替手写几十行样板——「机器能机械生成的，别让人手写」；`@测试`/`@期望` 让测试零门槛。

## 练习

1. 写一个泛型函数 `交换<T>(甲: T, 乙: T): (T, T)` 返回交换后的元组，分别用整数和字符串调用；
2. 写一个泛型函数 `查找<T>(列表: 数组<T>, 目标: T) 约束 T <: 相等: 整数`——找到返回下标，找不到返回 -1；
3. 写一个 `@打印表达式` 宏：展开为 `打印行("<表达式文本> = " + <表达式值>)`（提示：`$(input.toString())` 与 `$(input)` 各用一次）；
4. 用 `zhc expand` 查看自己宏的展开视图，确认位置映射；
5. 给 `结构体 学生` 派生 `相等`，验证两个字段相同的实例 `==` 为真。

## 小结

- 泛型：`函数 名<T>(...)` / `类型<T>`；调用自动推断；`约束 T <: 可比较` 限定能力；
- 宏包首行 `macro package <名>`（官方语法 + `import std.ast.*`），宏签名 `(Tokens) -> Tokens`，调用 `@宏名(...)`；宏名可用中文；
- 两步编译：`cjc 宏包 --compile-macro` → `cjc 主程序`；`zhc run` 不支持宏包，用 `zhc expand --macro-pkg` 验证；
- `quote()` 构造代码，`$(...)` 只在**代码位置**插值（`$(input)` 嵌代码、`$(input.toString())` 插文本）；区别于字符串插值 `${...}`；
- `@派生(相等)` 自动生成样板实现；`@测试`/`@期望` 是内置测试框架（两个导入缺一不可）。
