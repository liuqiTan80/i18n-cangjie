# 第 14 章 错误处理与并发

> **本章学习目标**：掌握仓颉**消灭空指针**的两套机制——`选项`（Option）空安全模式与 `尝试`/`捕获` 异常体系，并入门并发：`生成` 任务、`同步` 临界区、锁与原子操作。
> **读完本章你能回答**：`选项` 和异常各管什么场景？取不存在的键为什么会崩溃？多个任务改同一个变量会发生什么？

---

## 14.1 定义：空安全——没有 null 的世界

**定义**：仓颉**没有 `null`/`空指针`**。可空性进入类型系统——`选项<T>` 要么 `有值(x)`（Some），要么 `无值`（None）。函数返回 `选项<T>` 时，编译器**强制**你处理「可能没有」——空指针 bug 从「运行时崩溃」前移成「编译期错误」。

**中文语法**：

```cangjie
函数 找名字(编号: 整数): 选项<字符串> {
    如果 (编号 == 1) {
        返回 有值("小明")        // 有值 = Some：包装一个值
    }
    返回 无值                   // 无值 = None：表示「没有」
}

主函数() {
    匹配 (找名字(1)) {
        情况 有值(名字) => 打印行("找到：${名字}")
        情况 无值 => 打印行("没找到")
    }
}
```

**注意事项**：

- `无值` 可以赋给任何 `选项<T>`（类型由上下文推断）；
- `选项` 值**不能当普通值用**：`找名字(1) + "!"` 编译报错——必须先解包；
- 构造 `选项` 的三种方式：`有值(x)`、`无值`、`x.有值()`。

## 14.2 解包三兄弟：匹配 / 获取或默认 / 获取或抛出

**定义**：`选项` 拿不出里面的值就毫无用处。三种常用取法：

```cangjie
函数 找名字(编号: 整数): 选项<字符串> {
    如果 (编号 == 1) { 返回 有值("小明") }
    返回 无值
}

主函数() {
    // ① 匹配：安全分支（推荐，穷尽性检查）
    匹配 (找名字(1)) {
        情况 有值(名字) => 打印行("找到了：${名字}")
        情况 无值 => 打印行("没有这个人")
    }
    // ② 获取或默认：无值时给兜底值（参数是 lambda）
    打印行(找名字(1).获取或默认({ => "无名" }))
    // ③ 获取或抛出：确定有值才用；无值会抛异常
    打印行(找名字(1).获取或抛出())
}
```

**对照表**：

| 取法 | 语义 | 无值时 |
|---|---|---|
| `匹配` | 分支处理两种情况 | 走 `无值` 分支（最安全） |
| `获取或默认({ => 兜底 })` | 有值取值、无值用兜底 | 返回兜底值 |
| `获取或抛出()` | 确信有值 | 抛异常（程序崩溃） |

**注意事项**：`获取或默认` 的参数是 **lambda**（`{ => 0 }`）不是普通值；「宁可匹配，少用抛出」——`获取或抛出` 用错了等于把空安全又变回空指针。

## 14.3 预期失败用选项（官方没有 Result 类型）

**定义**：官方 1.0.5 **没有** `结果`（Result）类型——「可能失败」统一用 `选项<T>` 表达：成功是 `有值(成功值)`，失败是 `无值`。

**中文语法**：

```cangjie
导入 转换.*
导入 正则.*

函数 解析分数(文本: 字符串): 选项<整数> {
    如果 (正则("^\\d+$").匹配正则(文本)) {   // 锚定 ^...$：整串是数字才过
        返回 有值(整数.解析(文本))     // 是数字 → 成功
    }
    返回 无值                           // 不是数字 → 失败
}

主函数() {
    匹配 (解析分数("95")) {
        情况 有值(分数) => 打印行("分数：${分数}")
        情况 无值 => 打印行("不是数字")
    }
}
```

**注意事项**：失败是返回值的一部分，调用方**必须**处理——比异常更「函数式」，适合「**预期中的失败**」（格式错误、查无此人、越界）；`整数.解析` 需要 `导入 转换.*`；想带**失败原因**就返回 `选项<字符串>` 或在 `有值` 里放自定义枚举（第 13 章）。

> ⚠️ 实测提醒：`匹配正则` 是**包含匹配**——`正则("\\d+")` 对 `"a1"` 也返回真（匹配到子串 `1`）！先判断后解析的写法必须加锚 `^\\d+$`，否则 `"a1"` 会直接漏进 `整数.解析` 抛异常（第 10 章思考题 4、附录 C 踩坑）。

## 14.4 异常：意外错误的自动上抛

**定义**：不可预见的错误（除零、越界、协议错误）不适合用返回值逐层传播——异常沿调用栈**自动上抛**，谁有能力处理谁捕获。

**四个关键字**：

| 关键字 | 作用 |
|---|---|
| `抛出` | 主动制造异常，函数立即终止 |
| `尝试` | 圈出异常保护区 |
| `捕获` | 拦截指定类型的异常，程序继续执行 |
| `最终` | 无论是否异常都执行的收尾（关文件、释放锁） |

**中文语法**：

```cangjie
函数 除以(被除数: 整数, 除数: 整数): 整数 {
    如果 (除数 == 0) {
        抛出 异常("除数不能为零")       // 主动制造异常
    }
    返回 被除数 / 除数
}

主函数() {
    尝试 {
        让 结果 = 除以(10, 0)
        打印行("结果：${结果}")
    } 捕获 (错误: 异常) {
        打印行("出错了：${错误.消息}")   // 拦截指定异常
    } 最终 {
        打印行("无论成败都会执行")       // 无条件收尾
    }
}
```

**注意事项**：

- 常用异常子类：`算术异常`、`索引越界异常`、`类型转换异常`、`空值异常`、`参数异常`——捕获时按需细分；`捕获` 从上到下匹配**第一个兼容类型**（子类写在父类前面）；
- `抛出` 的表达式类型是 `空类型`（Nothing）——可以放在任何需要值的位置；
- `尝试` 必须有 `捕获` 或 `最终` 之一；`最终` 在 `返回` **之后**执行；`最终` 里不要写可能抛异常的代码；
- **不要用异常做常规控制流**（性能与可读性都差）——见 14.5 的分工。

## 14.5 选项 vs 异常：错误处理的分工

**定义**：判断标准只有一个——**这个失败是「预期中的」还是「意外的」？**

| 场景 | 选择 | 理由 |
|---|---|---|
| 解析用户输入（可能不是数字） | `选项` | 输入千奇百怪是**常态**，调用方必须处理 |
| 查表（键可能不存在） | `选项` | 查无此人不是程序错误 |
| 除零、下标越界 | 提前判断 + 异常兜底 | 好代码不该走到这一步；走到就是 bug |
| 文件损坏、内存不足 | 异常 | 意外情况，调用方通常无法预防 |

**经验法则**：能返回 `选项` 就返回 `选项`；异常留给「**这里不该出错**，出错了就是程序 bug」的情况。`获取或抛出` 就是「我确信有值，没有就是 bug」的宣言。

## 14.6 断言与前置检查

**定义**：程序员的自我检查——「这里不可能出错」。官方 `断言`（assert）只能在测试宏（`@测试`/`@期望`，第 15 章）内部使用；普通代码里的「不变量检查」用手写 `如果` + `抛出` 代替。

**中文语法**：

```cangjie
函数 取中间(列表: 数组<整数>): 整数 {
    如果 (列表.长度 == 0) {
        抛出 异常("空列表没有中间值")    // 前置检查：先校验再干活
    }
    返回 列表[列表.长度 / 2]
}

函数 设置年龄(年龄: 整数): 整数 {
    如果 (年龄 < 0 || 年龄 > 150) {
        抛出 异常("年龄不合法：${年龄}")
    }
    返回 年龄
}

主函数() {
    打印行(设置年龄(30))
    打印行(取中间([1, 2, 3]))
    // 打印行(设置年龄(-5))   // 会抛出异常
}
```

**注意事项**：前置检查帮助**尽早发现逻辑错误**（比错误蔓延成奇怪现象好得多）；但**不要用断言做输入校验**——用户输入要用 `选项` 或异常友好处理，断言是「程序自己错了」的信号。

## 14.7 退出（退出 / exit）

**定义**：立即终止进程：`退出(状态码)`——0 成功、非 0 失败。状态码让调用方（脚本/CI）知道成败。

**中文语法**：

```cangjie
导入 环境.*

主函数() {
    让 配置 = 读取行()
    如果 (配置 == "") {
        打印行("缺少配置")
        退出(1)              // 致命错误：终止进程，状态码 1
    }
    打印行("配置：${配置}")
}
```

**注意事项**：`退出` 返回 `空类型`（永不返回）；退出前 `最终` 块**不会**执行（进程直接终止）——需要清理先手动做；`退出` 是「无法继续」的最终手段，不要滥用。

## 14.8 并发入门：生成

**定义**：启动一个**并发任务**：`生成 { 任务代码 }`——把「这段代码放到另一个执行上下文跑」封装成函数调用。

**中文语法**：

```cangjie
主函数() {
    生成 { 打印行("任务一") }
    生成 { 打印行("任务二") }
    打印行("主函数")
}
```

**注意事项**：输出顺序**不确定**（三个任务并发执行，谁先打印都可能）；`生成` 返回任务句柄（可等待完成）；**并发共享可变数据必须同步**（见 14.9/14.10）——这是并发 bug 的头号来源。

## 14.9 同步：临界区

**定义**：多个任务同时改同一个 `可变` 数据会**数据竞争**（读到一半的值、丢失更新）。`同步(锁对象) { 临界区 }` 把代码块加锁——同一时刻只有一个执行上下文能进入。

**中文语法**：

```cangjie
导入 标准同步.{锁}

可变 计数 = 0

主函数() {
    让 锁对象 = 锁()
    同步(锁对象) {
        计数 += 1        // 临界区：同一时刻只有一个任务在改
    }
    打印行(计数)
}
```

**注意事项**：

- `同步` **必须带锁对象参数**（1.0.5 实测——不能 `同步 { }`）；
- **锁要小**：临界区越短越好；**不要嵌套同步**（死锁风险）；
- **不可变数据（`让`）不需要同步**——这是「默认不可变」的并发红利。

## 14.10 锁与原子

**定义**：更细粒度的并发原语：`原子整数`（AtomicInt64）、`原子引用`（AtomicReference）、`原子布尔`（AtomicBool）、`锁`（Mutex）。原子操作是无锁的「安全增减」——比同步块更快。

**中文语法**：

```cangjie
导入 标准同步.*

主函数() {
    // 原子计数：多任务安全增减
    让 原子计数 = 原子整数(0)
    生成 { 原子计数.原子加(1) }        // 原子加 = fetchAdd
    生成 { 原子计数.原子加(1) }
    打印行("原子计数：${原子计数.原子加载()}")   // 原子加载 = load

    // 锁的显式用法：加锁 / 解锁（成对出现）
    让 互斥锁 = 锁()
    互斥锁.加锁()
    互斥锁.解锁()
}
```

**注意事项（1.0.5 实测真相）**：

- 方言模块路径：`导入 标准同步.*`；
- 只有**整数原子**支持算术（`原子加` fetchAdd）；`原子引用`/`原子布尔` 只有读写与交换（`原子加载`/`原子存储`/`原子交换`）；
- `原子引用` **只接受引用类型**（类对象）——传 `字符串` 等值类型编译报错；
- `锁().加锁()`/`解锁()` 忘了解锁会卡死——用 `尝试/最终` 保证解锁（`尝试 { 互斥锁.加锁(); ... } 最终 { 互斥锁.解锁() }`）；
- 官方 `可重入锁`（ReentrantMutex）已弃用——统一用 `锁`（Mutex，本身可重入）。
## ✳ 设计思想

**① 错误处理是「设计决策」不是「语法」**：先给每个失败场景分类——预期失败（输入、查无）走 `选项`，意外错误（bug、环境）走异常。这个分类决定 API 形态——好的 API 让「对的用法容易，错的用法不可能」。

**② Fail fast（快速失败）**：`获取或抛出()`、`抛出 异常("...")` 都是「出错立刻大声说出来」——错误越早暴露越容易修。把错误吞掉（`捕获` 后什么都不做）是最危险的代码。

**③ 前置检查：好函数先校验再干活**：函数第一件事就是检查参数合法性（防御式编程）。

**④ 默认不可变是并发红利**：`让` 绑定的数据不会被并发修改——不需要锁、不会数据竞争。并发程序里尽量 `让`，只有真正共享的可变状态才需要 `同步`/原子。

**⑤ 临界区最小化**：锁的范围越小，并发度越高。把「只读计算」移出临界区，只锁「真正修改共享状态」的那几行。

## 练习

1. 用 `选项` 实现「按索引取数组元素」：越界返回 `无值` 而不是抛异常；
2. 用 `尝试`/`捕获` 包住一次整数除法，除零时打印友好提示；
3. 写一个 `解析整数` 函数：合法输入返回 `有值(数)`，非法输入返回 `无值`（提示：`正则("^\\d+$").匹配正则` 判断——记得加锚，`\\d+` 本身是包含匹配）；
4. 用 `生成` 启动 3 个任务各自打印 1..3，观察输出顺序是否确定，再用 `同步(锁)` 包住打印，看顺序变化；
5. 思考：为什么 `选项` 值不能直接 `+ 1`？这设计在保护你什么？

## 小结

- `选项<T>` + `有值`/`无值` 消灭空指针；`匹配` 穷尽处理、`获取或默认` 兜底、`获取或抛出` 确信取值；
- 预期失败用 `选项`（官方无 Result），意外错误用 `尝试`/`捕获`/`最终`/`抛出`；不要用异常做控制流；
- `退出(状态码)` 终止进程（`最终` 不会执行）；前置检查用手写 `如果` + `抛出`；
- 并发：`生成` 开任务、`同步(锁)` 保护临界区、`原子整数` 无锁计数；`原子引用` 只收引用类型；
- 运行时输出保持官方格式（`真` → `true`）。
