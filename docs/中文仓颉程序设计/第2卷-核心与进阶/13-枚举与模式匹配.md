# 第 13 章 枚举与模式匹配

> **本章学习目标**：掌握枚举（有限取值集合 + 携带数据）与模式匹配（穷尽性检查、解构、守卫），理解「匹配比如果链安全」。
> **读完本章你能回答**：枚举的核心价值是什么？`情况` 漏写一个会发生什么？`匹配` 和 `如果` 链的区别？

---

## 13.1 定义：枚举是什么

**定义**：`枚举` = **有限取值集合**——把「所有可能的情况」列出来。比「魔法数字」安全得多：编译器穷尽性检查保证所有取值都被处理。

**中文语法**：

```cangjie
枚举 方向 { 上 | 下 | 左 | 右 }

主函数() {
    让 朝向 = 方向.上
    匹配 (朝向) {
        情况 方向.上 => 打印行("向上")
        情况 方向.下 => 打印行("向下")
        情况 方向.左 => 打印行("向左")
        情况 方向.右 => 打印行("向右")
    }
}
```

**注意事项**：

- 取值用 `枚举名.成员`（`方向.上`）；
- 成员之间用 `|` 分隔；
- 匹配枚举时**强制全分支**（除非有 `_` 兜底）——漏分支编译报错，这是枚举的核心价值。

## 13.2 携带数据：标签联合

**定义**：枚举成员还能**携带数据**——每种形态各带各的数据，这是「多种形态的数据」的经典建模（官方叫 tagged union）。

**中文语法**：

```cangjie
枚举 通知 {
    文本(字符串) | 数字(整数) | 结束
}

主函数() {
    让 内容 = 通知.文本("你好")
    匹配 (内容) {
        情况 通知.文本(文字) => 打印行("文本：${文字}")
        情况 通知.数字(数) => 打印行("数字：${数}")
        情况 通知.结束 => 打印行("结束")
    }
}
```

**注意事项**：带数据成员像构造器（`通知.文本("你好")`）；匹配时 `情况 通知.文本(文字)` **同时判断 + 解构**——把数据拿出来。

## 13.3 匹配：模式匹配 + 穷尽性检查

**定义**：`匹配 (值) { 情况 模式 => ... }` —— 比 `如果` 链更结构化的分支。`如果` 链是「手动管理分支」——漏写一个 `否则` 编译器不吭声，运行时悄悄走错路；**穷尽性检查**把「分支完整性」变成**编译错误**。

**中文语法**：

```cangjie
函数 星期名(数字: 整数): 字符串 {
    匹配 (数字) {
        情况 1 => 返回 "一"
        情况 2 => 返回 "二"
        情况 3 => 返回 "三"
        情况 _ => 返回 "未知"     // _ 通配符：匹配任意
    }
}

主函数() {
    对于 (i 在 1..4) {              // 1..4 是半开区间：1, 2, 3
        打印行("星期${i}：${星期名(i)}")
    }
}
```

**注意事项**：

- `_` 通配符匹配任意值——整数没有穷尽性检查，必须有兜底；
- `匹配` 是**表达式**（有值）：`让 描述 = 匹配 (方向) { ... }`；
- 匹配枚举/选项/元组必须穷尽（或 `_` 兜底）——编译器替你检查「所有情况都处理了吗」。

## 13.4 元组模式：同时判断 + 解构

**定义**：匹配元组时按形状拆开——（0, 0）原点、（x, 0）x 轴……每个模式同时完成判断与解构。

**中文语法**：

```cangjie
主函数() {
    让 点 = (3, 4)
    匹配 (点) {
        情况 (0, 0) => 打印行("原点")
        情况 (x, 0) => 打印行("在 x 轴上：${x}")
        情况 (0, y) => 打印行("在 y 轴上：${y}")
        情况 (x, y) => 打印行("普通点（${x}，${y}）")
    }
}
```

**注意事项**：模式里的 `x`、`y` 是**新绑定的名字**（自动解构），不是外面的变量；元组模式穷尽性由编译器检查（上面的 4 个分支覆盖了所有可能）。

## 13.5 匹配守卫：形状 + 条件

**定义**：`情况 模式 其中 (条件)`——「形状匹配 + 条件过滤」两步走。

**中文语法**：

```cangjie
主函数() {
    让 分数 = 95
    匹配 (分数) {
        情况 x 其中 (x >= 90) => 打印行("优秀")
        情况 x 其中 (x >= 60) => 打印行("及格")
        情况 _ => 打印行("加油")
    }
}
```

**注意事项**：守卫里的 `x` 是匹配到的值（这里就是分数本身）；守卫条件为假时落到下一个分支；整数匹配必须有 `_` 兜底。

## 13.6 综合实战：把「如果链」改写成「匹配」

用「成绩评级」对比两种写法（同一逻辑）：

```cangjie
// 写法一：如果链（命令式）
函数 评级1(分数: 整数): 字符串 {
    如果 (分数 >= 90) { 返回 "优秀" }
    否则如果 (分数 >= 60) { 返回 "及格" }
    返回 "加油"
}

// 写法二：匹配守卫（声明式）
函数 评级2(分数: 整数): 字符串 {
    匹配 (分数) {
        情况 x 其中 (x >= 90) => 返回 "优秀"
        情况 x 其中 (x >= 60) => 返回 "及格"
        情况 _ => 返回 "加油"
    }
}

主函数() {
    打印行(评级1(95))    // 优秀
    打印行(评级2(95))    // 优秀
}
```

**注意事项**：两种写法等价，`匹配` 的优势在于**模式**（枚举、元组、解构）场景——当分支不只是「比大小」而是「按形状区分」时，匹配是唯一干净的答案。
## ✳ 设计思想

**① 穷尽性检查：把「漏分支」变成编译错误**。`如果` 链漏写分支 = 运行时悄悄走错路；`匹配` 漏写分支 = 编译期大声报错。新增枚举成员时，所有匹配点编译报错——**强迫你处理新情况**（可扩展性的安全网）。

**② 用类型建模，不用数字**：`方向.上` 比数字 `1` 安全——编译器能检查、代码能自述、传错类型直接报错。「魔法数字」是代码坏味道，枚举是解药。

**③ 表达式即值**：`匹配` 是表达式——「分支必须都有值」从源头消灭「忘记初始化」；函数式风格渗透到命令式结构。

**④ 先匹配形状，再匹配条件**：模式解决「是什么」，守卫解决「合不合规」——两步分离让每个分支的意图清晰。

## 练习

1. 定义 `枚举 天气 { 晴 | 雨 | 雪 }`，写函数 `带什么(天气: 天气): 字符串` 返回建议（晴→防晒、雨→带伞、雪→穿棉衣），并**故意删掉一个分支**观察穷尽性报错；
2. 定义 `枚举 形状 { 圆(浮点) | 矩形(浮点, 浮点) }`，写 `面积()` 函数用匹配分别计算；
3. 用 `匹配` + 守卫改写「游乐场规则」（8-18 岁 与 身高 130+）为多分支版本；
4. 挑战：用元组模式匹配实现「判断点在第几象限」：`(正, 正)` 第一象限、`(负, 正)` 第二……提示：`情况 (x, y) 其中 (x > 0 与 y > 0)`。

## 小结

- `枚举 名 { 成员1 | 成员2 }`；取值 `枚举名.成员`；成员可**携带数据**；
- `匹配 (值) { 情况 模式 => ... }`：模式匹配 + 穷尽性检查（枚举/选项/元组必须全分支或 `_` 兜底）；
- 元组模式 `情况 (x, 0) =>`：同时判断 + 解构；守卫 `情况 x 其中 (条件)`：形状 + 条件；
- `_` 通配符兜底；`匹配` 是表达式（有值）；
- 核心价值：漏分支从「运行时 bug」变成「编译期错误」。
