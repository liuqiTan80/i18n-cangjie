# zhc 语言包开发指南

> 语言包把标准仓颉变成任意母语方言：`lang-packs/<代码>/` 目录一套文件即一种语言
> （`ZHCLANG` 环境变量切换）。本文说明语言包结构、完整度口径与贡献流程。
> 术语用词先查[术语表](术语表.md)，关键字/标准库映射以《中文仓颉程序设计》附录 A/B 为基准。

## 一、语言包结构与完整度

每个语言包 = `lang_info.toml`（名称/扩展名声明）+ 五类词表：

| 文件 | 内容 | 教学可用性（zh 包基线） |
|---|---|---|
| `keywords.toml` | 关键字映射（`函数` → `func`） | 59 词全 |
| `stdlib.toml` | 标准库别名（`打印行` → `println`） | 214 词全 |
| `module_paths.toml` | import 语句路径段映射（`标准集合` → `std.collection`） | 19 词全 |
| `errors.toml` | 诊断翻译：645 条诊断码（14 人工精翻 + 631 自动）+ 20 条消息兜底 | 教学必需 |
| `ui.toml` | 界面文案：`["界面消息"]`（键 = zh 模板串，缺键回退原文）+ `["测试输出"]`（cjpm test 输出词典） | zh 仅测试词典；非 zh 提供界面翻译 |

完整度查询：`zhc lang list`（新版本输出每包逐类词条数，缺失文件显示 `-`）。
**教学可用语言包 = 五类文件齐全 + 词条数与 zh 基线相当**——9 包现状（2026-09-06 实测；ar 为 demo 档 RTL 试点）：

```text

[en] en（恒等映射）  full     关键字 58 / 标准库 162 / 模块路径 14 / 诊断码 50  / 消息兜底 0  / 界面 312
[ru] Русский        standard 关键字 59 / 标准库 205 / 模块路径 19 / 诊断码 50  / 消息兜底 20 / 界面 322
[ja] 日本語          standard 关键字 59 / 标准库 206 / 模块路径 19 / 诊断码 50  / 消息兜底 20 / 界面 312
[ko] 한국어          standard 关键字 59 / 标准库 205 / 模块路径 19 / 诊断码 50  / 消息兜底 20 / 界面 312
[fr] Français       standard 关键字 59 / 标准库 205 / 模块路径 19 / 诊断码 50  / 消息兜底 20 / 界面 312
[es] Español        standard 关键字 59 / 标准库 205 / 模块路径 19 / 诊断码 50  / 消息兜底 20 / 界面 312
[de] Deutsch        standard 关键字 59 / 标准库 205 / 模块路径 19 / 诊断码 50  / 消息兜底 20 / 界面 312
```

- **en 包**：恒等映射（英语方言 = 官方仓颉），界面消息 312 键全表（英语提示，缺键回退中文原文）；
  errors 表收 Top-50 高频码（en 用户的母语即官方英文，消息兜底 0 为设计如此）；
- **ru 包**：standard——俄语方言（`.rc`），关键字 59 + 标准库 205 + 模块路径 19 +
  Top-50 诊断码 + 消息兜底 20 + 界面全表 322（312 界面 + 10 测试词典）。ru 最早验证
  「语言无关」架构并作完整语言包**样板**，现与其余五语同级 standard；继续按第五节
  补齐（错误表向 zh 645 码扩进）可率先升 full；
- **ja 包**：standard——假名+日文汉字风格的日语方言（`.jc` 源码），关键字 59 + 标准库
  206（zh 官方值全覆盖，P-6 ja 样板）+ 模块路径 19 + Top-50 诊断码 + 消息兜底 20 +
  界面全表 312（全量档），门禁全过；errors 走 `diag_translations_ja.py` 增量表 +
  `--lang ja` 生成链（见第二节）。
  冒烟示例（日语关键字：`メイン`/`おく`/`もし`/`ひょうじ`/`リスト`/`ながさ`）：
  ```jc
  メイン() {
      おく 名前: 文字列 = "倉頡"
      ひょうじ("こんにちは、${名前}！名前の長さは ${名前.ながさ}")
  }
  ```
- **ko/fr/es/de 包**（standard，2026-09 新增）：与 ja 同构——关键字 59 + 标准库
  205 + 模块路径 19 + Top-50 诊断码 + 消息兜底 20 + 界面全表 312（`zhc mapping check`
  SDK 级实测通过，九语方言 hello 均端到端跑通）；fr/es/de 键采用无变音符拼写（避免
  词法切分歧义）；术语约定与选型依据见[国际化方案对比](国际化方案对比.md)第三节。
  无 SDK 环境可跑 `python3 scripts/verify-lang-packs.py` 快速回归。
- **界面消息计数口径**：`zhc lang list` 的「界面 N」= 界面消息 + 测试词典条数之和
  （zh 的 10 即测试词典 10 条；ru 的 322 = 312 界面 + 10 测试；en 的 312 仅界面消息）。

## 二、生成物与源头（改哪一层）

语言包是**生成物**，分两条生成链，**不要直接手改生成物**（重新生成会覆盖）：

```text
zh 错误链：tools/diag_translations.py（sema 394 条）+ diag_translations2.py（parse/lex/chir 250 条）
        └→ python3 tools/gen_full_errors.py --lang zh     → zhc/lang-packs/zh/errors.toml（645 诊断码 + 消息兜底 20）
        └→ python3 tools/gen_error_dict.py                → docs/errors-dictionary.md（错误字典附录）
非 zh 错误链（ru/ja/ko/fr/es/de 六包，增量式）：
        tools/diag_translations_<代码>.py（诊断码表 + MSG_<代码> 消息兜底表）
        └→ python3 tools/gen_full_errors.py --lang <代码> → zhc/lang-packs/<代码>/errors.toml
           （在生成器 INCR 注册表登记即分发；缺翻译码运行时回退官方原文）
ui 全包链：tools/ui_translations_<代码>.py（界面翻译源 dict；zh 特殊：不建表仅测试词典）
        └→ python3 tools/gen_ui_packs.py                  → zhc/lang-packs/*/ui.toml（自动发现全部语言包）
```

- **关键字/标准库/模块路径**：直接编辑 `lang-packs/zh/*.toml`（手工维护的源文件）；
- **诊断翻译（zh 全集式）**：改 `tools/diag_translations*.py`（644 条官方自动翻译）与
  `tools/gen_full_errors.py` 顶部 `CURATED`（14 条人工精翻：13 官方高频 + 1 方言自定义）；
  实战命中码的修复示例补在 `FIX_EXAMPLES`（自动条目专用，已在 CURATED 的码应升级进 CURATED）——
  改完重新生成 `errors.toml` 与错误字典；
- **诊断翻译（非 zh 增量式）**：在 `tools/diag_translations_<代码>.py` 的翻译表加条目
  （同构四元组；消息兜底加在 `MSG_<代码>` 表），`python3 tools/gen_full_errors.py
  --lang <代码>` 重新生成——只收已翻译码，缺翻译码运行时走「优雅回退」显示官方原文，
  因此可逐条扩充（完整度以 `zhc lang list` 为准；六语言已在 `gen_full_errors.py` 的
  INCR 注册表登记，新增语言只需补翻译表 + import + 登记一行）；
- **人工精翻标记**：`# 人工精翻` 注释由生成器写在精翻条目前，`gen_error_dict.py` 据此在
  字典中标注「人工精翻 / 自动生成」——新增精翻条目标记自动生效，无需改字典脚本；
- **机器翻译标注**：错误字典头部有「翻译质量标注」段——631 条自动翻译为模板化措辞，
  个别生硬属已知状态；发现措辞问题请修订翻译表并重新生成（改生成物不生效且会被覆盖）。

## 三、质量门禁（改完必须全过）

1. **`zhc mapping check`**：五项质量门禁 + 跨语言一致性检查（改词表后必跑）；
2. **教程代码全量验证**：`bash scripts/tutorial-check.sh`（教程用词必须被语言包覆盖——
   教程代码跑不过 = 词表缺词，按报错补词）；
3. **全量验收**：`bash scripts/acceptance.sh`（含诊断教学用例库 16 场景 + 生成物防漂移
   检查：zh/ru errors.toml 与错误字典不一致会直接报失败；ui.toml 重生成 diff 为空；
   语言跟随冒烟断言）；
4. **zhc 自身单测**：`zhc test`（语言包解析/别名/诊断翻译相关测试在 acceptance 第 9 段）。

## 三·五、诊断码实战触发率（0 触发清单怎么用）

> 645 条码面里哪些真的被用户踩到、哪些常年 0 触发？埋点统计回答这个问题，
> 让精翻与黄金样例的优先级从「拍脑袋」变成「看数据」。

用法（zhc 内置埋点，设置即生效）：

```bash
# 1. 收集：设置环境变量后跑验收/教程/真实使用（命中码逐行追加写入该文件）
export ZHC_DIAG_STATS=/tmp/diag-stats.txt
bash scripts/acceptance.sh        # 验收全流程即覆盖大量错误场景
unset ZHC_DIAG_STATS

# 2. 聚合：与 errors.toml 码面比对，输出命中率 + 0 触发清单
python3 tools/diag_coverage.py /tmp/diag-stats.txt            # 默认显示前 30 条
python3 tools/diag_coverage.py /tmp/diag-stats.txt --top 0    # 全量清单
```

埋点行为：`zhc check` 等命令在**按 DiagKind 错误码表命中**时把稳定错误码
追加写日志（`~/.zhc/diag-log/` 的 logMiss 同款 try 包裹，失败静默不影响主流程）；
消息表兜底/原文回退路径不计数。

0 触发清单的用途（重要，别误读）：

- **语料有限时 0 触发 ≠ 死码**——教程与验收只踩到高频场景；先扩语料（新黄金样例/
  教程用例）再下结论；
- 扩语料后仍 0 触发的码 = 超低频/死码 → 精翻优先级低，自动翻译兜底即可；
- 命中但不在码面（消息表兜底路径命中）说明消息表在干活，属正常。

## 四、修正流程示例（把一条自动翻译改成精翻）

1. 在 `tools/gen_full_errors.py` 的 `CURATED` 加入该码（参考现有条目的四元组格式）；
2. 重跑：`python3 tools/gen_full_errors.py`（确认输出「精翻 N + 自动 M」数字正确）；
3. 重跑：`python3 tools/gen_error_dict.py`（字典头部标注自动更新）；
4. 跑第三节门禁（至少 1 + 2）。

## 五、新增一种教学语言（以六语 standard 包为样板）

1. `zhc mapping scaffold <代码>` 生成骨架（含 `lang_info.toml`），按 zh 包结构补齐
   五类文件；先补 `keywords.toml`（60 键全部翻译——zh 词表为基线（59 键 + `在`→in，2026-09-08 补），这是能「写程序」
   的最低门槛，六语 standard 包已验证）；
2. 补 `stdlib.toml`（先按 zh 词表逐条翻译高频 214 词，教程用词全覆盖为准）；
3. 补 `module_paths.toml`、`errors.toml`：错误链新建 `tools/diag_translations_<代码>.py`
   增量表（同构四元组，参考六语现有表；带消息兜底则同文件加 `MSG_<代码>` 表）→ 在
   `tools/gen_full_errors.py` 的 INCR 注册表登记 → `python3 tools/gen_full_errors.py
   --lang <代码>` 生成（先收高频精翻即可，缺翻译码运行时优雅回退），报错缺词时按
   第 4 条方式验证补齐；
   `ui.toml`：界面消息翻译源新建 `tools/ui_translations_<代码>.py`（键 = zh 模板串全表，
   参考 `ui_translations_en.py` 的 312 键结构）→ `python3 tools/gen_ui_packs.py` 生成
   （自动发现语言包，无需改生成器）；先译高频键即可（缺键回退英文/中文原文，界面
   语言跟随度以 `zhc lang list` 的界面条数为准）；测试词典按需补（en 可不建，英文原样）；
4. 用新语言跑既有验证：`ZHCLANG=<代码> zhc run` 跑示例与教程代码（报错缺词就补
   词表），诊断翻译用 `zhc check` 错误样例核对（可借用 acceptance 第 4 段黄金样例的
   错误源码清单）；
5. 完整度以 `zhc lang list` 词条数为准对外公布（教学可用标准见第一节）。

### ar RTL 试点要点（阶段 D 样板，2026-09-06 入档 demo）

ar 是第一个 RTL 语言包（`lang_info.toml` 声明 `"方向" = "rtl"`），把「新语言零脚本
加入」流水线（P-4/L3：ui/errors 生成器自动发现 + INCR 注册表，不建表即不生成）在
RTL 书写系统上完整走了一遍。实测结论与约定：

- **cjc 标识符支持（对 `demo/hello.ar.ac` 同法实测）**：纯阿拉伯字母、hamza 载体
  字母（أ إ آ ئ ؤ）、词中变音符（tashkeel）、阿拉伯-印度数字后缀（١٢٣）全部编译
  通过——cjc 分词遵循 XID 白名单，与 zhc 的 [xid.cj](../zhc/src/xid.cj) 一致；
- **词表书写约定**：方言词不带变音符（阿语排版常态，输入法友好），hamza 按正字
  保留；键内不带空格——多词概念两种写法：连写单串（غيرآمن=unsafe）或带空格整串键
  （وإلا إذا=else if，与 en/de 包同构，词法器按最长键串匹配实测可用）；
- **术语形态**：动词/操作用命令式（دع=let、أنشئ=spawn、اعرض=println），类型词用
  名词（نص=String、عدد=Int64）；修饰词用「غير + 词根」构词（غير=mut、غيرآمن=unsafe）
  避免变音符后不可用；
- **档位现状**：demo（无 ui.toml/errors.toml）——UI 消息走运行时三级回退链
  ar→en（acceptance 2b2 断言 `File not found` 英文文案），诊断消息回退官方原文；
  升级路径同第五节步骤 1-3（界面补翻 + 错误表 Top-50 → standard）。

## 六、贡献清单（新人入口）

- 修订 631 条自动翻译中措辞生硬的条目（数量多、单条改动小——最易入手）；
- 给 `CURATED` 增加新的高频场景精翻（需设计教学提示与修复示例，参考现有条目风格；
  高频依据 = 第三节·五的 ZHC_DIAG_STATS 命中数据，优先处理命中过的码）；
- 把六语 standard 包错误表从 Top-50 码向 zh 全量 645 码补进（母语人工翻译 + 消息兜底
  扩充；errors 走 `diag_translations_<代码>.py` 增量表 + INCR 生成链，见第二、五节）；
- 新增词表词条前先跑 `check_langpack.py`（教程目录内工具）看是否已在教程代码中使用，
  避免造出没人用的映射。

## 七、语言包档位与 Schema（全球化，2026-09 起）

每个语言包的 `lang_info.toml` 末尾带 **schema 1 档位声明**，`zhc lang list` 与
文档以此对外公布成熟度（诚实分级优于让用户自己发现）：

| 字段 | 说明 | 取值 |
|---|---|---|
| `"档位"` | 成熟度总评 | `full`（界面+错误表完整）/ `standard`（界面完整、错误表部分）/ `demo`（界面部分覆盖） |
| `"方向"` | 书写方向（P-10，schema 1 起） | `ltr`（默认，现 8 包）/ `rtl`（ar 包已用：首个 RTL 试点，bidi 排版/行长规则预留） |
| `"界面覆盖率"` | 界面消息母语覆盖 | 如 `100%（全量档）`；demo 档写 `N%（缺键回退 EN/zh 原文）` |
| `"错误表"` | 诊断教学消息覆盖 | `完整 645 条` / `无（回退英文原文）` 等 |
| `"维护者"` / `"反馈"` | 母语维护者署名与反馈入口 | 诚招母语审校者的钩子 |
| `"schema"` | 档位声明格式版本 | 当前 `1`；破坏性变更升版本并在此登记迁移说明 |

### 界面消息（ui.toml）的档位机制

界面消息键 = zh 模板串（运行时形态），由 `tools/gen_ui_packs.py` 从源码提取生成：

- **全量档**（en/ru/ja/ko/fr/es/de 七包，界面 100%）：翻译表 `ui_translations_<code>.py`
  与源码键集**严格对齐**（缺漏/多余即报错），lang_info 档位 full/standard；
- **demo 档**（ar 包在用，2026-09-06 起）：`ui_translations_<code>.py` 可先覆盖
  **子集**（多余键报错），缺失键生成时**回退 EN，再回退 zh 原文**，头部注明覆盖率；
  新语言可经此档渐进补翻后升 standard/full；
- 补翻流程：编辑 `ui_translations_<code>.py` → `python3 tools/gen_ui_packs.py`
  → 覆盖率与 `ui.toml` 同步更新 → `zhc mapping check` + acceptance 段 13 防漂移。
  翻译达标（覆盖率 100% 且母语者审校）后，把 lang_info 档位升为 `full`。
