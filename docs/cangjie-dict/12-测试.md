# 12 测试

> 测试是「给程序上保险」：写一小段代码验证另一段代码的行为。没有测试的程序像没有刹车系统的车。
> 本卷词条：测试 / 期望 / 断言 / 断言相等 / 测试运行 / 属性测试与 mock。

## 词条 12.1 测试（测试 / Test）

- **是什么**：用 `@测试` 宏标记的**测试函数**：`@测试 函数 测试加法() { ... }`——测试框架自动收集并运行。
- **为什么**：**回归保护**——改代码后跑一遍测试，立刻知道有没有改坏东西。测试即文档（测试展示了「这个函数应该怎么用、结果是什么」）。
- **怎么用**：
  ```cangjie
  导入 标准核心.*
  函数 两倍(数: 整数): 整数 { 返回 数 * 2 }

  @测试
  函数 测试两倍() {
      断言相等(两倍(21), 42)
  }
  ```
- **注意**：测试文件与源码同目录（`src/`）；测试函数名以 `测试` 开头是惯例；测试**不依赖顺序**（每个测试独立）。

## 词条 12.2 期望（期望 / Expect）

- **是什么**：测试里的**断言宏**：`@期望(表达式, 期望值)`——不满足则测试失败。
- **为什么**：`@期望` 是方言测试的断言语法（官方 `@Expect`）：自动比较表达式的值与期望值，失败时给出**中文诊断**（表达式文本 + 实际值 + 期望值）——不用自己写失败信息。
- **怎么用**：
  ```cangjie
  导入 标准核心.*
  函数 评级(分数: 整数): 字符串 {
      如果 (分数 >= 60) { 返回 "及格" }
      返回 "不及格"
  }

  @测试
  函数 测试评级() {
      @期望(评级(85), "及格")
      @期望(评级(40), "不及格")
  }
  ```
- **注意**：布尔断言用 `@期望(表达式, 真)`（期望值写 `真`/`假` 字面量）；`@期望` 失败只报告**第一个失败**（同函数内后续断言跳过）；期望值与表达式类型必须一致。

## 词条 12.3 断言（断言 / assert）

- **是什么**：运行时条件检查：`断言(条件, "信息")`——条件为假抛 `断言异常`（见 8.10）。
- **为什么**：测试与业务代码共用同一套「不变量检查」：测试里检查「结果应该如此」，业务里检查「前提不该如此」。断言失败 = 程序员的假设被打破——立即暴露，不要等到奇怪现象蔓延。
- **怎么用**：
  ```cangjie
  导入 标准核心.*
  @测试
  函数 测试断言() {
      断言(两倍(21) == 42, "两倍计算错误")
  }
  函数 两倍(数: 整数): 整数 { 返回 数 * 2 }
  ```
- **注意**：`断言` 是函数（带参数），`@期望` 是宏（吃表达式）——**`@期望` 能看到表达式的文本，诊断更友好**；断言消息用中文写清楚「哪个假设被打破」。

## 词条 12.4 断言相等（断言相等 / assertEqual）

- **是什么**：比较两个值相等的断言：`断言相等(实际, 期望)`。
- **为什么**：最常用的断言——「结果应该等于某值」。失败信息自动带两侧的值，比 `断言(a == b)` 的「条件为假」有用得多。
- **怎么用**：
  ```cangjie
  导入 标准核心.*
  函数 求和(甲: 整数, 乙: 整数): 整数 { 返回 甲 + 乙 }

  @测试
  函数 测试求和() {
      断言相等(求和(2, 3), 5)
      断言相等(求和(-1, 1), 0)
  }
  ```
- **注意**：比较用 `相等`（equals）语义——字符串比较内容、结构体按字段；浮点比较有精度问题（用误差范围断言，见 2.2）；容器比较需逐元素（或派生 `相等`）。

## 词条 12.5 测试运行（zhc test / cjpm test）

- **是什么**：运行项目全部测试的命令：`zhc test`（方言项目）或 `cjpm test`（官方项目）。
- **为什么**：测试框架自动**发现**（`@测试` 标记的函数）、**运行**、**汇总**——输出每个测试的通过/失败，失败时打印中文诊断。
- **怎么用**：
  ```bash
  zhc test        # 在项目根目录运行全部测试
  # 输出示例：
  # ✅ 通过 3 个测试
  # ❌ 失败 1 个：测试评级（期望「及格」，实际「不及格」）
  ```
- **注意**：测试编译与主程序独立（测试代码不进入发布产物）；`zhc test` 的工作目录是项目根（文件测试注意路径）；测试失败时退出码非 0（CI 会拦截）。

## 词条 12.6 属性测试与 mock（std.unittest）

- **是什么**：标准库测试套件的进阶能力：**属性测试**（`@属性测试` 自动生成随机输入验证性质）与 **mock**（模拟依赖对象）。
- **为什么**：手写用例覆盖有限——属性测试用**随机输入**（几百组）验证「不变量」（如 `反转(反转(x)) == x`）；mock 让被测代码在**没有真实依赖**（网络、数据库）时也能测。
- **怎么用**（示意）：
  ```cangjie
  导入 标准核心.*
  // 属性测试：任意整数 x，两倍后再减半应回到 x（近似）
  @属性测试
  函数 性质测试两倍(任意整数: 整数) {
      断言相等(两倍(任意整数) / 2, 任意整数)
  }
  函数 两倍(数: 整数): 整数 { 返回 数 * 2 }
  ```
- **注意**：属性测试的参数由框架注入（`整数` 类型自动生成随机值）；mock 用于模拟接口（`@可模拟` 接口 + `模拟` 对象）；这两项是**进阶**——入门先把 `@测试` + `@期望` 用熟（zhc 语言包内置 `测试`/`期望`/`断言`/`断言相等` 方言别名，全部中文）。
