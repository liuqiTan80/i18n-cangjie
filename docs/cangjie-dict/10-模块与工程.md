# 10 模块与工程

> 程序大了要拆文件，文件要归包，包要定可见性，最后用工具链组织成工程。本卷讲「代码的组织与构建」。
> 本卷词条：导入 / 包 / 公开 / 私有 / 内部 / 受保护 / 外部 / 项目结构 / 依赖管理 / 构建与运行 / zhc 工具链 / 语言包机制。

## 词条 10.1 导入（导入 / import）

- **是什么**：引入其他包/模块的名字：`导入 标准集合.{向量}`、`导入 标准库.{打印行}`、`导入 标准核心.*`。
- **为什么**：名字有**归属**（属于某个包），用之前先「把门打开」。三种形态：
  | 写法 | 含义 |
  |---|---|
  | `导入 包.{名字}` | 只引入指定名字 |
  | `导入 包.{甲, 乙}` | 引入多个 |
  | `导入 包.*` | 引入全部（通配） |
  | `导入 包.{名字 作为 别名}` | 起别名（官方支持） |
- **怎么用**：
  ```cangjie
  导入 标准集合.{向量, 哈希映射}
  导入 数学.*
  主函数() {
      可变 列表 = 向量<整数>()
      列表.添加(1)
      打印行(开方(16.0))     // 4.0（std.math.sqrt）
  }
  ```
- **注意**：导入未安装的包 → zhc 报「找不到包」**方言错误**（这是 zhc 自定义的错误码，见 09 章教程）；未使用的导入是**警告**（`zhc check`/`lint` 会提示）；通配导入可能名字冲突（同名时需限定 `包.名字`）。

## 词条 10.2 包（包 / package）

- **是什么**：代码的**归属单位**：`包 学校`——文件首行声明它属于哪个包。
- **为什么**：包 = 命名空间 + 可见性边界。同一包内互相可见；跨包要 `导入` + 对方 `公开`。包名惯例：小写/反域名（`学校.教务`）。
- **怎么用**：
  ```cangjie
  包 学校.教务
  导入 标准核心.*
  // 本文件属于 学校.教务 包
  ```
- **注意**：方言 `包` → 官方 `package`；**宏包**（`宏 包`）是另一回事（见 9.3）；入口文件（含 `主函数`）通常归默认包或项目包。

## 词条 10.3 公开（公开 / public）

- **是什么**：跨包可见的成员：`公开 函数 ...`、`公开 类 ...`。
- **为什么**：**默认私有**的可见性哲学：暴露给外部的是「API 面」，必须显式声明。这迫使设计者思考「哪些是给别人用的」——未公开的都是实现细节（以后随便改）。
- **怎么用**：
  ```cangjie
  包 学校
  公开 函数 计算总分(成绩: 数组<整数>): 整数 {
      可变 总和 = 0
      对于 (分 in 成绩) { 总和 += 分 }
      返回 总和
  }
  // 别的包：导入 学校.{计算总分}
  ```
- **注意**：`公开` 的类型/函数/字段才能在包外访问；公开 API 的改动会影响使用者（破坏性变更要谨慎）。

## 词条 10.4 私有（私有 / private）

- **是什么**：**文件内**可见：`私有 函数 内部细节() ...`。
- **为什么**：最严格的封装——实现细节不出本文件。类字段默认私有（见 6.1），顶层声明默认包内可见（`私有` 进一步收紧到文件）。
- **怎么用**：
  ```cangjie
  私有 函数 内部辅助() { /* 只有本文件能用 */ }
  主函数() { 内部辅助() }
  ```

## 词条 10.5 内部（内部 / internal）

- **是什么**：**包内**可见（同包不同文件也能用），包外不可见。
- **为什么**：包是协作单位——包内各文件互用内部 API 是常态（`内部` 介于私有与公开之间，是默认值）。
- **怎么用**：
  ```cangjie
  内部 函数 包内共享() { /* 同包可用 */ }
  ```
- **注意**：顶层声明的**默认可见性**就是包内可见（相当于 internal）；显式写 `内部` 更清楚。

## 词条 10.6 受保护（受保护 / protected）

- **是什么**：**子类可见**（跨包继承时子类可访问，包外非子类不可）。
- **为什么**：继承场景的「半公开」——给子类扩展用的钩子，不给外部调用。配合 `开放`/`重写` 使用。
- **怎么用**：
  ```cangjie
  开放 类 动物 {
      受保护 函数 内部状态(): 字符串 { 返回 "健康" }
  }
  类 狗 <: 动物 {
      公开 函数 报告(): 字符串 { 返回 内部状态() }   // 子类可访问
  }
  ```
- **注意**：`受保护` 成员对「非子类外部」不可见；类内其他成员默认私有。

## 词条 10.7 外部（外部 / foreign）

- **是什么**：声明**外部语言**（C/FFI）的函数/变量：`外部 函数 打印到系统(文本: 字符串)`。
- **为什么**：与 C 库互操作（操作系统 API、成熟 C 库）——仓颉程序不是孤岛。`外部` 声明告诉编译器「这个函数在外部实现，按 C 调用约定」。
- **怎么用**（示意，需要链接 C 库）：
  ```cangjie
  外部 函数 系统时间(): 整数
  主函数() {
      打印行(系统时间())
  }
  ```
- **注意**：外部函数默认按 C ABI；复杂类型（字符串）跨 FFI 需要对应 C 类型声明；`外部` 用起来有安全责任（unsafe 场景），教程示例点到为止。

## 词条 10.8 项目结构（cjpm.toml）

- **是什么**：仓颉官方构建工具 cjpm 的工程描述文件（TOML）：包名、版本、依赖、编译目标。
- **为什么**：一个项目 = 一个 `cjpm.toml` + `src/` 源码目录。构建工具按它编译、测试、打包——**约定目录 + 声明配置**。
- **怎么用**（`zhc init 项目名` 自动生成）：
  ```toml
  [package]
  name = "我的程序"
  version = "0.1.0"
  edition = "1.0.5"

  [dependencies]
  # 依赖的包（如 "std.random" = "1.0.5"）
  ```
- **注意**：zhc 项目用 `zhc init` 创建（内含 `src/main.zc` 方言入口）；官方项目用 `cjpm init`（`src/main.cj` 官方语法）——两者都能被 `zhc run` 运行。

## 词条 10.9 依赖管理

- **是什么**：项目依赖其他库（标准库/第三方）的声明与管理：`cjpm.toml` 的 `[dependencies]` 节 + `cjpm fetch`/`update`。
- **为什么**：代码复用跨越项目边界——依赖声明让构建可复现（别人 clone 项目后一条命令装齐依赖）。
- **怎么用**：
  ```bash
  cjpm fetch      # 拉取声明的依赖
  cjpm update     # 更新到最新兼容版本
  ```
- **注意**：zhc 语言包的「找不到包」诊断（`package_search_error`）就是依赖缺失的友好提示；依赖版本用语义化版本（`0.1.0`、`^1.2`）。

## 词条 10.10 构建与运行

- **是什么**：把源码变成可执行程序的完整动作：编译（cjc/cjpm build）→ 链接 → 运行。
- **为什么**：方言代码**不是直接运行**的——zhc 先转译成官方仓颉（`expand` 可看），再交给编译器。理解这条流水线：`方言源码 → 转译 → 官方源码 → 编译 → 二进制`。
- **怎么用**：
  ```bash
  zhc run src/main.zc        # 转译 + 编译 + 运行（最常用）
  zhc check src/main.zc      # 只转译 + 编译检查，不运行
  cjpm build                 # 官方构建（产物在 target/）
  ```
- **注意**：`zhc run` 的输出会显示「替换方言标识符 N 处」——这是转译统计；纯官方语法文件（`.cj`）无需转译。

## 词条 10.11 zhc 工具链

- **是什么**：zhc 提供的完整命令集——中文编程的「工作台」。
- **为什么**：每个命令对应一个开发动作，全部中文输出（`--help` 也是中文）——「让使用者开发时忘记英语」。
- **怎么用**：
  | 命令 | 作用 |
  |---|---|
  | `zhc init 名称` | 新建方言项目 |
  | `zhc run 文件` | 转译 + 编译 + 运行 |
  | `zhc check 文件` | 转译 + 编译检查 |
  | `zhc lint 文件` | 方言代码规范检查 |
  | `zhc expand 文件` | 查看转译前后对照（教学视图） |
  | `zhc eject 文件` | 导出官方仓颉源码 |
  | `zhc test` | 运行项目测试（方言单测） |
  | `zhc mapping list/check` | 查看/校验语言包映射 |
  | `zhc --help` | 中文帮助 |
- **注意**：命令的输出、错误提示、教学诊断全部中文；`zhc eject` 导出的官方代码可脱离方言独立编译。

## 词条 10.12 语言包机制

- **是什么**：方言词表按「语言包」组织：`zhc/lang-packs/zh/` 下 `keywords.toml`（关键字）、`stdlib.toml`（标准库别名）、`module_paths.toml`（模块路径）、`errors.toml`（错误消息）、`stdlib_meta.toml`（标准库元数据）。
- **为什么**：**转译即查表**——方言不是新语言，而是「词表驱动的重写规则」：查表替换 + 上下文保护（字符串不误改、声明名豁免、插值保护）。语言包可扩展意味着**新方言可以自己造**（换成别的语言词表就是另一种方言）。
- **怎么用**：
  ```bash
  zhc mapping list          # 列出当前语言包的词表
  zhc mapping check         # 校验词表与官方符号对应
  ZHC_LANG_PACKS=路径       # 环境变量指定语言包目录
  ```
  ```toml
  # keywords.toml 片段：方言 → 官方
  "函数" = "func"
  "让" = "let"
  ```
- **注意**：语言包是**双向映射**（转译 + 反向映射用于错误提示/expand 视图）；`errors.toml` 的 645 条诊断码 = 官方 644 + 方言自定义 1（找不到包）；词表缺失时走「原文回退 + 记录」闭环（`zhc mapping check --missing` 可查）。
