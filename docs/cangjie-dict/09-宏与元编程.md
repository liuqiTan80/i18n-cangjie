# 09 宏与元编程

> 宏是「写代码的代码」：在**编译期**接收代码、产出代码。这是仓颉区别于多数现代语言的杀手锏特性。
> 本卷词条：宏 / 引用 / 宏包 / 声明宏 / 过程宏 / 派生 / 编译期求值。

## 词条 9.1 宏（宏 / macro）

- **是什么**：编译期执行的代码变换器：`宏 名字(input: Tokens): Tokens`——吃代码 token，吐代码 token。调用写作 `@宏名(参数)`。
- **为什么**：普通函数只能操作**值**（运行时）；宏能操作**代码本身**（编译期）。这带来三类函数做不到的事：
  1. **语法糖再造**：把重复模式（`记录日志`、`测量耗时`）打包成宏调用；
  2. **编译期检查**：在编译期验证模式（如 DSL 语法校验）；
  3. **性能**：展开在编译期完成，运行时零开销。
  仓颉把宏设计为**卫生宏**（不会意外捕获调用方变量）+ **类型化**（输入输出都是 Tokens），比 C 预处理器的文本替换安全得多。
- **怎么用**（完整流程见 9.3 宏包；调用侧最简单）：
  ```cangjie
  导入 调试.*
  主函数() {
      让 x = 3
      @调试日志(x + 1)     // 示意：宏在编译期展开，普通运行环境无法演示
  }
  ```
- **注意**：宏调用以 `@` 开头；宏名可用**中文**（语言包「宏」节映射，如 `@调试日志`）；宏展开在编译期完成，`zhc expand` 可查看展开前后对照。

## 词条 9.2 引用（引用 / quote）

- **是什么**：宏内部构造代码的语法：`引用(打印行($(名字)))`——把「代码模板」变成 Tokens。
- **为什么**：宏的「输出」是代码，而代码在源码里就是文本。`引用(...)` 让你用**写代码的方式写代码**；`$(表达式)` 是**代码位置的插值**——把变量值/子 Tokens 嵌入模板（区别于字符串插值 `${}`：`$()` 插的是代码不是文本）。
- **怎么用**：
  ```cangjie
  // 宏包内（官方语法）：把传入表达式变成「打印它的文本」
  公开 宏 调试日志(input: Tokens): Tokens {
      引用(打印行($(输入.toString())))
  }
  ```
- **注意**：`$(输入.toString())` 插入的是**字符串字面量**（`"x + 1"`）；`$(输入)` 直接嵌入**代码 token**（保持为表达式）；`$()` 只在**代码位置**有效——字符串字面量里不会替换。

## 词条 9.3 宏包（宏 包）

- **是什么**：宏必须定义在**宏包**中：源码**首行** `宏 包 包名`；主程序 `导入 宏包名.*` 后使用。
- **为什么**：宏包是**独立编译单元**——宏包先被编译成宏库（`.cjo` + 动态库），主程序编译时展开。这个「两步编译」隔离了宏的编译环境，也让宏可以跨项目分发（相当于「代码生成器插件」）。
- **怎么用**：
  ```
  define/define.cj          # 宏包源码（首行 宏 包 define）
  define/define.cjo         # ① 宏包编译产物：cjc define/define.cj --compile-macro
  main.cj                   # ② 主程序：cjc main.cj -o main（import define.* 自动展开）
  ```
  ```cangjie
  // define/define.cj（宏包内写官方语法）
  宏 包 define
  公开 宏 调试日志(input: Tokens): Tokens {
      引用(打印行($(输入.toString())))
  }
  ```
- **注意**：宏包内**只能暴露宏**（不能导出版本外的类型/函数）；zhc 的 `zhc init` 项目模板与 `zhc expand` 教学视图已内置两步编译支持；宏包文件用 `.cj` 扩展名（官方语法，不经方言转译）。

## 词条 9.4 声明宏（声明式宏）

- **是什么**：用「模式 → 展开」规则**声明**的宏（Rust 的 `macro_rules!` 类似物）。
- **为什么**：不需要编程逻辑（没有 `如果`/循环），纯文本模式匹配——「看到什么模式就替换成什么」。适合简单语法糖；复杂变换用过程宏（9.5）。
- **怎么用**：声明宏在仓颉中以宏库形式提供（`宏` 关键字 + 模式匹配写法），与过程宏共用 `@调用` 语法；具体模式语法见官方《宏》文档。
- **注意**：声明宏能力是过程宏的子集——**项目实践中优先掌握过程宏**（9.5），声明宏按需查阅。

## 词条 9.5 过程宏（命令式宏）

- **是什么**：用**完整编程逻辑**（任意代码）处理 Tokens 的宏：`宏 名(input: Tokens): Tokens { ...任何代码... }`。
- **为什么**：输入可以是**任意代码**，宏体内可以循环、匹配、查表——「代码生成器」的全能力。仓颉 1.0 的宏是过程式风格（函数式宏），这是它与 Rust 声明宏的重要差异：**宏就是普通函数，只是吃 Tokens**。
- **怎么用**：
  ```cangjie
  // 宏包内：生成「循环 N 次」的代码
  公开 宏 重复(输入: Tokens): Tokens {
      让 次数 = 输入.toString()       // 输入是代码文本
      引用({
          对于 (i in 0..$(次数)) {
              打印行("第${i}次")
          }
      })
  }
  ```
- **注意**：宏内**不能**做类型检查（Tokens 是纯语法）；要类型信息需官方更高级的宏 API（`TypedTokens`）；宏展开错误在编译期报告——`zhc` 会把宏相关错误也转成中文提示。

## 词条 9.6 派生（派生 / Derive）

- **是什么**：自动生成**样板实现**的宏：给类型标 `@派生(相等, 比较)`，编译器自动生成 `相等`/`比较` 等方法。
- **为什么**：结构体/枚举的 `相等`（equals）、`比较`（compare）、`哈希`（hashCode）实现**机械重复**——手写又臭又容易错（漏一个字段）。派生宏按「字段逐个比较」的语义自动生成，是「约定优于配置」的典范。
- **怎么用**：
  ```cangjie
  // 语法示意（官方 Derive 宏）
  结构体 学生 @派生(相等) {
      公开 可变 名字: 字符串
  }
  ```
- **注意**：派生条件：字段类型必须支持被派生的操作（如派生 `比较` 要求字段都可比较）；方言 `派生` → 官方 `Derive`；派生宏与手写实现二选一（都写了报冲突）。

## 词条 9.7 宏与编译期求值

- **是什么**：宏在**编译期**运行——宏里的循环、计算都在编译阶段完成，运行时只剩展开结果。
- **为什么**：这是宏的**性能哲学**：把「每次运行都做的重复工作」提前到「编译时做一次」。例：宏生成 100 条 case 分支，运行时就是 100 条**已生成**的代码——没有循环开销、没有运行时解释。
- **怎么用**：
  ```cangjie
  // 宏包内：编译期生成 1..N 的累加代码（示意）
  公开 宏 预计算累加(输入: Tokens): Tokens {
      可变 代码 = ""
      对于 (i in 0..5) { 代码 += "打印行(${i * i});" }
      引用($(代码))    // 注意：生成代码的字符串拼接在编译期完成
  }
  ```
- **注意**：编译期执行**没有运行时错误**（宏崩溃 = 编译错误，好事——错误提前）；宏不能做 IO（设计约束，保证构建可复现）；「编译期求值」是宏与泛型（编译期类型检查）之外，仓颉的第三种编译期机制。
