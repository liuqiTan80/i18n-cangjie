# 08 错误处理与并发

> 错误处理回答「出问题时怎么办」，并发回答「多件事同时进行时怎么办」——两者都是真实程序绕不开的课题。
> 本卷词条：选项 / 有值 / 无值 / 预期失败用选项 / 异常 / 抛出 / 尝试 / 捕获 / 最终 / 断言 / 退出 / 生成 / 同步 / 锁与原子。

## 词条 8.1 选项（选项 / Option）

- **是什么**：可空包装类型 `选项<T>`——要么 `有值(x)` 要么 `无值`（见 2.12）。
- **为什么**：仓颉**消灭空指针**的核心机制：可空性进入类型系统，编译器强制处理「可能没有」。函数返回 `选项<字符串>` 时，调用方**必须**用 `匹配` 处理两种情况——漏掉一种编译失败。
- **怎么用**：
  ```cangjie
  函数 找名字(编号: 整数): 选项<字符串> {
      如果 (编号 == 1) { 返回 有值("小明") }
      返回 无值
  }
  主函数() {
      匹配 (找名字(1)) {
          情况 有值(名字) => 打印行("找到：${名字}")
          情况 无值 => 打印行("没找到")
      }
      // 快捷方式：
      打印行(找名字(1).获取或默认({ => "无名" }))
  }
  ```
- **注意**：`无值` 可以赋给任何 `选项<T>`；**没有** `null`/`空指针` 这个说法；`选项` 值不能当普通值用（`找名字(1) + "!"` 报错——必须先解包）。

## 词条 8.2 有值（有值 / Some）

- **是什么**：`选项` 的「有值」分支：`有值(内容)`。
- **怎么用**：见 8.1；在 `匹配` 中 `情况 有值(名字)` 同时判断并解包。
- **注意**：`有值(无值)` 合法（嵌套选项，少用）；构造 `选项` 的三种方式：`有值(x)`、`无值`、`x.有值()`。

## 词条 8.3 无值（无值 / None）

- **是什么**：`选项` 的「没有值」分支（见 1.10）。
- **怎么用**：见 8.1。
- **注意**：`无值` 是**值**不是类型（类型是 `选项<T>`）；`无值 == 无值` 为真。

## 词条 8.4 预期失败用选项（官方无 Result）

- **是什么**：官方 1.0.5 **没有** `结果`（Result）类型——「可能失败」统一用 `选项<T>` 表达：成功是 `有值(成功值)`，失败是 `无值`。
- **为什么**：失败是返回值的一部分，调用方**必须**处理（`匹配` 强制穷尽两种情况）——比异常更「函数式」，适合「预期中的失败」（格式错误、查无此人）；异常留给「意外」（见 8.6 的分工思想）。
- **怎么用**：
  ```cangjie
  导入 转换.*
  导入 正则.*
  函数 解析分数(文本: 字符串): 选项<整数> {
      如果 (正则("\\d+").匹配正则(文本)) {
          返回 有值(整数.解析(文本))
      }
      返回 无值          // 不是数字 → 失败
  }
  主函数() {
      匹配 (解析分数("95")) {
          情况 有值(分数) => 打印行("分数：${分数}")
          情况 无值 => 打印行("不是数字")
      }
  }
  ```
- **注意**：`整数.解析`（Int64.parse）需要 `导入 转换.*`（std.convert）；「成功/失败」的信息都塞在 `有值`/`无值` 里——想带**失败原因**就返回 `选项<字符串>` 或定义自己的枚举（见 6.7）；`选项` 没有「异常堆栈」，它只表达「没有值」。

## 词条 8.5 异常（异常 / Exception）

- **是什么**：**意外错误**的对象：`异常("消息")`；可携带消息与堆栈。
- **为什么**：不可预见的错误（内存不足、协议错误）不适合用返回值传播——异常沿调用栈**自动上抛**，谁有能力处理谁捕获。仓颉异常是**检查异常**（可检查异常列表见编译器文档）——设计上比 Java 更克制。
- **怎么用**：
  ```cangjie
  函数 除以(被除数: 整数, 除数: 整数): 整数 {
      如果 (除数 == 0) { 抛出 异常("除数不能为零") }
      返回 被除数 / 除数
  }
  ```
- **注意**：`异常` 的常用子类：`算术异常`、`索引越界异常`、`类型转换异常`、`空值异常`、`参数异常`——捕获时按需细分；不要用异常做常规控制流（性能与可读性都差）。

## 词条 8.6 抛出（抛出 / throw）

- **是什么**：主动制造异常：`抛出 异常("消息")`。
- **为什么**：函数检测到「自己处理不了的情况」时，把问题**抛给上层**——责任上移。
- **怎么用**：见 8.5。
- **注意**：`抛出` 后函数立即终止；`抛出` 的表达式类型是 `空类型`（Nothing，见 2.7）——因此 `抛出` 可以放在任何需要值的位置（如 `返回 抛出 异常("x")` 或 `让 x = 抛出 ...`）。

## 词条 8.7 尝试（尝试 / try）

- **是什么**：开启**异常保护区**：`尝试 { 可能出错的代码 }`。
- **为什么**：把「可能抛异常」的代码圈起来，配合 `捕获` 处理——异常只在保护区内被拦截。
- **怎么用**：见 8.8。
- **注意**：`尝试` 必须有 `捕获` 或 `最终` 之一（不能只有 `尝试` 块）；`尝试` 块内声明的变量块外不可见（作用域规则，见 3.5）。

## 词条 8.8 捕获（捕获 / catch）

- **是什么**：拦截指定类型的异常：`捕获 (错误: 异常) { 处理 }`。
- **为什么**：按类型分流处理：`捕获 (错误: 文件不存在异常)` 只处理文件问题，其他异常继续上抛。捕获后程序**继续执行**（不崩溃）。
- **怎么用**：
  ```cangjie
  函数 除以(被除数: 整数, 除数: 整数): 整数 {
      如果 (除数 == 0) { 抛出 异常("除数不能为零") }
      返回 被除数 / 除数
  }
  主函数() {
      尝试 {
          让 结果 = 除以(10, 0)
          打印行("结果：${结果}")
      } 捕获 (错误: 异常) {
          打印行("出错了：${错误.消息}")
      }
  }
  ```
- **注意**：`捕获` 分支从上到下匹配**第一个兼容类型**（子类异常要写在父类前面）；捕获变量的名字（`错误`）可随意起；`捕获` 后可以再 `抛出`（记录后重新抛出）。

## 词条 8.9 最终（最终 / finally）

- **是什么**：无论是否异常**都会执行**的收尾块：`最终 { 清理 }`。
- **为什么**：资源清理（关文件、释放锁）必须**无条件执行**——`最终` 保证它跑（即使 `捕获` 里又抛出、即使 `返回` 提前退出）。
- **怎么用**：
  ```cangjie
  主函数() {
      尝试 {
          打印行("干活")
      } 捕获 (错误: 异常) {
          打印行("处理错误")
      } 最终 {
          打印行("无论如何都执行")
      }
  }
  ```
- **注意**：`最终` 在 `返回` **之后**执行（返回值先算好再跑清理）；`最终` 里不要写可能抛异常的代码（会覆盖原异常）；`尝试/捕获/最终` 的方言顺序与官方一致。

## 词条 8.10 断言（断言 / assert）

- **是什么**：检查「不变量」：`断言(条件, "失败信息")`——条件为假时抛 `断言异常`。**注意：`断言` 只能在测试宏（`@测试`/`@期望`，见 12 卷）内部使用**——普通 `主函数` 代码里没有 `断言`，本词条示例用手写 `如果` 检查代替。
- **为什么**：**程序员的自我检查**：断言「这里不可能出错」（`断言(总数 > 0)`）。断言是开发期保险丝，帮助**尽早发现逻辑错误**（比错误蔓延成奇怪现象好得多）。发布构建可用选项关闭。
- **怎么用**：
  ```cangjie
  函数 取中间(列表: 数组<整数>): 整数 {
      如果 (列表.长度 == 0) { 抛出 异常("空列表没有中间值") }
      返回 列表[列表.长度 / 2]
  }
  主函数() { 打印行(取中间([1, 2, 3])) }
  ```
- **注意**：断言失败抛异常（可被 `捕获` 拦截）；不要用断言做**输入校验**（用户输入要用错误处理，断言是「程序自己错了」的信号）。

## 词条 8.11 退出（退出 / exit）

- **是什么**：立即终止进程：`退出(状态码)`——0 表示成功，非 0 表示失败。
- **为什么**：程序「无法继续」时的最终手段（配置缺失、致命错误）；状态码让调用方（脚本/CI）知道成败。
- **怎么用**：
  ```cangjie
  导入 环境.*
  主函数(): 单元 {
      让 配置 = 读取行()
      如果 (配置 == "") {
          打印行("缺少配置")
          退出(1)
      }
      打印行("配置：${配置}")
  }
  ```
- **注意**：`退出` 返回 `空类型`（永不返回，见 2.7）；退出前 `最终` 块**不会**执行（进程直接终止）——需要清理先手动做。

## 词条 8.12 生成（生成 / spawn）——并发入门

- **是什么**：启动一个**并发任务**：`生成 { 任务代码 }`（官方 spawn）。
- **为什么**：多核时代：下载文件、渲染界面、处理请求可以**同时进行**。`生成` 把「这段代码放到另一个执行上下文跑」封装成一个函数调用——比手动管理线程简单得多。
- **怎么用**：
  ```cangjie
  主函数() {
      生成 { 打印行("任务一") }
      生成 { 打印行("任务二") }
      打印行("主函数")
  }
  ```
- **注意**：输出顺序**不确定**（并发执行）；`生成` 返回任务句柄（可等待完成，官方 Future）；并发**共享可变数据需要同步**（见 8.13/8.14）——这是并发 bug 的头号来源。

## 词条 8.13 同步（同步 / synchronized）

- **是什么**：把代码块**加锁**：`同步(锁对象) { 临界区 }`——同一时刻只有一个执行上下文能进入。同步块必须有锁对象参数（官方 synchronized(锁)）。
- **为什么**：多个任务同时改同一个 `可变` 数据会**数据竞争**（读到一半的值、丢失更新）。同步块 = 「这段代码我独占，其他任务等着」。
- **怎么用**：
  ```cangjie
  导入 标准同步.{锁}
  可变 计数 = 0
  主函数() {
      让 锁对象 = 锁()
      同步(锁对象) {
          计数 += 1        // 临界区：同一时刻只有一个任务在改
      }
      打印行(计数)
  }
  ```
- **注意**：**锁要小**（临界区越短越好——长临界区拖慢所有并发）；不要嵌套同步（死锁风险）；不可变数据（`让`）**不需要**同步——这是「默认不可变」的另一大红利。

## 词条 8.14 锁与原子（std.sync）

- **是什么**：标准库 `标准同步`（官方 std.sync）模块提供的并发原语：`锁`（Mutex，可重入互斥锁）、`原子整数`（AtomicInt64）、`原子引用`（AtomicReference）、`原子布尔`（AtomicBool）。
- **为什么**：`同步` 块适合临界区；需要**更细粒度**控制（等待条件、原子计数）时用这些原语。原子操作是无锁的「安全增减」——比同步块更快。
- **怎么用**：
  ```cangjie
  导入 标准同步.*
  主函数() {
      让 原子计数 = 原子整数(0)
      生成 { 原子计数.原子加(1) }
      生成 { 原子计数.原子加(1) }
      打印行("原子计数：${原子计数.原子加载()}")
      // 锁的用法：加锁 / 解锁
      让 互斥锁 = 锁()
      互斥锁.加锁()
      互斥锁.解锁()
  }
  ```
- **注意**：方言模块路径：`导入 标准同步.*`（官方 std.sync，见 10.1 模块表）；`原子整数(初始值)` 构造、`.原子加(增量)`（fetchAdd）增、`.原子加载()`（load）读；`锁().加锁()`/`解锁()`（lock/unlock）成对使用（忘了解锁会卡死——用 `尝试/最终` 保证解锁）；原子类型：原子整数（AtomicInt64）/原子引用（AtomicReference）/原子布尔（AtomicBool）——只有整数原子支持算术（`原子加` fetchAdd），引用/布尔原子只有读写与交换（load/store/swap）；`原子引用` 只接受**引用类型**（class 对象——传 `字符串` 等值类型会编译报错）。
