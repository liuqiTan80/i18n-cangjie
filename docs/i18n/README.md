# zhc 文档多语言本地化方案（docs/i18n/）

> 目标：让所有用户都能用自己熟悉的母语**看懂并顺利使用** zhc——包括项目文档、
> 界面文案、学习资料与库翻译。本页是本地化的总入口：范围分级、目录结构、
> 术语约定与同步维护机制。运行时方言（写代码用的语言）机制见
> [语言包开发](../语言包开发.md)；库翻译集中管理见
> [多语言翻译集中管理方案](../多语言翻译集中管理方案.md)（§19）。

## 一、翻译内容范围（四级，按用户接触顺序）

| 级别 | 内容 | 载体 | 状态 |
|---|---|---|---|
| **L0 运行时界面** | CLI 用法/进度/错误提示、测试输出词典 | 语言包 `ui.toml`（键 = zh 模板串，缺键回退） | 七包界面 100% 全量档（zh 不建表仅测试词典 10 条；ru 另带测试词典 10 条，合计 322） |
| **L1 方言词表** | 关键字/标准库别名/模块路径 | 语言包 `keywords/stdlib/module_paths.toml` | zh 全量（59/214/19）；en 恒等（58/162/14）；六语 standard：关键字 59 全 + 标准库 205–206 + 模块路径 19 |
| **L2 库翻译** | 第三方库 API 映射 | `zhc share` 注册表 `<语言>/crates/<名>.toml`（与 libs/ 平台同构） | csv4cj/ini4cj（zh）已入库，fr/ko 经 Hub 按需分发 |
| **L3 阅读文档** | README/快速上手/学习资料 | `docs/i18n/<语言>/`（本目录） | 八语快速上手齐备；**en 教程全书（00-20）与 ja 第 1 卷（00-07）受管译文已入库**；其余语言为第 0 课导学 |

分级原则：**越靠近用户操作的内容越优先**——先能跑通（L0/L1），再能扩展（L2），
最后深读（L3）。

## 二、组织结构与语言切换

```text
docs/i18n/
├── README.md            本页（方案总入口，中文）
├── en/  fr/  de/  es/   English · Français · Deutsch · Español
├── ko/  ja/  ru/        한국어 · 日本語 · Русский
│   └── 每语言：README.md（快速上手）+ 教程译文
│       （en 全书 00-20 共 21 篇 / ja 第 1 卷 00-07 / 其余第 0 课导学）
└── （后续语言/文档按同样结构扩展，门禁自动纳管）
```

- **选择与切换**：主 README 顶部有八语导航行，每个译文页顶部有同款导航
  （含回链），任何页面一跳即达；
  运行时语言用 `ZHCLANG` 切换，文档语言与代码方言相互独立（可读英文文档、写韩语代码）；
- **翻译 vs 改写**：快速上手类文档按「本地化改写」处理（结构对齐中文原版、
  示例换成本语言方言、命令保持一致），而非逐句直译——保证表达符合该语言习惯；
- **元数据头**：每个译文文件首行携带同步锚点（供门禁脚本校验，渲染不可见）：
  `<!-- zhc-i18n 源: README.md 基线: <hash64> 时间: YYYY-MM-DD -->`。

## 三、术语统一与翻译质量约定

1. **术语表随语言走**：每个译文页末尾附该语言术语表（本页下方为 zh 基准），
   新增译文必须先声明术语表并全篇一致；与该语言的语言包用词互相呼应
   （ko：방언/언어 팩/매핑；fr：dialecte/paquet de langue/mappage）；
2. **恒等规则跨语言一致**：get/size/print 等通用短名与命令名（`zhc run`、
   `cjpm build`）一律不译，保证可复制执行；
3. **语言习惯**：允许语序与措辞本地化，禁止机翻腔；示例输出保留运行时真实输出
   （中文提示是程序真实行为，如实展示）；
4. **审校口径**：与 §19 Hub 相同——翻译者自审 → 术语表核对 → PR 复审。

**zh 基准术语**：方言（dialect）· 语言包（language pack）· 映射（mapping）·
转译（transpile）· 共享仓库/Hub（shared registry）· 基线（baseline）·
门禁（quality gate）· 落后/同步（stale/in-sync）。

## 四、同步维护机制（内容新增/更新时版本一致）

与 §19 同思路：**源文件 hash64 指纹驱动**，门禁脚本无 SDK 依赖（CI 可跑）：

```bash
python3 scripts/verify-i18n-docs.py     # 逐译文核对源指纹 + 导航链接
```

- 译文头部「基线」= 源文件（如根 README.md）的 hash64 校验和；
- 源文档更新 → 指纹变化 → 门禁把该译文标为**落后**（验收红）；
- 翻译者更新译文 → 刷新头部基线与时间 → 门禁恢复绿；
- 源删除/移动 → 门禁报**源缺失**，防止僵尸译文。

**更新流程（新增内容同理）**：
1. 改中文源文档（zh 是唯一正本）；
2. 跑 `verify-i18n-docs.py` → 得到落后清单；
3. 按清单逐语言更新译文（术语表核对），刷新基线锚点；
4. 重跑门禁全绿 → 提交（译文与源同一 PR，保证评审时可见双语对照）。

**新增一种语言**：`docs/i18n/<代码>/README.md`（含锚点与导航）→ 主 README
导航行加链接 → 本页语言清单登记 → 门禁自动纳管。

**新增一篇文档**：中文源写入 `docs/` → 需要翻译的语言在 `docs/i18n/<语言>/`
建立同名文件（带锚点）→ 门禁自动纳管；暂不翻译的语言不建文件（门禁不报错，
避免强制全量翻译）。

## 四·五、教程的多语言（受管译文入库）

《中文仓颉程序设计》中文正本（20 章 + 3 附录 + 答案，150+ 代码块实测）为锁定区，
**目录与内容保持不动**（check-libs --locked 守护）；多语言版以**受管译文**形式入仓：

- 译文存 `docs/i18n/<语言>/tutorial-XX.md`，首行锚点声明源章节 + 基线 hash64，
  `verify-i18n-docs.py` 逐篇纳管（源变动 → 标落后，需人工同步刷新）；
- 每章译文结构对齐中文正本，示例换成本语言方言代码（可实测运行）；
- 当前进度：**en 全书 00-20（21 篇）+ ja 第 1 卷 00-07（8 篇）已入库全同步**；
  未翻译语言保留 tutorial-00 导学（不强制全量，门禁不报错）。

## 五、与运行时本地化的关系

- 文档多语言（本页）与代码方言（语言包）、库翻译（share Hub）共用同一套
  基础设施：hash64 指纹、校验和门禁、`ZHCLANG`/`ZHC_PULL_LANG` 变量、
  缺译回退策略——一套机制管所有翻译资产；
- 教程（《中文仓颉程序设计》，150+ 代码块实测）中文正本属锁定区，译文按章
  受管入库（见四·五节），避免主仓膨胀与锁定区耦合由锚点门禁平衡。
