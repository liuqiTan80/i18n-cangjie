# 第 10 章 文字列とテキスト処理

> **この章の学習目標**：文字列補間と文字列メソッド群を使いこなし、インポート文を学び、正規表現に初めて触れる。
> **この章を読み終えると答えられる問い**：文字列の「長さ」はなぜ文字数と違うのか？漢字を半分に切ると何が起きるのか？正規表現の `\d` はなぜ文字列では `\\d` と書くのか？

---

## 10.1 定義：文字列とは何か

**定義**：文字列（`文字列` = 公式 `String`）は**不変の Unicode 文字の並び**——いったん作ったら変更できず、「変更」する操作はすべて新しい文字列を返す。内部は **UTF-8 バイト**で格納：日本語・中国語の漢字 1 字 = 3 バイト。

## 10.2 補間：${} でテンプレートを組む

**定義**：文字列の中で `${式}` を使うと変数や式を埋め込める——倉頡で文字列を組み立てる主な方法。

**日本語の書き方**：

```jc
メイン() {
    おく なまえ = "倉頡"
    おく バージョン = 1
    ひょうじ("${なまえ} 言語、バージョン ${バージョン}.0")   // 倉頡 言語、バージョン 1.0
    ひょうじ("四則：${3 + 4 * 2}")             // 四則：11（中には任意の式を置ける）
    ひょうじ("入れ子：${なまえ.ながさ}")         // 入れ子：6（メソッド呼び出しも OK）
}
```

**注意事項**：

- 補間の中は**二重に変換**される——方言の単語（`ながさ` など）は `${}` の中でも公式名に翻訳される；
- 補間には**変数と式だけ**を置き、キーワードを置かない——`"${関数}"` のような補間部はコードとして二重変換され、キーワードを入れるとコンパイルエラーになる；
- 文字列の連結は `+`（少量）；大量の連結は `もじあつめ`（10.5）。

## 10.3 文字列メソッド群：検索 / 切り出し / 変換 / 分割

**定義**：文字列処理は最も頻度の高いプログラミング場面。方言はよく使うメソッドをすべて母語化しており、四つの大分類をカバーする。

```jc
いれる 正規表現.*
メイン() {
    おく テキスト = "  倉頡 言語 処理  "
    // ① 検索
    ひょうじ(テキスト.ながさ)                     // 24（バイト数！UTF-8 では漢字 1 字 = 3 バイト）
    ひょうじ(テキスト.さがす("言語"))             // Some(9)（バイトの添字。見つからないと None）
    ひょうじ(テキスト.はじまる("  倉頡"))         // true（実行時出力は公式形式）
    ひょうじ(テキスト.おわる("処理  "))           // true
    // ② 切り出し（文字列スライスはバイト単位——漢字 1 字 = 3 バイト）
    ひょうじ("倉頡言語"[0..3])              // 倉（先頭 3 バイト = 漢字 1 字）
    ひょうじ("(${テキスト.trimAscii()})")       // (倉頡 言語 処理)（前後の空白を除去。trimAscii は公式名＝中国語方言の「修剪」。日本語パック未収録）
    // ③ 変換
    ひょうじ("abc".toAsciiUpper())           // ABC（公式名＝「大写」。日本語パック未収録）
    ひょうじ("ABC".toAsciiLower())           // abc（公式名＝「小写」。同上）
    ひょうじ("漢-字".おきかえる("-", "→"))        // 漢→字
    // ④ 分割
    おく 部分 = テキスト.trimAscii().わける(" ")
    ひょうじ(部分.ながさ)                     // 3（わける は配列を返す）
    // ⑤ 判定（正規表現マッチ）
    ひょうじ(せいき("\\d+").ヒット("123"))  // true
}
```

**四つの真実（覚えておこう）**：

| 真実 | 説明 |
|---|---|
| **長さはバイト数** | `"倉頡".ながさ` は 6 であって 2 ではない。文字数で走査するには `runes()` |
| **スライスはバイト単位** | `テキスト[0..3]` で漢字 1 字。バイト境界を外すと文字化けやクラッシュの元 |
| **大文字/小文字は純粋な ASCII** | `toAsciiUpper()`/`toAsciiLower()` は英字のみ変換。日本語に大文字の概念はない |
| **正規表現マッチは `ヒット`** | = 公式 `matches`。戻り値はブール。`せいき("\\d+")` の中の `\\` はエスケープ済みの `\` |

## 10.4 インポート文

**定義**：`いれる`（import）：ほかのモジュールの名前に「ドアを開ける」。パスは `.` で区切る。

**日本語の書き方**：

```jc
いれる 標準コレクション.{リスト, マップ};    // 精密インポート：波かっこの名前だけを導入
いれる 標準コレクション.*                     // ワイルドカード：そのモジュールの全名前を導入
いれる 正規表現.*                         // std.regex：正規表現型とマッチ
いれる 数学.*                         // std.math：平方根、絶対値など
いれる 標準変換.*                         // std.convert：フォーマット、toString など
```

**注意事項**：

- `標準コレクション` = `std.collection`（言語パックの「モジュールパス」節）。波かっこ内の母語名も 1 つずつ置換される；
- 末尾のセミコロンは省略可（公式と同じ）；
- インストールしていないパッケージをインポートすると zhc が「パッケージが見つからない」方言エラーを報告。未使用インポートは警告；
- ワイルドカードは名前の衝突がありうる（同名なら `パッケージ.名前` で限定）。

## 10.5 連結と収集：もじあつめ

**定義**：`もじあつめ` は要素を**つなげて 1 つの文字列にする**（公式 `collectString`）——大量連結の正しい姿勢。文字列補間 `${}` は「テンプレートを組む」需要をカバーする。

```jc
いれる 標準コレクション.*
メイン() {
    変数 めいぼ = リスト<文字列>()
    めいぼ.くわえる("あ"); めいぼ.くわえる("い"); めいぼ.くわえる("う")
    ひょうじ(めいぼ |> もじあつめ(くぎり: ""))   // あいう（区切りなし）
    ひょうじ("円周率 = ${3.14159}")            // 文字列補間で小数を出力
}
```

**注意事項**：

- 公式 1.0.5 に**`join` はない**——区切りを付けたいなら `うつす`（map）してから収集するか、自分で処理する；
- `くぎり` は**名前付き引数**（公式 `delimiter`）；
- `フォーマット`（format）は**数値のメソッド**（`42.フォーマット("${0}")`、`いれる 標準変換.*` が必要）——独立した `フォーマット` パッケージは**ない**。`いれる フォーマット.*` と書かないこと。

## 10.6 正規表現の初体験

**定義**：正規表現 = 「文字列のパターン」を記述する小さな言語——`\d` は数字、`+` は 1 個以上、`[0-9]` は範囲、`.` は任意の 1 文字。正規表現オブジェクトは `せいき("パターン")` で作る（公式 `Regex`、`いれる 正規表現.*` が必要）。

**日本語の書き方**：

```jc
いれる 正規表現.*
メイン() {
    ひょうじ(せいき("\\d+").ヒット("123"))       // true（123 はすべて数字）
    ひょうじ(せいき("\\d+").ヒット("12a"))       // true！部分文字列 "12" にマッチ——包含マッチ
    ひょうじ(せいき("^\\d+$").ヒット("12a"))     // false（^ 先頭 + $ 末尾で「全体が完全一致」）

    おく でんわ = "138-1234-5678"
    ひょうじ(せいき("\\d{3}-\\d{4}-\\d{4}").ヒット(でんわ))  // true（{3} はちょうど 3 個）
}
```

**注意事項**：

- **エスケープの落とし穴**：正規表現の `\d` は文字列の中では `\\d` と書く（文字列の `\\` が本物の `\` になる）——初心者の最も多いエラー；
- `ヒット` は**ブール**を返す（「マッチしたか」——注意：包含マッチなので `せいき("\\d+")` は `"12a"` にも真を返す。部分列 `"12"` にマッチしたから。「全体が数字」と判定するには `^` 先頭 + `$` 末尾のアンカーが必須）。内容を取り出すにはより高度な API（公式ドキュメントへ）；
- 正規表現は「形式の判定」向き。複雑なテキスト解析（入れ子・再帰）には不向き——そんなときはパーサーを手書きする。

## ✳ 設計思想

**① エンコーディング意識：バイト ≠ 文字**。日本語・中国語は UTF-8 で 1 字 3 バイト。「文字列の長さ」はバイト数——初心者が最も踏みがちな穴。文字列は本質的にバイト列であり、文字単位で扱うには `chars()` を通る。倉頡は「テキスト」（文字）と「バイト」（二進）を区別する——ファイル・ネットワーク・暗号化が扱うのはバイト列であって文字ではない。両者を混同するのは古典的なバグの元。

**② 不変の文字列**：文字列は変更できず、操作のたびに新しい値を作る——おかげで文字列は安全に共有できる（引数で渡しても書き換えを心配しない）。代償は大量連結時の性能（だから `もじあつめ` がある）。

**③ 宣言的なテキスト処理**：`わける` → `こす` → `もじあつめ` のパイプは手書きループより直読的——「分解 → 選別 → 組み立て直す」がテキスト処理の標準的な心構え。

## 練習

1. 補間で表示しよう：「私の名前は XX、今年 X 歳、プログラミングを学んで X 日」；
2. `"  倉頡 言語 処理  "` を `trimAscii()` してから空白で分割し、`おきかえる` で「言語」を「開発」に変えて、区切りごとに表示しよう；
3. 正規表現で検証しよう：`"abc123"` が英字で始まるか、`"2026-09-01"` が `\d{4}-\d{2}-\d{2}` 形式か；
4. `もじあつめ` で `リスト<文字列>`（"あ","い","う"）を `"あいう"` につなごう。次に区切り付き `"あ、い、う"` も試そう（ヒント：`うつす` で各要素に「、」を足してから収集。末尾の処理に注意）；
5. 挑戦：1 つの文の中で、各文字が何回現れるか数えよう（ヒント：`runes()` で走査 + `マップ` でカウント。第 11 章の容器の先取り）。

## まとめ

- 補間 `${}` には変数と式。二重変換される。文字列は `+`（少量）、`もじあつめ`（大量）；
- メソッド群は四分類：検索（`さがす`/`はじまる`/`おわる`）、切り出し（スライス/`trimAscii()`）、変換（`toAsciiUpper`/`toAsciiLower`/`おきかえる`）、分割（`わける`）；
- `ながさ` はバイト数（漢字 3 バイト/字）、スライスもバイト単位、大文字/小文字は純 ASCII；
- `いれる` は二形態：精密（`{名前}`）とワイルドカード（`*`）。モジュールパスは言語パックに載っている；
- 正規表現：`せいき("パターン").ヒット(テキスト)` はブールを返す。`\d` は文字列で `\\d` と書く。
