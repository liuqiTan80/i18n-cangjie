# 第 7 章 関数に初めて触れる

> **この章の目標**
> - 「関数」がコードを名前付きボックスにしまい、必要なときに取り出して使える仕組みだと理解する；
> - 関数の定義を学ぶ：引数（材料）と戻り値（完成品）；
> - 関数がなぜコードを重複させず、直しやすく、読みやすくするのかを理解する。
>
> **この章を読み終えると答えられる**：関数と変数ボックスの違いは？引数と戻り値とは？関数を呼び出すとき、中では何が起きる？

---

## 7.1 繰り返し書くコードは関数にしまう

第 5 章の「成績ランク分け」の判断を、三回使わなければならなくなったとしましょう。三回コピペしますか？コードは長くて醜くなり、直すときは三か所直さなければならず、一か所直し忘れたらバグになります。

**関数**こそ解決策：あるコードのかたまりを「道具箱」にしまい、名前を付けて、必要なときにいつでも取り出します。

## 7.2 関数を定義する

```jc
関数 ランク分け(点数: せいすう): 文字列 {
    もし (点数 >= 90) { かえす "優秀" }
    またもし (点数 >= 60) { かえす "合格" }
    でなければ { かえす "がんばれ" }
}

メイン() {
    ひょうじ("たろうのランク：${ランク分け(85)}")
    ひょうじ("はなこのランク：${ランク分け(95)}")
}
```

分解して見ましょう：

- `関数 ランク分け`：「ランク分け」という名前の関数を定義；
- `(点数: せいすう)`：**引数**——関数が働くために必要な「材料」。ここでは整数を一つ受け取り、`点数` と呼びます；
- `: 文字列`：**戻り値の型**——関数が渡す「完成品」は文字；
- `かえす "優秀"`：完成品を渡して、関数は**その場で終了**（後ろのコードは実行されません）；
- `ランク分け(85)`：関数を**呼び出す**（使う）。85 を渡します。

> たとえ話：関数は自動販売機——お金を入れる（引数）、商品が出る（戻り値）。入れるお金が違えば、出る商品も違います。

## 7.3 引数と戻り値：材料と完成品

もう一つ例を——長方形の面積を求めます：

```jc
関数 面積を求める(幅: じっすう, 高さ: じっすう): じっすう {
    かえす 幅 * 高さ
}

メイン() {
    ひょうじ("幅 3・高さ 4 の面積：${面積を求める(3.0, 4.0)}")
    ひょうじ("幅 5・高さ 6 の面積：${面積を求める(5.0, 6.0)}")
}
```

細かいポイント：

- **引数には型を必ず書きます**（`: じっすう`）——これは関数と外の世界との「契約」：何を渡し、何が返るか、書き合っておけば誰もあいまいになりません；
- 引数は**読み取り専用**（引数に再代入はできません）——入り口で渡された材料のようなもので、いったん受け取ったら別のものと交換はできません；
- 引数は複数にできます（カンマで区切る）。ゼロでも OK。

## 7.4 材料も完成品もなしでもいい

引数も戻り値も要らないときは、そのまま空にします：

```jc
関数 あいさつ() {
    ひょうじ("こんにちは！")
}

メイン() {
    あいさつ()
    あいさつ()
}
```

- `関数 あいさつ()`：かっこが空 = 材料は不要；
- `: 戻り値の型` が無い = 完成品はなし（実際には「ユニット」という空の値が返りますが、気にする必要はありません）；
- 二回呼べば二回表示——**一回書いて、何度も使う**。

## 7.5 なぜ関数を使うの？

1. **重複しない**：同じロジックは一度だけ書く（ランク分けの基準を変えたら、一か所直すだけ）；
2. **直しやすい**：一か所直せば、使っている全部の場所に反映される；
3. **読みやすい**：`ランク分け(85)` は一目で何をしているか分かる。長々とした `もし` の連なりよりすっきり；
4. **テストしやすい**：小さな関数は単独で検証しやすい——数を与えて、何が返るか見る（第 18 章でテストを本格的に扱います）。

> 関数の命名の小ルール：「動詞 + 目的語」——`合計を計算`、`ファイルを読む`、`面積を求める`。一目で何をするか分かります。

## 7.6 やってみよう

1. `総和(最大数: せいすう): せいすう` 関数を書き、ループで `1+2+…+最大数` を計算して、100 と 1000 で呼び出してみましょう；
2. `偶奇判定(数: せいすう): 文字列` 関数を書こう：偶数なら「偶数」、奇数なら「奇数」を返す（ヒント：`数 % 2 == 0` なら 2 で割り切れる。`%` は余り）；
3. 考えよう：`ランク分け(85)` の 85 と、関数の中の `点数` は同じボックス？——**違います**！呼び出しのとき、コンピューターは「点数」という新しいボックスを作って 85 を入れます。関数が終わるとボックスは消えます；
4. 挑戦：`星を描く(個数: せいすう)` 関数を書き、`個数` 個の `*` を一行で表示する。そして 3 行（個数 1、2、3）呼び出してみましょう。

## ✳ プログラミング思想の小話：抽象——細部を隠す

関数の最大の価値は「タイプ量が減る」ことではなく、**抽象**にあります：

- `ランク分け(85)` を使う人は、**ランク分けの中身を知る必要がありません**（長い `もし` の連なりを読まなくていい）；
- 洗濯機を使うときに、中のモーターがどう回るか知る必要がない——知っていればいいのは「服を入れる、ボタンを押す、服を取り出す」だけ。

これが抽象の力です：**「どうやるか」を中に隠し、「何をするか」だけを外に出す**。プログラムのすべての層は、この「隠す」ことの上に成り立っています：

- 関数がロジックを隠す → メインは呼び出しだけ考えればいい；
- クラスがデータを隠す（第 12 章）→ 外からはメソッドしか見えない；
- 言語パックが単語表を隠す（第 1 章）→ あなたは母語を書くだけ。

**プログラムを書ける人とは、層に分けて細部を隠せる人のことです。**

## 🍳 日常アルゴリズム小話：自動販売機

「ランク分け」のたとえを本物のコードに——ボタンが四つある自動販売機：

```jc
関数 販売(ボタン: せいすう): 文字列 {
    もし (ボタン == 1) { かえす "コーラ" }
    またもし (ボタン == 2) { かえす "オレンジジュース" }
    またもし (ボタン == 3) { かえす "ミネラルウォーター" }
    かえす "その商品はありません"      // ほかのボタンは全部無効
}

メイン() {
    ひょうじ("1 を押す：${販売(1)}")
    ひょうじ("2 を押す：${販売(2)}")
    ひょうじ("9 を押す：${販売(9)}")
}
```

この例の二つの小ワザに注目：

- **「最後の返却」**：最後の `かえす` に `でなければ` が要りません——なぜなら前の `かえす` はどれも関数を即終了させるので、最後の行まで来たということは前の条件が全部不成立だったことを意味します。関数型の書き方の常套手段です；
- **関数は「ブラックボックス」**：メインは「何番を押すと何が出るか」だけを知っていて、販売機の中がどう判断しているかはまったく関知しません——これが抽象です。

## まとめ

- `関数 名前(引数: 型): 戻り値の型 { ... }`：関数を定義；
- 引数は材料（**型を必ず書く**、読み取り専用）、`かえす` で完成品を渡して即終了；
- 呼び出し：`名前(実引数)`；一回書いて、何度も使う；
- 引数も戻り値もない関数：かっこは空、戻り値の型は書かない；
- 関数の四つの利点：重複しない、直しやすい、読みやすい、テストしやすい；
- 思想：**抽象**——「どうやるか」を隠し、「何をするか」を見せる。

## 練習問題

1. `かえす` の後のコードは実行される？`かえす 1` の後に `ひょうじ("まだ続く")` を書いて実行し、出力を見てみよう——そしてコンパイラがなぜ警告するのか考えよう；
2. `ランク分け(85)` と `ランク分け(85.5)` はどちらが正しい？なぜ？（ヒント：引数の型は `せいすう` と書いた）
3. 関数を呼び出すとき、引数のボックスと関数の外の変数は同じ？（7.6 節の問題 3）これは何を守っている？
4. 挑戦：`最大(甲: せいすう, 乙: せいすう): せいすう` 関数を書いて大きい方を返そう。では三つの数ならどう比較する？
