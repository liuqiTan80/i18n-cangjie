# 第 9 章 型システム

> **この章の学習目標**：「データをしまう」ための基礎をすべて身につける——3 種類の束縛（`おく`/`変数`/`定数`）、整数からタプルまでの型体系、型推論と明示的な変換。
> **この章を読み終えると答えられる問い**：なぜ既定が `おく` なのか？なぜ倉頡は暗黙の型変換をしないのか？型注釈はいつ必須なのか？

---

## 9.1 定義：型はデータの分類ラベル

**定義**：型はデータが**何をしまえるか**（範囲）、**どんな演算ができるか**（メソッド）、**どれだけの領域を占めるか**（ビット幅）を決める。倉頡は**強い静的型付け**言語——すべての値はコンパイル時に型が確定し、間違った型を入れると即座にエラーになる。

**基本型の一覧**：

| 方言の型 | 公式の型 | 説明 | 例 |
|---|---|---|---|
| `せいすう` | `Int64` | 64 ビット符号付き整数（既定） | `42` |
| `せいすう32` | `Int32` | 32 ビット整数 | `42`（注釈後） |
| `むごうせいすう` | `UInt64` | 負でない整数 | `7u64` |
| `じっすう` | `Float64` | 64 ビット浮動小数点数（既定） | `3.14` |
| `じっすう32` | `Float32` | 32 ビット浮動小数点数 | `1.75f32` |
| `文字列` | `String` | 不変の Unicode テキスト | `"倉頡"` |
| `しんぎ` | `Bool` | 真/偽 | `真`、`偽` |
| `もじ` | `Rune` | 単一の Unicode 文字 | `'頡'` |
| `ユニット` | `Unit` | 返り値のない型 | `()` |
| `なにもなし` | `Nothing` | 値を持たない型 | `exit(1)` の返り値 |

**注意**：三つの「なし」を混同しない——`なにもなし`（Nothing、**値がない**）、`()`（Unit の唯一の値）、`オプション` 系の「なし」（Option 族の「ない」、第 14 章）。

## 9.2 三つの束縛：おく / 変数 / 定数

**定義**：名前を値に結びつける三つの方法。可変性が増えていく：

| 束縛 | 意味 | 向き |
|---|---|---|
| `おく` | 作った後**変更不可**（既定の選択） | ほとんどすべての宣言 |
| `変数` | 再代入できる（申請して得る特権） | カウント、累積、状態 |
| `定数` | **コンパイル時**に確定、実行時コストゼロ | 円周率など永遠に変わらない値 |

**日本語の書き方**：

```jc
定数 円周率 = 3.14159

メイン() {
    おく 生年 = 2000          // 型は自動で せいすう と推論
    // 生年 = 2001            // ❌ 不変の値には代入できない

    変数 カウント = 0
    カウント += 1              // 複合代入：カウント = カウント + 1
    ひょうじ("カウント = ${カウント}")   // カウント = 1
    ひょうじ("円周率 ≈ ${円周率}")
}
```

**注意事項**：

- `おく` は「変数」ではなく**束縛**——束縛関係は変わらない。ただし束縛した**対象**が参照型（クラス）なら、内部は変化しうる（第 12 章）；
- `定数` の値はコンパイル時に計算できなければならない（リテラルや他の定数式）；
- コンパイラが「不変の値に代入できない」と報告したら → `おく` を `変数` に変える。逆に一度も変更されない変数は `おく` に戻す（lint が教えてくれる）。

## 9.3 整数族とビット幅

**定義**：整数はビット幅で段階分け——`せいすう`（64 ビット既定）、`せいすう32`、`せいすう8`……ビット幅 = 記憶領域と値の範囲。既定 64 ビットは「一番あふれにくい汎用の選択」。

```jc
メイン() {
    おく a: せいすう = 100          // 64 ビット（既定）
    おく b: せいすう32 = 100        // 32 ビット
    おく c: むごうせいすう = 100    // 負でない
    ひょうじ(a + せいすう(b))        // ビット幅が違えば直接足せない：明示的に せいすう へ（9.10 参照）
}
```

**注意事項**：

- `せいすう32`/`じっすう32` と既定ビット幅の型は**混在計算できない**（公式は自動昇格しない。「二項式が無効」と報告される——明示変換が必要）；
- 無符号に `-1` はコンパイルエラー（範囲検査）；
- 接尾辞一覧：整数 `i8/i16/i32/i64/u8/u16/u32/u64`、浮動小数 `f16/f32/f64`；**接尾辞は小文字必須**（`42U8` は構文エラー）。

## 9.4 浮動小数族

**定義**：小数は浮動小数点数——`じっすう`（Float64 既定）、`じっすう32`（Float32）。浮動小数点数は**近似値**（二進法ではすべての小数を正確に表せない）。浮動小数点数の比較に `==` は使わない。

```jc
いれる 数学.*
メイン() {
    おく 身長: じっすう32 = 1.75f32
    おく 体重: じっすう32 = 65.5f32
    ひょうじ(身長 * 体重)        // 同型（じっすう32 × じっすう32）はそのまま計算

    // 浮動小数点数の比較の正しい姿勢：誤差の範囲
    おく a = 0.1 + 0.2
    ひょうじ(ぜったいち(a - 0.3) < 0.0001)   // true（ぜったいち は 数学 モジュール）
}
```

**注意事項**：浮動小数リテラルは既定で `じっすう`（Float64）；接尾辞 `f32`/`f64` でビット幅を強制；`ぜったいち` は `数学` モジュール（`いれる 数学.*`）。

## 9.5 しんぎ（ブール）

**定義**：値は二つだけ——`真`、`偽`。条件は**必ずブール式**（数値を置けない）。

```jc
関数 年齢判定(とし: せいすう): しんぎ { かえす とし >= 18 }

メイン() {
    おく 成人 = 真
    ひょうじ(成人 かつ 年齢判定(18))   // true
    // もし (1) { }                    // ❌ 条件に数値を置けない
}
```

**注意事項**：方言エイリアスは `真`/`偽`；**実行時出力は公式の形式のまま**——`ひょうじ(真)` は `true` と出力される（方言はコードを変換するだけで、実行時出力は翻訳しない）。

## 9.6 文字と文字列

**定義**：`もじ`（Rune）= 単一の Unicode 文字（一重引用符）；`文字列`（String）= 不変の Unicode 文字の並び（二重引用符）。

```jc
いれる 標準コレクション.*
メイン() {
    おく c = '頡'
    ひょうじ(c)                          // 頡
    ひょうじ("倉頡".ながさ)               // 6 —— 【バイト数】！UTF-8 では漢字 1 字 = 3 バイト
    ひょうじ("倉頡プログラミング"[0..3])  // 倉（スライスはバイト単位。漢字 1 字 = 3 バイト）
    // 文字単位で扱う runes() は日本語パック未収録のため公式名を直接使用：
    ひょうじ("倉頡".runes() |> はじめ)   // Some(倉)（はじめ はオプションを返す。値を取り出すには unwrapOrThrow()）
}
```

**注意事項（初心者が必ず踏む二つの落とし穴）**：

- **落とし穴 1**：`文字列[i]` が返すのは**バイト**（UInt8）——日本語だと文字の途中を取ってしまう！`"倉頡"[0]` は「倉」ではない；
- **落とし穴 2**：スライス `s[始..終]` もバイト単位——始点と終点が文字の境界にないと**実行時例外**；
- 文字単位で扱うには `runes()`（惰性イテレータ。公式名。中国語方言の「字符流」に相当。日本語パック未収録のため直接使用）；文字列は `+` で連結（少量）、大量の連結は `もじあつめ`（第 10 章）。

## 9.7 配列とタプル

**定義**：`はいれつ<T>`：長さ固定・連続メモリ・添字 O(1) アクセス。タプル `(T1, T2, ...)`：**異なる型**をひとまとめにする。

```jc
メイン() {
    // 配列：長さ固定
    おく 固定 = [10, 20, 30]
    ひょうじ(固定[1])              // 20
    おく 空配列: はいれつ<せいすう> = []   // 空配列は型注釈が必須

    // タプル：型を混ぜられる
    おく がくせい = (1, "太郎", 真)
    ひょうじ(がくせい[0])            // 1（タプルは [添字] でアクセス）
    おく (番号, 名前, 在籍) = がくせい   // 分解：一度にばらす
    ひょうじ(名前)               // 太郎
}
```

**注意事項**：配列は**長さを変えられない**（動的な増減は `リスト`、第 11 章）；添字が範囲を超えると実行時例外；`(1)` は数であってタプルではない。⚠️ 実測（公式 1.0.5）：**1 要素タプルの末尾カンマ `(1,)` はコンパイルエラー**（式を期待）——1 要素を包みたいなら 1 要素配列 `[1]` を使うこと。タプルは最低 2 要素。

## 9.8 範囲（Range）

**定義**：`始点..終点`（半開区間、終点を含まない）と `始点..=終点`（閉区間、終点を含む）——ループ、スライス、所属判定の共通抽象。

```jc
いれる 標準コレクション.*
メイン() {
    それぞれ (i in 1..5) { ひょうじ(i) }     // 1 2 3 4（半開区間、末尾を含まない）
    それぞれ (i in 1..=5) { ひょうじ(i) }    // 1 2 3 4 5（閉区間）
    ひょうじ((1..10) |> ふくむ(3))           // true（範囲の包含判定。範囲はかっこで包む）
}
```

**注意事項**：範囲は既定で昇順；`5..1` は空の範囲（エラーにならない）；所属判定はパイプ `(1..10) |> ふくむ(3)`。

## 9.9 型推論と注釈

**定義**：ローカル変数は型を書かなくても、コンパイラが初期値から推論する——「書くときは動的言語のよう、調べるときは静的言語のよう」。**推論できるところは書かず、肝心なところは必ず書く**。

```jc
メイン() {
    おく とくてん = 90              // せいすう と推論
    おく なまえ = "太郎"          // 文字列 と推論
    おく 組み = [1, 2, 3]       // はいれつ<せいすう> と推論
    おく とし: せいすう32 = 12      // 32 ビットを強制（注釈必須）
}
```

**注釈が必須の場面**：

- 空の入れ物/空配列（`[]`、`リスト<せいすう>()` は推論できない）；
- 特定のビット幅が必要（`せいすう32`、`じっすう32`）；
- **関数の引数**（推論しない——引数はインターフェース契約の一部）。

**注意**：注釈と推論が衝突したら注釈が優先（`おく x: じっすう = 1` は合法。リテラルが 1.0 に適応する）。

## 9.10 型変換：すべて明示

**定義**：倉頡は**暗黙変換をしない**——変換のたびに明示的に書く。暗黙変換はバグの温床（`"1" + 1` はいったい何？）。明示すれば変換点がすべて見えて、制御でき、レビューできる。

**日本語の書き方**：

```jc
いれる 標準変換.*
メイン() {
    おく とくてん = 95
    ひょうじ(とくてん.もじか())        // "95"（toString）

    おく 割合: じっすう = じっすう(とくてん)   // せいすう → じっすう（コンストラクタ）
    おく 整数値 = せいすう(3.9)        // 3（小数切り捨て。ゼロ方向へ：せいすう(-3.9) → -3）
    ひょうじ(整数値)

    ひょうじ(せいすう.かいせき("12"))  // 12（かいせき は せいすう を返す。入力が不正なら例外——先に判定するほうが安全、第 14 章）
}
```

**変換方法の対照表**：

| 場面 | 書き方 |
|---|---|
| 数値族の相互変換 | コンストラクタ：`せいすう(x)`、`じっすう(x)`、`せいすう32(x)` |
| 数値 → 文字列 | `とくてん.もじか()`（`いれる 標準変換.*` が必要） |
| 文字列 → 数値 | `せいすう.かいせき("42")`（不正入力は例外。先に判定するか捕捉する） |
| 型階層の変換 | `として`——クラス階層専用。**数値には使えない**（第 12 章） |

**注意事項**：`として` と数値コンストラクタは別物——`せいすう(3.9)` は数値変換、`(ペット として 犬)` は型階層の変換（第 12 章）。

## ✳ 設計思想

1. **不変が既定（`おく` 優先）**：可変性 = 予期しない変更 + 並行競合 + 推論の難しさ。「不変」を既定にすれば、`変数` は申請して得る特権になる——`変数` を見渡せばどこが変わりうるか一目瞭然；
2. **強い型付け + 全面推論**：両派の利点を兼ねる——動的言語の書き心地 + 静的言語の安全性。原則：推論できるところは書かず、肝心なところ（引数、境界、契約）は必ず書く；
3. **暗黙変換の撲滅**：暗黙変換は「型」の意味を失わせる（コンパイラも読者も知らないまま、実行時になって初めて分かる）。明示変換は「エラーをコンパイル時に食い止める」哲学の具体化；
4. **値型と参照型の役割分担**（第 12 章で展開）：値型はコピー意味論（予測可能、スレッド安全）、参照型は共有意味論（効率的、多態）。意味論を決めるのは呼び出し側ではなく型の作者；
5. **リテラルの多態**：`42` は型を持たず、文脈に応じて型を取る——だが**変数同士は決して暗黙変換しない**：リテラルは「過去を持たない」値、変数は持っている。

## 練習

1. `おく` と `変数` を 1 つずつ宣言し、`変数` を `おく` に書き換えてから意図的に変更し、日本語の診断を読もう；
2. 型不一致の代入（`おく x: せいすう = "テキスト"`）を書き、教学ヒントと修正例を見よう；
3. `定数` で円周率を宣言して円の面積を計算しよう。接尾辞で `せいすう32`/`むごうせいすう`/`じっすう32` を 1 つずつ書こう；
4. `runes()` で自分の名前を 1 文字ずつ表示しよう。`"こんにちは"[0]` がどんなバイトを出すか試してみよう；
5. タプル + 分解で、学生の（番号、名前、得点）を返して表示しよう。

## まとめ

- 三つの束縛：`おく`（既定、不変）/ `変数`（申請して得る特権）/ `定数`（コンパイル時）；
- 型体系：整数族/浮動小数族/文字列/しんぎ/文字/ユニット/なにもなし。接尾辞は小文字（i64/u64/f32/u8）；
- 文字列は**バイト**で長さ・スライス——文字単位は `runes()`；配列は長さ固定、タプルはまとめ役、範囲は半開；
- 推論で注釈を省けるが、空の入れ物・特定ビット幅・引数は注釈必須；
- 変換はすべて明示：コンストラクタ（数値同士）、`もじか`/`かいせき`（文字列 ↔ 数値）、`として`（クラス階層）。
