# 第 13 章 列挙とパターンマッチ

> **この章の学習目標**：列挙（有限な値の集合 + データを添える）とパターンマッチ（網羅性の検査、分解、ガード）を身につけ、「マッチはもし連鎖より安全」を理解する。
> **この章を読み終えると答えられる問い**：列挙の核心的な価値は何？`場合` を 1 つ書き漏らすとどうなる？`マッチ` と `もし` 連鎖の違いは？

---

## 13.1 定義：列挙とは何か

**定義**：`列挙` = **有限な値の集合**——「ありうる全部のケース」を書き並べる。「マジックナンバー」よりずっと安全：コンパイラの網羅性検査が、すべての値を処理したことを保証してくれる。

**日本語の書き方**：

```jc
列挙 方向 { 上 | 下 | 左 | 右 }

メイン() {
    おく 向き = 方向.上
    マッチ (向き) {
        場合 方向.上 => ひょうじ("上へ")
        場合 方向.下 => ひょうじ("下へ")
        場合 方向.左 => ひょうじ("左へ")
        場合 方向.右 => ひょうじ("右へ")
    }
}
```

**注意事項**：

- 値は `列挙名.メンバ`（`方向.上`）；
- メンバは `|` で区切る；
- 列挙のマッチは**全分岐が強制**される（`_` の受け皿がない限り）——分岐漏れはコンパイルエラー。これが列挙の核心的な価値。

## 13.2 データを添える：タグ付きユニオン

**定義**：列挙のメンバは**データを添える**こともできる——形ごとにそれぞれのデータを持つ。これは「多様な形のデータ」の古典的なモデリング（公式には tagged union と呼ばれる）。

**日本語の書き方**：

```jc
列挙 通知 {
    テキスト(文字列) | 数値(せいすう) | 終了
}

メイン() {
    おく メッセージ = 通知.テキスト("こんにちは")
    マッチ (メッセージ) {
        場合 通知.テキスト(ぶん) => ひょうじ("テキスト：${ぶん}")
        場合 通知.数値(かず) => ひょうじ("数値：${かず}")
        場合 通知.終了 => ひょうじ("終了")
    }
}
```

**注意事項**：データ付きメンバはコンストラクタのように使う（`通知.テキスト("こんにちは")`）。マッチのとき `場合 通知.テキスト(ぶん)` は**判定と分解を同時に**行う——データを取り出している。

## 13.3 マッチ：パターンマッチ + 網羅性検査

**定義**：`マッチ (値) { 場合 パターン => ... }`——`もし` 連鎖より構造的な分岐。`もし` 連鎖は「手動で分岐を管理する」——`でなければ` を 1 つ書き漏らしてもコンパイラは黙っていて、実行時にこっそり道を間違える。**網羅性検査**は「分岐の完全さ」を**コンパイルエラー**にしてくれる。

**日本語の書き方**：

```jc
関数 曜日名(数字: せいすう): 文字列 {
    マッチ (数字) {
        場合 1 => かえす "月"
        場合 2 => かえす "火"
        場合 3 => かえす "水"
        場合 _ => かえす "不明"     // _ ワイルドカード：何にでもマッチ
    }
}

メイン() {
    それぞれ (i in 1..4) {              // 1..4 は半開区間：1, 2, 3
        ひょうじ("曜日${i}：${曜日名(i)}")
    }
}
```

**注意事項**：

- `_` ワイルドカードは任意の値にマッチする——整数に網羅性検査はないので、受け皿が必須；
- `マッチ` は**式**（値を持つ）：`おく 説明 = マッチ (方向) { ... }`；
- 列挙/オプション/タプルのマッチは網羅が必須（または `_` で受け）——「全部のケースを処理したか」をコンパイラが代わりに検査してくれる。

## 13.4 タプルパターン：判定と分解を同時に

**定義**：タプルのマッチは形に沿って分解する——(0, 0) は原点、(x, 0) は x 軸……各パターンが判定と分解を同時に済ませる。

**日本語の書き方**：

```jc
メイン() {
    おく 点 = (3, 4)
    マッチ (点) {
        場合 (0, 0) => ひょうじ("原点")
        場合 (x, 0) => ひょうじ("x 軸上：${x}")
        場合 (0, y) => ひょうじ("y 軸上：${y}")
        場合 (x, y) => ひょうじ("普通の点（${x}，${y}）")
    }
}
```

**注意事項**：パターンの中の `x`、`y` は**新しく束縛される名前**（自動で分解される）。外の変数とは別物。タプルパターンの網羅性はコンパイラが検査する（上の 4 分岐ですべての可能性をカバーしている）。

## 13.5 マッチガード：形 + 条件

**定義**：`場合 パターン そのなか (条件)`——「形のマッチ + 条件のフィルタ」の二段構え。

**日本語の書き方**：

```jc
メイン() {
    おく 点数 = 95
    マッチ (点数) {
        場合 x そのなか (x >= 90) => ひょうじ("優秀")
        場合 x そのなか (x >= 60) => ひょうじ("合格")
        場合 _ => ひょうじ("ガンバレ")
    }
}
```

**注意事項**：ガードの中の `x` はマッチした値（ここでは点数そのもの）。ガードの条件が偽なら次の分岐へ落ちる。整数のマッチには必ず `_` の受け皿が必要。

## 13.6 総合実戦：「もし連鎖」を「マッチ」に書き換える

「点数の評価」で二つの書き方を比べてみる（同じロジック）：

```jc
// 書き方一：もし連鎖（命令的）
関数 評価1(点数: せいすう): 文字列 {
    もし (点数 >= 90) { かえす "優秀" }
    またもし (点数 >= 60) { かえす "合格" }
    かえす "ガンバレ"
}

// 書き方二：マッチガード（宣言的）
関数 評価2(点数: せいすう): 文字列 {
    マッチ (点数) {
        場合 x そのなか (x >= 90) => かえす "優秀"
        場合 x そのなか (x >= 60) => かえす "合格"
        場合 _ => かえす "ガンバレ"
    }
}

メイン() {
    ひょうじ(評価1(95))    // 優秀
    ひょうじ(評価2(95))    // 優秀
}
```

**注意事項**：二つの書き方は等価。`マッチ` の強みは**パターン**（列挙・タプル・分解）の場面——分岐が「大小比較」ではなく「形の区別」になるとき、マッチだけがきれいな答えになる。

## ✳ 設計思想

**① 網羅性検査：「分岐漏れ」をコンパイルエラーにする**。`もし` 連鎖の分岐漏れ = 実行時にこっそり道を間違える。`マッチ` の分岐漏れ = コンパイル時に大声でエラー。列挙にメンバを足すと、マッチしている箇所が全部コンパイルエラーになる——**新しいケースの処理を強制される**（拡張性の安全網）。

**② 型でモデリングし、数字に頼らない**：`方向.上` は数字 `1` より安全——コンパイラが検査でき、コードが自分を語り、型の取り違えは即エラー。「マジックナンバー」はコードの悪臭。列挙がその解毒剤。

**③ 式は値**：`マッチ` は式——「どの分岐も必ず値を持つ」が源流から「初期化忘れ」を絶つ。関数型の流儀が命令型の構造にも浸透する。

**④ まず形をマッチし、それから条件をマッチする**：パターンは「何であるか」を、ガードは「条件にかなうか」を担当する——二段に分かれることで、それぞれの分岐の意図がくっきりする。

## 練習

1. `列挙 天気 { 晴れ | 雨 | 雪 }` を定義し、関数 `持ち物(天気: 天気): 文字列` でアドバイスを返そう（晴れ→日焼け止め、雨→傘、雪→コート）。そして**わざと分岐を 1 つ消して**網羅性エラーを観察しよう；
2. `列挙 形 { 円(じっすう) | 長方形(じっすう, じっすう) }` を定義し、`面積()` 関数でマッチを使ってそれぞれ計算しよう；
3. `マッチ` + ガードで「遊園地のルール」（8〜18 歳 と 身長 130cm 以上）を多分岐バージョンに書き換えよう；
4. 挑戦：タプルパターンで「点が第何象限か」を判定しよう：`(正, 正)` 第 1 象限、`(負, 正)` 第 2……ヒント：`場合 (x, y) そのなか (x > 0 かつ y > 0)`。

## まとめ

- `列挙 名 { メンバ1 | メンバ2 }`。値は `列挙名.メンバ`。メンバは**データを添えられる**；
- `マッチ (値) { 場合 パターン => ... }`：パターンマッチ + 網羅性検査（列挙/オプション/タプルは全分岐か `_` の受け皿が必須）；
- タプルパターン `場合 (x, 0) =>`：判定と分解を同時に。ガード `場合 x そのなか (条件)`：形 + 条件；
- `_` ワイルドカードで受け；`マッチ` は式（値を持つ）；
- 核心的な価値：分岐漏れが「実行時バグ」ではなく「コンパイル時エラー」になる。
