# 第 5 章 コンピューターは考える：判断

> **この章の目標**
> - `もし`/`またもし`/`でなければ` でプログラムに「分かれ道」を歩かせる；
> - 比較演算子（`==`、`>`、`>=`……）とブール値（`真`/`偽`）を知る；
> - 複数の条件を組み合わせる（`かつ`、`または`、`でない`）。
>
> **この章を読み終えると答えられる**：判断は上から下へどう実行される？`=` と `==` はどう違う？条件の中に数字を入れられる？

---

## 5.1 もし……なら……

コンピューターの最も得意なことの一つが、**判断**です。構文は話し言葉のまま：

```jc
メイン() {
    おく 点数 = 85
    もし (点数 >= 60) {
        ひょうじ("合格！")
    }
}
```

- `もし (条件)`：**条件が成り立てば**、波かっこの中のコードを実行します；
- `>=` は「以上」。比較演算子には：`==`（等しい）、`!=`（等しくない）、`>`（大きい）、`<`（小さい）、`>=`（以上）、`<=`（以下）があります。

> 覚えておいて：等しいかどうかの判定は**等号 2 つ**の `==`。等号 1 つの `=` は「ボックスに入れる」（代入）。2 つで初めて「比べる」（比較）です。これは初心者に一番多い間違いの一つ——幸い倉頡が直接エラーで止めてくれます。

## 5.2 またもし、でなければ：多分岐の判断

```jc
メイン() {
    おく 点数 = 85
    もし (点数 >= 90) {
        ひょうじ("優秀！")
    } またもし (点数 >= 60) {
        ひょうじ("合格")
    } でなければ {
        ひょうじ("がんばれ、くじけないで")
    }
}
```

まるでクイズの流れ：最初の条件が成り立たなければ次の条件を試し、どれも成り立たなければ `でなければ` へ。**上から下へ、一本の道だけを通る**——最初に「成立」した条件のところだけ実行され、後はもう見ません。

## 5.3 真と偽

判断の結果は二つだけ：`真`（成立）と `偽`（不成立）。これが第 4 章で見た `しんぎ`（ブール）型です：

```jc
メイン() {
    おく 雨が降る = 真
    もし (雨が降る) {
        ひょうじ("傘を持って！")
    }
}
```

`真` と `偽` はそのまま変数にしまえますし、比較から生まれることもあります：`85 >= 60` という「式」の結果は `真`。そう、`もし (点数 >= 60)` はつまり「この比較の結果は `真` か `偽` か」を尋ねているのです。

> 注意：条件の中に**数字は入れられません**。`もし (1)` は間違い——条件は必ず本物の「真/偽の判断」でなければなりません。これで「代入」を「比較」と書き間違える古典的バグが防げます（`もし (x = 1)` になったらどうなるか考えてみてください）。

## 5.4 条件の組み合わせ：かつ、または、でない

一つの条件では足りないときは、論理語で組み合わせます：

```jc
メイン() {
    おく 年齢 = 15
    おく チケットあり = 真
    もし (年齢 >= 12 かつ チケットあり) { ひょうじ("入場できます") }
    もし (年齢 < 6 または 年齢 > 80) { ひょうじ("無料") }
    もし (でない チケットあり) { ひょうじ("チケットを買ってください") }
}
```

| ことば | 意味 | 例 |
|---|---|---|
| `かつ` | 両方成り立って初めて成立（AND） | `雨が降る かつ 傘がある` |
| `または` | どちらか一つで成立（OR） | `雨が降る または 雪が降る` |
| `でない` | ひっくり返す（NOT） | `でない 雨が降る` = 降っていない |

> **小ひみつ（ショートサーキット）**：`偽 かつ 何でも` は即 `偽`——右側の条件はコンピューターが見向きもしません；`真 または 何でも` は即 `真`。これが安全な書き方を保証します：`リスト.ながさ > 0 かつ リスト[0] > 1`——最初の条件が成り立たなければ、右の範囲外アクセスは実行されません（第 11 章で使います）。

## 5.5 やってみよう

1. プログラムを書こう：あなたの身長（たとえば 155）。150 を超えていたら「ジェットコースターに乗れます」、そうでなければ「もうちょっと伸びよう」；
2. 点数をランク分け：`>=90` 優秀、`>=80` 良好、`>=60` 合格、それ以外はがんばれ——`またもし` を使います；
3. 考えよう：`もし (5 > 3)` と `もし (3 > 5)`、どちらが中身を実行する？
4. 挑戦：「遊園地のルール」を作ろう——年齢が 8 歳以上 18 歳以下 `かつ` 身長 130 を超えているときだけ乗れる。それ以外は理由を表示（ヒント：`年齢 >= 8 かつ 年齢 <= 18`）。

## ✳ プログラミング思想の小話：判断 = 分かれ道

`もし` はプログラムが初めて「考える」場所——プログラムはもう一直線ではなく、**分かれ道を歩く**ようになります。

背後にある思想は：**プログラム = 順次 + 分岐 + 繰り返し**。あなたがこれまで書いたすべてのプログラムは、この三つで組み立てられています：

- **順次**（第 2 章）：一歩ずつ進む；
- **分岐**（本章）：状況を見て道を選ぶ；
- **繰り返し**（第 6 章）：ぐるぐる回る。

**どんな複雑なプログラムも、突き詰めればこの三つの構造です。** これはコンピューター科学の有名な「構造化プログラミング」の考え方——レゴが数種類の基本ブロックだけで何でも組み立てられるのと同じ。複雑なプログラムを見ても慌てないで：その「順次・分岐・繰り返し」がどこにあるかを探しましょう。

## 🍳 日常アルゴリズム小話：成績ランク分けマシン

先生がクラス全員の成績をランク分けする——これこそ典型的な多分岐の判断です：

```jc
メイン() {
    おく 点数 = 85
    もし (点数 >= 90) {
        ひょうじ("優秀")
    } またもし (点数 >= 80) {
        ひょうじ("良好")
    } またもし (点数 >= 60) {
        ひょうじ("合格")
    } でなければ {
        ひょうじ("がんばれ")
    }
}
```

注意したいのは判断の**順番**：高い方から並べます（90 → 80 → 60）。もし先に `もし (点数 >= 60)` と書いたら、85 点は永遠に「良好」に届きません——60 の条件が先に成立して、そのまま帰ってしまうからです。**分岐の順序がそのまま優先順位**——これが多分岐で一番踏みやすい落とし穴です。

> 考えてみよう：点数を 95、70、40 に変えてそれぞれ実行すると、何が出力される？

## まとめ

- `もし (条件) { ... }`：条件が成り立つときだけ実行；
- `またもし`、`でなければ`：多分岐——**上から下へ、最初に成立した道だけを通る**；
- 比較演算子：`== != > < >= <=`；等しいかは `==`、代入は `=`；
- ブール：`真`/`偽`；条件は必ずブール判断、数字は入れられない；
- 組み合わせ：`かつ`（両方成立）、`または`（どちらか成立）、`でない`（反転）；
- 分岐の順序 = 優先順位：ランク分けは高い方から書く。

## 練習問題

1. 5.2 のランク分けで、先に `点数 >= 60` を書いたら、85 点は何と出力される？なぜ？
2. `もし (点数 = 85)` はエラーになる？試してみよう——これはあなたを何から守っている？
3. `かつ` を使って判断を書こう：明日「雨が降る かつ 気温が 10 度未満」なら、傘と上着を忘れずに、と表示する；
4. 予想しよう：`でない (年齢 < 18)` と `年齢 >= 18` は同じこと？なぜ？
