# 第 4 章 数と文字

> **この章の目標**
> - 4 つの基本「材料」を知る：整数、浮動小数点数、文字列、ブール値；
> - コンピューターで足す・引く・掛ける・割る；
> - 補間 `${}` で文字と数を一つの文に縫い合わせる。
>
> **この章を読み終えると答えられる**：`12` と `"12"` はどう違う？なぜ `7 / 2` は `3` になる？コンピューターはどうやって「たろうは 95 点だった」を一文に組み立てるの？

---

## 4.1 ボックスには何を入れられる？

ここまで数字と文字を入れましたが、実は基本の「材料」は 4 種類です：

| 材料 | 名前 | 例 |
|---|---|---|
| 整数（小数点なし） | `せいすう` | `12`、`-3`、`0` |
| 小数（浮動小数点数） | `じっすう` | `3.14`、`-0.5` |
| 文字（文字列） | `文字列` | `"こんにちは"`、`"abc"` |
| 真/偽（ブール値） | `しんぎ` | `真`、`偽` |

コンピューターはきっちり区別します：`12` は数、`"12"` は文字——信じなければ足し算してみてください、エラーになります！「りんご 12 個 + 文字 12」には意味がないからです。これが**型**：材料ごとにルールが違い、間違った材料を入れるとコンピューターが即座に止めます（本章の最後に実験があります）。

## 4.2 コンピューターは計算機

```jc
メイン() {
    おく りんごの値段 = 3
    おく なしの値段 = 4
    おく 合計 = りんごの値段 + なしの値段
    ひょうじ("全部で${合計}円")
    ひょうじ("りんご 3 個で${りんごの値段 * 3}円")
    ひょうじ("なしの方が${なしの値段 - りんごの値段}円高い")
}
```

演算記号：`+` 足す、`-` 引く、`*` 掛ける、`/` 割る。

数学と同じく**掛け算・割り算が先**で、足し算・引き算は後。先に計算したいところはかっこで囲みます：`(りんごの値段 + なしの値段) * 2`。

## 4.3 整数どうしの割り算の落とし穴

```jc
メイン() {
    ひょうじ(7 / 2)          // 出力は 3。3.5 ではない！
    ひょうじ(7.0 / 2.0)      // 出力は 3.5
    ひょうじ(7 % 2)          // 出力は 1（% は余り）
}
```

**整数を整数で割ると、結果も整数**（余りは切り捨て）。`7 / 2` は `3` であって `3.5` ではありません！`3.5` が欲しければ小数を使います：`7.0 / 2`。

`%` は**余り**を求めます：`7 % 2` は 1。ある数が奇数か偶数かの判定や、数の下一桁を取り出すのは、全部これを使います——第 5 章で登場します。

## 4.4 文字をつなぐ：補間

文字と数を組み合わせたいときは、`${}` の穴埋めが一番簡単です：

```jc
メイン() {
    おく 名前 = "たろう"
    おく 点数 = 95
    ひょうじ("${名前}は${点数}点でした")
}
```

出力：`たろうは95点でした`。`${}` の中には変数だけでなく、計算式まで入れられます：

```jc
メイン() {
    おく りんご = 3
    おく なし = 4
    ひょうじ("全部で${りんご + なし}個の果物")   // 全部で7個の果物
}
```

> 改行して出力したい？`\n` を使います：`ひょうじ("一行目\n二行目")` は 2 行で出力されます。`\n` は「改行文字」と読みます。

## 4.5 やってみよう

1. 計算しよう：毎日 2 円おこづかいが増えたら、1 年（365 日）でいくら増える？プログラムで計算しましょう；
2. 一文を出力しよう：「私の身長は」+ あなたの身長（補間 `${}` を使う）；
3. `ひょうじ(1 + "2")` を試して、型エラーの表示を読んでみましょう——💡 の解説が「型の不一致」をどう説明しているか注目；
4. 挑戦：第 3 章の「おこづかい帳」をレベルアップ——金額を小数で持ち（たとえば 100.5 円）、25.3 円の物を買ったら残りいくら？（出力の小数桁を観察しよう）

## ✳ プログラミング思想の小話：型は「分類ラベル」

なぜコンピューターはこんなに融通が利かず、`12` と `"12"` を区別するのでしょう？

**型の違う値はできることが違う**からです：数は足し引きでき、文字はつなげて検索でき、真/偽は判断に使えます（第 5 章）。もしコンピューターが「数 + 文字」を許したら、`1 + "2"` は `3` なのか `"12"` なのか——プログラマー各自が自分の答えを考え始め、プログラムは混乱します。

だからプログラミング言語は**型**でそれぞれの値にラベルを貼ります：**型が「この値にどんな演算ができるか」を決める**。これは台所の道具の分類と同じ：包丁は切るもの、鍋は炒めるもの。包丁で炒めようとはしませんよね。

> これは倉頡の設計哲学の一つでもあります：**暗黙の型変換をしない**——コンピューターに「おせっかい」で数字を文字に変えさせません。すべての変換はプログラマーが明示的に書きます（第 9 章で変換方法を学びます）。融通が利かないのは、間違いを出さないためです。

## 🍳 日常アルゴリズム小話：おつりを数える

お店で買い物：品物は 7 円、あなたは 20 円出しました。お店の人はどうやっておつりを計算するでしょう？

```jc
メイン() {
    おく 払ったお金 = 20
    おく 値段 = 7
    おく おつり = 払ったお金 - 値段
    ひょうじ("おつりは${おつり}円")

    // レベルアップ：1 円・5 円・10 円玉しかなかったら、どう組み合わせる？
    おく 十円 = おつり / 10          // 20 - 7 = 13、13 / 10 = 1 枚
    おく 残り = おつり % 10          // 余りは 3 円
    おく 五円 = 残り / 5           // 3 / 5 = 0 枚
    おく 一円 = 残り % 5           // 余りは 3 円
    ひょうじ("10円玉${十円}枚、5円玉${五円}枚、1円玉${一円}枚")
}
```

この例には二つのアルゴリズムの考え方が隠れています：
- **`/` と `%` は生まれつきのコンビ**：`割り算` で「何枚に換えられるか」、`余り` で「いくら残るか」——組み合わせると「おつりの組み合わせ」アルゴリズムになります；
- この「先に割ってから余りを取る」手筋は**貪欲アルゴリズム**の原型：毎回一番大きな額面から使います（第 17 章で深く学びます）。

## まとめ

- 4 つの基本材料：`せいすう`、`じっすう`、`文字列`、`しんぎ`（`真`/`偽`）；
- 演算：`+ - * / %`；掛け算・割り算が先、かっこ優先；
- **整数 ÷ 整数 = 整数**（`7 / 2` = 3）；小数が欲しければ `7.0 / 2`；
- `%` は余り：偶奇判定もおつり計算もこれで；
- 補間 `${}`：変数や計算式を文字列に埋め込む、`"${名前}は${点数}点でした"`；
- 型は分類ラベル：`12` と `"12"` は別物。コンピューターは「暗黙の変換」をしない。

## 練習問題

2. なぜ `1 + "2"` はエラーになる？もし許されたら世界はどうなる？（ヒント：`"1" + "2"` が `"12"` なら、`1 + "2"` は何になるべき？）
3. `${}` の中に `ひょうじ("...")` を入れられる？なぜ？（ヒント：補間が欲しいのは「値」。ひょうじ は「動作」）
