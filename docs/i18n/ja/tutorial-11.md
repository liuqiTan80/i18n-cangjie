# 第 11 章 集合とコンテナ

> **この章の学習目標**：三つのコンテナを使いこなす——リスト（動的リスト）、マップ（キーと値）、ハッシュ集合（重複なし）。`うつす`/`こす`/`たたむ`/`ならべる` で宣言的なデータ処理を学ぶ。
> **この章を読み終えると答えられる問い**：リストとマップはいつ使い分ける？存在しないキーを取ると何が起きる？`うつす` はなぜすぐ結果を出さないのか？

---

## 導入の物語：1 つの箱に収まらないときは？

クラスの 45 人のテストの点数、変数を 45 個書くわけにはいかない。**リスト**（動的リスト）は長い並びを入れる「ランドセル」：

```jc
いれる 標準コレクション.{リスト}

メイン() {
    変数 点数表 = リスト<せいすう>()
    点数表.くわえる(95)
    点数表.くわえる(88)
    点数表.くわえる(76)
    ひょうじ("全部で${点数表.ながさ}個の点数")
    ひょうじ("最初の点数：${点数表[0]}")
}
```

- `リスト<せいすう>()`：整数専用の空のランドセル；
- `点数表.くわえる(95)`：ランドセルに 1 つ入れる；
- `点数表.ながさ`：いくつ入っているか数える（**プロパティ**を直接読む。かっこを付けない）；
- `点数表[0]`：1 番目を取る（**番号は 0 から**——0 が最初、1 が 2 番目。プログラミングの世界の決まり）。

でも「何番目か」で探すのが不便なこともある：「ポチ」と入力したら年齢がすぐ知りたい——名前で探すほうが自然だ。**マップ**（辞書）は点名簿——1 マスに**キー**（名前）、1 マスに**値**（情報）：

```jc
いれる 標準コレクション.{マップ}

メイン() {
    変数 ペット年齢 = マップ<文字列, せいすう>()
    ペット年齢["ポチ"] = 3
    ペット年齢["タマ"] = 5
    おく ポチとし = ペット年齢["ポチ"]
    ひょうじ("ポチ${ポチとし}歳")
    ひょうじ("うちに${ペット年齢.ながさ}匹")
}
```

> たとえ話：リストは**列に並ぶ**（0 番目、1 番目……順番に探す）。マップは**点名簿**（名前で探す。並ばなくてよい）。

この二つの直感がこの章の核心：「何で探したいか」を先に考えてからコンテナを選ぶ。存在しないキーを取るとどうなるかは、11.3 で答える。

## 11.1 定義：三つのコンテナがそれぞれ 1 つの問いに答える

**定義**：コンテナ = 長いデータを入れる「ランドセル」。「何を探すか、何で探すか」を先に考える——これは API を覚えるよりずっと大事：

| コンテナ | 公式 | 答える問い | 代償 |
|---|---|---|---|
| `はいれつ`/`リスト` | Array/ArrayList | 「順番に何をしまうか」 | 探索は走査 O(n) |
| `マップ` | HashMap | 「このキーには何が対応するか」 | 無順序、キーはハッシュ可能が条件 |
| `ハッシュ集合` | HashSet | 「この値はあるかないか」 | 無順序、重複できない |

- **はいれつ**（第 9 章）：長さ固定、増減不可；
- **リスト**：動的に増減できるリスト——要素がいくつになるか分からないときに使う（**動的リストの既定の選択**）；
- **マップ**：`キー → 値` の対応表。名前でデータを引き、平均 O(1) で検索；
- **ハッシュ集合**：「あるかないか」だけに関心がある。要素は重複せず、`ふくむ` 判定は O(1)。

## 11.2 リスト（リスト / ArrayList）：動的リスト

**日本語の書き方**：

```jc
いれる 標準コレクション.{リスト}
メイン() {
    変数 点数表 = リスト<せいすう>()
    点数表.くわえる(95)               // 末尾に追加 = add
    点数表.くわえる(88)
    点数表.くわえる(76)
    ひょうじ(点数表.ながさ)           // 3（ながさ はプロパティ。かっこを付けない）
    ひょうじ(点数表[0])             // 95（添字アクセス）
    点数表.のぞく(1..2)             // のぞく は範囲だけ受け付ける：添字 1（88）を削除
    ひょうじ(点数表.ながさ)           // 2
    それぞれ (てん in 点数表) {
        ひょうじ("点数：${てん}")   // 走査
    }
}
```

**注意事項（間違いやすい）**：

- `ながさ` は**プロパティ**であってメソッドではない（`.ながさ`。かっこを付けない。`.ながさ` は文字列/配列でもプロパティ）；
- 添字が範囲を超えると**実行時例外**（例：`点数表[9]`）——先に `ながさ` を見てから取る；
- **リストの `のぞく` は範囲だけ受け付ける**（公式 `remove(Range)`）：`のぞく(1..2)` は 1 個削除、`のぞく(1..3)` は 2 個削除。「値」で消す既成メソッドはないので、添字を探してから消す；
- 配列 ↔ リストの相互変換：`リスト.from(はいれつ)`；
- 公式に**`反転`（reversed）メソッドはない**。逆順にしたいなら添字を逆に回す：

```jc
いれる 標準コレクション.{リスト}
メイン() {
    おく 元 = [1, 2, 3]
    変数 逆順 = リスト<せいすう>()
    それぞれ (i in 0..元.ながさ) {
        逆順.くわえる(元[元.ながさ - 1 - i])   // 最後から前に向かって取る
    }
    ひょうじ(逆順[0])                      // 3（元のコンテナは変わらない）
}
```

## 11.3 マップ（マップ / HashMap）：キーと値のペア

**日本語の書き方**：

```jc
いれる 標準コレクション.{マップ}
メイン() {
    変数 ペット年齢 = マップ<文字列, せいすう>()
    ペット年齢["ポチ"] = 3               // しまう：マップ[キー] = 値
    ペット年齢["タマ"] = 5
    ひょうじ(ペット年齢["ポチ"])           // 3（取る：マップ[キー]）
    ひょうじ(ペット年齢.ながさ)              // 2
    それぞれ (なまえ in ペット年齢.キー()) {      // キー() で全部のキーを取る。辞書走査の定番
        ひょうじ("${なまえ}${ペット年齢[なまえ]}歳")
    }
}
```

**注意事項（間違いやすい）**：

- **存在しないキーを取ると実行時例外**（`ペット年齢["いない"]` でクラッシュ）——取る前に `ふくむ` で判定するか、`なければきてい` で保険をかける；
- キーはハッシュ可能でなければならない：文字列・整数は自然に可能。独自型は `ハッシュ` を実装する（第 12 章）；
- **走査の順序は保証されない**（ハッシュは無順序）：同じマップを 2 回走査しても順序が違うことがある。順序に依存しないこと；
- 値の変更は `マップ[キー] = 新しい値`；削除は `マップ.のぞく(キー)`（キーで消す。リストの範囲削除とは違う）；
- `キー()` はメソッド（かっこ付き）。返るのは**ビュー**——走査中にマップを増減しないこと。

**総合実戦：グループ集計**（公式に groupBy はない。マップで手書きする——「グループ名 → カウント」が標準の型）：

```jc
いれる 標準コレクション.{リスト, マップ}
メイン() {
    変数 てん = リスト<せいすう>()
    てん.くわえる(95); てん.くわえる(45); てん.くわえる(70)
    変数 グループ = マップ<文字列, せいすう>()
    それぞれ (とくてん in てん) {
        おく 組名 = もし (とくてん >= 60) { "合格" } でなければ { "不合格" }
        グループ[組名] = グループ.取得(組名).なければきてい({ => 0 }) + 1
    }
    ひょうじ(グループ.ながさ)       // 2
    ひょうじ(グループ["合格"])    // 2
}
```

> `取得(キー)`（= 公式 `get`）は `オプション` を返し、`.なければきてい({ => 0 })`（= `getOrDefault`）はキーが無いときに 0 から始める——これが「カウント」の定番の書き方（`オプション` の詳解は第 14 章）。

## 11.4 ハッシュ集合（ハッシュ集合 / HashSet）：重複しない集合

**日本語の書き方**：

```jc
いれる 標準コレクション.{ハッシュ集合}
メイン() {
    変数 既読 = ハッシュ集合<せいすう>()
    既読.くわえる(1)
    既読.くわえる(1)            // 重複は無視される
    既読.くわえる(2)
    ひょうじ(既読.ながさ)       // 2
    ひょうじ(既読.ふくむ(2))    // true
}
```

**代表的な使い方：重複除去**（公式に distinct メソッドはない。ハッシュ集合が自然に重複を消す）：

```jc
いれる 標準コレクション.{リスト, ハッシュ集合}
メイン() {
    変数 めいぼ = リスト<せいすう>()
    めいぼ.くわえる(1); めいぼ.くわえる(2); めいぼ.くわえる(1)
    変数 ユニーク = ハッシュ集合<せいすう>()
    それぞれ (かず in めいぼ) { ユニーク.くわえる(かず) }   // 重複の 1 は無視
    ひょうじ(ユニーク.ながさ)       // 2
}
```

**注意事項**：ハッシュ集合は**無順序**（元の順序は保証されない）。「順序を保って重複除去」したいなら手書きループ + `ふくむ` 判定（`もし (!結果.ふくむ(かず)) { 結果.くわえる(かず) }`）。

## 11.5 高階関数：うつす / こす / あるく

**定義**：頻出の「宣言的」操作 3 つ。方言ではパイプ `コンテナ |> 関数` で書く：

| 操作 | 働き | 返り値 |
|---|---|---|
| `うつす({ x => ... })` | 全要素を変換 | 惰性イテレータ |
| `こす({ x => ... })` | 条件を満たす要素だけ残す | 惰性イテレータ |
| `あるく({ x => ... })` | 各要素に動作を実行（表示など） | ユニット |

```jc
いれる 標準コレクション.*
メイン() {
    変数 めいぼ = リスト<せいすう>()
    めいぼ.くわえる(1); めいぼ.くわえる(2); めいぼ.くわえる(3)
    // うつす：各要素 ×2
    おく 倍加 = めいぼ |> うつす({ x => x * 2 }) |> はいれつあつめ
    ひょうじ(倍加[0])                // 2
    // こす：60 以上だけ残す
    変数 てん = リスト<せいすう>()
    てん.くわえる(95); てん.くわえる(45); てん.くわえる(70)
    おく 合格 = てん |> こす({ x => x >= 60 }) |> はいれつあつめ
    ひょうじ(合格.ながさ)              // 2
    // あるく：動作だけして結果を返さない
    変数 めいぼ2 = リスト<文字列>()
    めいぼ2.くわえる("あ"); めいぼ2.くわえる("い")
    めいぼ2 |> あるく({ なまえ => ひょうじ("こんにちは、${なまえ}") })
}
```

**三つの真実**：

- **惰性**：`うつす`/`こす` は**イテレータ**を返す。この時点ではまだ計算しない——`|> はいれつあつめ` で消費して初めて 1 つずつ計算する（省メモリ。無限チェーンも可能）；
- **元のコンテナは変わらない**：新しい列を生むのであって、元のリストを変更しない；
- `あるく` はユニットを返す。`それぞれ` ループと等価（純粋に好みの問題）。ラムダの中では**`ぬける`/`つづける` が使えない**（ラムダはループではない）——途中で終えたいなら `それぞれ` を使う。

## 11.6 たたむ / つみあげ / ならべる

**定義**：`たたむ`（fold）：初期値から始めて 1 つずつ累積する。`つみあげ`（reduce）：初期値なし、最初の要素から始める（空のコンテナなら `オプション` を返す）。`ならべる`（sort）：**その場で並べ替え**（元の配列を直接変更）。

**日本語の書き方**：

```jc
いれる 標準コレクション.*
いれる 標準ソート.*
メイン() {
    // たたむ：初期値 0 が返り値の型を決める
    変数 てん = リスト<せいすう>()
    てん.くわえる(95); てん.くわえる(85)
    おく 合計 = てん |> たたむ(0, { 累積, とくてん => 累積 + とくてん })
    ひょうじ(合計)                   // 180

    // つみあげ：初期値なし。オプションを返す（空のコンテナ → なし）
    おく 合計2 = てん |> つみあげ({ 累積, とくてん => 累積 + とくてん })
    ひょうじ(合計2.なければれいがい())     // 180

    // ならべる：配列をその場で変更するトップレベル関数
    変数 点数 = [88, 95, 70]
    ならべる(点数)                       // その場で昇順
    ひょうじ(点数[0])                  // 70
    ならべる(点数, くだり: 真)             // その場で降順（くだり は名前付き引数）
    ひょうじ(点数[0])                  // 95
}
```

**注意事項**：

- `ならべる` は**はいれつ**を受け取る。要素は比較可能であること。リストは先に `はいれつあつめ`（または `リスト.from(はいれつ)` で逆変換）してから並べる；
- 公式の旧 API `安定ソート` は非推奨——`ならべる(データ, 安定: 真)` で「等しい要素は元の順序を保つ」と表現する；
- 元データを変えたくない？並べる前にコピーを 1 枚取る。

## ✳ 設計思想

**① コンテナ選択は「データ構造」の決定**：「何を探すか、何で探すか」を先に考えてから選ぶ——順番 → リスト。名前 → マップ。「あるかないか」だけ → ハッシュ集合。

**② 可変性の規律：その場 vs 新しいコンテナ**：`ならべる` はその場で変更（新しい値を生まない）、`うつす`/`こす` は新しい列を生む（元のコンテナに触らない）。関数型スタイルは後者を好む——元データは「入力」であって、こっそり書き換えられない。デバッグのときの心の負担が小さい。

**③ 宣言的 > 命令的**：`てん |> こす({ x => x >= 60 }) |> はいれつあつめ` は読めばそのまま「不合格をふるい落として、配列に集める」——意図を直接言っている。手書きループは読者自身が意図を「翻訳」しなければならない。宣言的コードは「何をするか」と「どうやるか」を分ける。

**④ 惰性評価：使った分だけ計算**：イテレータはいっきに計算しない。チェーンを組んでも、各要素はパイプラインを 1 回だけ通る——これが「うつす が結果を出さない理由」の答え：まだ消費されていないのだ。

## 練習

1. `マップ` で「単語 → 意味」の小さな辞書を作り（3 語以上）、`キー()` で走査して全項目を表示しよう；
2. `リスト` に 1..100 の偶数を集め、`たたむ` で総和を出そう（ヒント：`こす({ x => x % 2 == 0 })`）；
3. `リスト` に 3 人のテストの点数を入れ、`ならべる` して高い順に表示しよう（ヒント：`くだり: 真`）；
4. 考えよう：なぜ `うつす` の結果は `はいれつあつめ` しないと繰り返し使えないのか？イテレータをそのまま表示すると何が見える？
5. 挑戦：11.3 のグループ集計を「点数帯（優/良/合格/不合格）」の 4 グループに改造しよう。

## まとめ

- 三つのコンテナ：リスト（動的リスト。`のぞく` は範囲だけ）、マップ（キーと値。存在しないキーを取ると**例外**）、ハッシュ集合（重複なし）；
- 高階関数パイプ：`コンテナ |> うつす/こす/あるく/たたむ/つみあげ |> はいれつあつめ`——惰性、元のコンテナは不変；
- `ならべる` はトップレベル関数（`いれる 標準ソート.*`）。その場で変更。`くだり`/`安定` は名前付き引数；
- 実行時出力は公式形式のまま（`真` → `true`）。
