# 第 8 章 関数を極める

> **この章の学習目標**：関数を使い尽くす——返り値の詳細、複数返り値、名前付き引数、オーバーロード、ラムダとクロージャ。
> **この章を読み終えると答えられる問い**：なぜ引数に型注釈が必須なのか？ラムダと普通の関数はどういう関係？「クロージャ」は何を捕まえるのか？

---

## 8.1 定義：関数の完全な構文

**定義**：再利用でき、名前を持ち、呼び出せるコードのまとまり。完全な形：

```
関数 名前(引数1: 型, 引数2: 型): 戻り型 {
    関数本体
    ...
    かえす 結果
}
```

**日本語の構文ポイント**：

| 部分 | 書き方 | 説明 |
|---|---|---|
| キーワード | `関数` | 関数を宣言する予約語 |
| 入口 | `メイン()` | **「関数」の接頭辞を付けない**——`関数 メイン` は構文エラー（入口はそもそも `メイン` という名前であって、「関数」として再宣言する必要はない） |
| 引数 | `(てんすう: せいすう)` | **型注釈が必須**（推論しない）——引数はインターフェースの契約 |
| 戻り型 | `: 文字列` | 返り値がなければ省略可（暗黙に `ユニット` を返す） |
| 返り値 | `かえす 値` | 結果を渡して**その場で関数を終了**する |

**例**：

```jc
関数 二倍(かず: せいすう): せいすう {
    かえす かず * 2
}

関数 面積(はば: じっすう, たかさ: じっすう): じっすう {
    かえす はば * たかさ
}

メイン() {
    ひょうじ(二倍(21))          // 42
    ひょうじ(面積(3.0, 4.0))    // 12.0
}
```

**注意事項**：

- 引数は**読み取り専用の束縛**——引数への再代入はできない；
- `: 文字列` を宣言したら**すべての経路で返す**こと——漏れるとコンパイラが「関数に戻りがない」と報告；
- 関数名は「動詞 + 目的語」のスタイル（`合計を計算`、`ファイルを読み込む`）。

## 8.2 返り値と早期リターン

**定義**：`かえす 値` は結果を渡してすぐ関数を終了する。関数本体の**最後の式の値**も自動的に返り値になる（末尾式）——ただし分かりやすさのため明示的な `かえす` を推奨。

```jc
関数 絶対値(かず: せいすう): せいすう {
    もし (かず < 0) {
        かえす -かず        // 早期リターン：負なら反転して終了
    }
    かえす かず             // ここまで来たら かず >= 0
}

メイン() {
    ひょうじ(絶対値(-5))   // 5
    ひょうじ(絶対値(3))    // 3
}
```

**注意事項**：

- `かえす` の後に文を置けない（到達不能コード警告）；
- **最後の `かえす` は保険**：先の `かえす` が即終了するので、最後の 1 行は `でなければ` で包まなくてよい；
- 返り値のない関数は `かえす` を省略できる。

## 8.3 複数返り値：タプル + 分解

**定義**：関数が返せるのは 1 つの値だけ——ただし**タプル**なら複数の値をまとめられる。呼び出し側は**分解**で一度にばらす。

```jc
関数 極値(めいぼ: はいれつ<せいすう>): (せいすう, せいすう) {
    かえす (めいぼ[0], めいぼ[めいぼ.ながさ - 1])
}

メイン() {
    おく (しょう, だい) = 極値([3, 7, 2, 9])
    ひょうじ("最小${しょう} 最大${だい}")   // 最小3 最大9
}
```

**注意事項**：

- タプルは `[添字]` でアクセス（`がくせい[0]`）、分解は `おく (a, b) = タプル`；
- `(1)` は普通の数であってタプルではない——1 要素タプルは `(1,)` と書く；
- 12 要素を超えるなら構造体/クラスを検討しよう（第 12 章）。

## 8.4 名前付き引数：順番を間違えない

**定義**：引数が多いとき、位置で渡すと順番を間違えやすい。宣言時に引数名の後ろへ `!` を付け、呼び出しは `名前: 値` で渡す。

**日本語の書き方**：

```jc
関数 登録(とし: せいすう, なまえ!: 文字列, がっきゅう!: 文字列) {
    ひょうじ("${なまえ} ${とし}歳 ${がっきゅう}")
}

メイン() {
    登録(12, なまえ: "太郎", がっきゅう: "1年2組")
}
```

**注意事項**：

- **名前なし引数は前に**（`登録(12, ...)`）、名前付き引数は後ろに書く；
- 引数名を書き間違えると「引数が見つからない」；
- 名前付き引数はインターフェースの**自己文書化**——呼び出し箇所に「この名前とこの値」がそのまま見える。

## 8.5 オーバーロード：1 つの名前、複数の意味

**定義**：同名で**引数が異なる**（個数または型）関数を複数宣言でき、コンパイラが実引数から版を選ぶ。

```jc
関数 説明(x: せいすう): 文字列 { かえす "整数：${x}" }
関数 説明(x: 文字列): 文字列 { かえす "テキスト：${x}" }

メイン() {
    ひょうじ(説明(1))        // 整数：1
    ひょうじ(説明("やあ"))   // テキスト：やあ
}
```

**注意事項**：

- **戻り型だけ違うのはオーバーロード不可**（衝突する）；
- 解決に曖昧さがあるとき、コンパイラは正確一致を優先する。

## 8.6 ラムダ：名前のない関数

**定義**：関数リテラル——`{ x => x * 2 }`。波かっこで全体を包み、`引数 => 式` と書く。ラムダは**第一級市民**：代入でき、渡せ、返せる。

```jc
いれる 標準コレクション.*
関数 二回適用(f: (せいすう) -> せいすう, x: せいすう): せいすう {
    かえす f(f(x))
}

メイン() {
    おく 倍加 = { x => x * 2 }
    ひょうじ(二回適用(倍加, 3))      // 12（関数を代入・引数に渡せる）

    変数 めいぼ = リスト<せいすう>()
    めいぼ.くわえる(1); めいぼ.くわえる(2); めいぼ.くわえる(3)
    おく 倍加後 = めいぼ |> うつす({ x => x * 2 }) |> はいれつあつめ
    ひょうじ(倍加後)                   // [2, 4, 6]
}
```

**注意事項**：

- 複数引数：`{ x, y => x + y }`；
- ラムダの引数型は通常、文脈から推論される；
- 関数型の書き方：`(せいすう) -> せいすう`；
- `\x => ...` は他言語の書き方。倉頡では**使えない**。

## 8.7 クロージャ：環境を覚えている関数

**定義**：ラムダは定義されたスコープの変数を**捕まえられる**——関数は「生まれた時の環境」を覚えていて、その変数が元のスコープを出た後も使える。

```jc
関数 加算器(増分: せいすう): (せいすう) -> せいすう {
    かえす { x => x + 増分 }       // 増分 を捕まえる
}

メイン() {
    おく たす5 = 加算器(5)
    ひょうじ(たす5(10))            // 15
}
```

**注意事項**：

- 捕まえるのは**変数そのもの**（スナップショットではない）——ラムダ呼び出し前に捕まえた変数が変更されたら、ラムダは新しい値を見る；
- クロージャは「関数 + 環境」の組み合わせ。コールバックやイベント処理の土台。

## 8.8 デフォルト引数：省略しても呼べる

**定義**：宣言時にデフォルト値を与えれば、呼び出し時に省略できる——公式 1.0.5 の書き方は `引数: 型 = デフォルト値`。**実測：zhc の方言チェッカーはこの書き方をまだサポートしていない**（「`,` を期待、実際は `)`」と報告される）。教学段階では**オーバーロード**で同じ効果を実現する（将来公式の倉頡を書くとき、デフォルト引数に自然に切り替えられる）：

```jc
関数 挨拶(): 文字列 {
    かえす 挨拶("ともだち")      // オーバーロード：引数なし版は引数あり版を再利用
}

関数 挨拶(なまえ: 文字列): 文字列 {
    かえす "こんにちは、${なまえ}！"
}

メイン() {
    ひょうじ(挨拶())             // こんにちは、ともだち！（デフォルト値）
    ひょうじ(挨拶("太郎"))       // こんにちは、太郎！
}
```

**注意事項**：

- 公式のデフォルト引数は引数リストの**末尾**に置く（デフォルト値を持つ引数の後ろに必須引数は置けない）。オーバーロードは引数の個数/型で区別するので、2 つの版が互いに曖昧にならないよう注意；
- 名前付き引数 `!` と組み合わせるとさらに読みやすい。

## ✳ 設計思想

1. **明示的なインターフェース契約**：関数の引数に型注釈が必須——契約の細部がすべて表に出ていて、呼び出し側もコンパイラも同じ契約を見ている；
2. **第一級関数**：関数は値のように渡せる（ラムダ）——関数型スタイル（`うつす`/`こす`、第 11 章）の土台；
3. **クロージャは遅延実行**：`加算器(5)` はすぐ結果を計算せず、「計算のレシピ」をしまって呼び出しを待つ——「動作をしまい、後で実行する」はコールバックやタイマーなど、あらゆる非同期設計の思想的原型；
4. **少ないほどよい**：オーバーロードも名前付き引数もデフォルト引数も、同じ目標——**呼び出し箇所を読みやすく**。インターフェース設計の第一原則：呼び出し側の体験優先。

## 練習

1. `階乗` 関数を書こう（再帰でもループでもよい）。さらに `(商, 余り)` を返す関数を書き、分解で受け取ろう；
2. ラムダ + `うつす` で `リスト<せいすう>` の全要素に 10 を足し、配列に集めよう；
3. `倍数器(倍数: せいすう): (せいすう) -> せいすう` というクロージャ工場を作り、「×2」「×3」の関数を 1 つずつ作って呼ぼう；
4. 「評価」をオーバーロード版に書き換えよう：`関数 評価(): 文字列`（内部で `評価(60)` を呼ぶ）+ `関数 評価(てんすう: せいすう): 文字列`、引数 0 個と 1 個でそれぞれ呼ぼう；
5. 考えよう：オーバーロードとデフォルト引数はどちらも「引数を省略できる」？どんな場面でオーバーロードが必須？（ヒント：引数の**型**が違うとき）

## まとめ

- `関数 名前(引数: 型): 型 { かえす ... }`；引数は注釈必須・読み取り専用・全経路で返す；
- 複数返り値 = タプル + 分解 `おく (a, b) = ...`；
- 名前付き引数：宣言で `!`、呼び出しで `名前: 値`、名前なし引数は前へ；
- オーバーロードは引数（個数/型）で区別。戻り型だけの違いは不可；
- ラムダ `{ x => x * 2 }` は第一級市民。クロージャは定義時の環境を捕まえる。「省略しても呼べる」はオーバーロードで実現（公式デフォルト引数 `= デフォルト値` は末尾に置く。zhc は未サポート）。
