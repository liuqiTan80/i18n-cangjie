# 第 20 章 拡張と演算子オーバーロード

> **この章の学習目標**：「型のソースを直さずに振る舞いを足す」二つの鍵——`拡張`（外付けメソッド/インタフェース実装）と `演算子` オーバーロード（独自型に `+`、`==`、`[]` などのネイティブな書き方をサポートさせる）を身につける。継承/上書き（第 12 章）との分担を理解し、「言語ネイティブな型」のように読める独自型を書く。
> **この章を読み終えると答えられる問い**：なぜ拡張は「外付け式」と言うのか？拡張はフィールドを追加できる？`+=` を直接オーバーロードできる？型に `+` を載せる前に何を考えておくべき？

---

## 20.1 思想から実践へ：なぜ拡張が必要か

第 16 章の 16.9 で拡張の思想を学んだ：古典 OO の「クラスを変更する」には二つの痛点がある——**変更する権限がない**（標準ライブラリ、他人のクラス）と**変更すれば全員に影響する**（脆い基底クラス）。`拡張` は「振る舞いを足す」を**外付け式**の操作にする：各モジュールが自分が関心を持つ型にだけメソッドを掛け、互いに干渉しない。

この章は思想を筋肉記憶にする。まず最も直接的な例——公式の整数型にメソッドを掛ける：

```jc
// 拡張メソッド：公式の型に「外付けメソッド」を掛ける（元の型は変更しない）
拡張 せいすう {
    おおやけ 関数 二倍(): せいすう { かえす これ * 2 }
    おおやけ 関数 ぐうすう(): しんぎ { かえす これ % 2 == 0 }
}

メイン() {
    おく 数値 = 21
    ひょうじ("${数値} の二倍 = ${数値.二倍()}")
    ひょうじ("${数値} は偶数？${数値.ぐうすう()}")
    ひょうじ("100 の二倍 = ${100.二倍()}")
}
```

実行結果：

```
21 の二倍 = 42
21 は偶数？false
100 の二倍 = 200
```

三つの要点：

1. `拡張 型 { ... }` の書き方はクラス本体とまったく同じ——メソッドもプロパティアクセサも書ける；
2. メソッドの内部で `これ` が「拡張された値」を指す：`数値.二倍()` の中で、`数値` がそのまま `これ`；
3. リテラルからも直接呼べる：`100.二倍()`——拡張は**型**に働くのであって、ある変数に働くのではない。

## 20.2 拡張の境界：振る舞いは足せるが、家財は足せない

拡張は**メソッド**（関数/プロパティアクセサ）を掛けられるが、型に**フィールド（記憶領域）を追加**はできない——記憶レイアウトは型定義のときに決まりきっていて、外付けはそれを変えられない。

| できること | できないこと |
|---|---|
| 関数（メソッド）を足す | `おく`/`変数` のフィールドを足す |
| プロパティアクセサ（`取得`/`設定`）を足す | 型の継承関係を変える（ただしインタフェース実装は補える。20.3 参照） |
| 演算子オーバーロードを足す（20.4-20.6 参照） | 元の型の非公開メンバに触る（可視性の規則は変わらない） |

この境界は実は**長所**：拡張は「振る舞い」だけを足し「状態」は足せない——つまり拡張が二つのモジュールの状態をかき混ぜることは決してない。それぞれがメソッドを掛け合っても干渉しない。

## 20.3 拡張によるインタフェース実装：無関係な型に共通の振る舞いを

第 12 章で学んだ：インタフェースは「能力の契約」。`クラス 犬 <: 鳴く` は**クラスを定義するとき**に能力を宣言する。だが「他人が定義したクラスを、まとめて同じように扱いたい」ときは？——`拡張 X <: インタフェース`：

```jc
// 拡張によるインタフェース実装：「無関係」な型に共通の振る舞いを持たせる（外部インタフェース実装）
インタフェース 鳴く {
    関数 鳴く(): 文字列
}

クラス 犬 {}
クラス 猫 {}
クラス めざまし {}

拡張 犬 <: 鳴く {
    おおやけ 関数 鳴く(): 文字列 { かえす "ワンワン" }
}
拡張 猫 <: 鳴く {
    おおやけ 関数 鳴く(): 文字列 { かえす "ニャーニャー" }
}
拡張 めざまし <: 鳴く {
    おおやけ 関数 鳴く(): 文字列 { かえす "キンコンカン" }
}

メイン() {
    おく なかまたち: はいれつ<鳴く> = [犬(), 猫(), めざまし()]
    それぞれ (仲間 in なかまたち) {
        ひょうじ(仲間.鳴く())
    }
}
```

実行結果：

```
ワンワン
ニャーニャー
キンコンカン
```

教学の重点：

- `犬`、`猫`、`めざまし` は定義時には無関係。**その後**、三つの `拡張 … <: 鳴く` で同じ能力を後付けする；
- 能力を後付けすれば、`はいれつ<鳴く>` に入れて一括で呼べる——**多態は事前の計画を必要としない**；
- 適用範囲：自分のクラスにインタフェースを補う、サードパーティのライブラリのクラスにインタフェースを補う（条件：インタフェースと型がどちらもこのモジュールから見えていること）。

> **思想のヒント**：拡張によるインタフェース実装は「組み合わせは継承に勝る」の最強形態——継承は**未来の予知**を要求する（クラスを書くときにすべてのサブクラスを考えておく）が、拡張は**いつでも後から切符を買える**。標準ライブラリの多くの「方言メソッド」（`trimAscii`/`わける` など）はまさにこの拡張の仕組みで文字列やコレクションに掛かっている。

## 20.4 演算子オーバーロード：あなたの型に「+」を

### 20.4.1 メンバ式オーバーロード

まずクラスの中に直接演算子を宣言する——ベクトル的なクラスに自分の `+` と `==` を定義する：

```jc
// クラス内で演算子オーバーロードを宣言：クラスに自分の「+」を定義する
クラス ベクトル {
    おおやけ おく よこ: せいすう
    おおやけ おく たて: せいすう
    初期化(よこ: せいすう, たて: せいすう) {
        これ.よこ = よこ
        これ.たて = たて
    }

    おおやけ 演算子 関数 +(ほか: ベクトル): ベクトル {
        かえす ベクトル(これ.よこ + ほか.よこ, これ.たて + ほか.たて)
    }
    おおやけ 演算子 関数 ==(ほか: ベクトル): しんぎ {
        かえす これ.よこ == ほか.よこ && これ.たて == ほか.たて
    }
}

メイン() {
    おく あ = ベクトル(1, 2)
    おく い = ベクトル(3, 4)
    おく う = あ + い            // あなたのクラスが初めて「+」をサポート
    ひょうじ("あ + い = (${う.よこ}, ${う.たて})")
    ひょうじ("あ == い？${あ == い}")
    ひょうじ("あ == ベクトル(1, 2)？${あ == ベクトル(1, 2)}")
}
```

実行結果：

```
あ + い = (4, 6)
あ == い？false
あ == ベクトル(1, 2)？true
```

構文の解剖——`おおやけ 演算子 関数 +(...)`：

| 断片 | 意味 |
|---|---|
| `おおやけ` | 省略可（クラス内メンバの既定可視性は普通の関数と同じ規則） |
| `演算子` | これが演算子オーバーロードだと宣言する（関数名の位置の前に書く） |
| `関数` | 普通の関数と共通の `関数` キーワード |
| `+` | オーバーロードしたい演算子の記号。関数名の位置に書く |
| `(ほか: ベクトル)` | 引数：二項演算子の右オペランド（単項演算子は引数なし） |
| `: ベクトル` | 戻り値の型：`+` はふつう新しいオブジェクトを返す |

`あ + い` はコンパイラによって `あ.+(い)` の呼び出しに書き換えられる——注意：**左オペランドがレシーバ**。だから `==` のオーバーロードの中で `これ` は左側の `あ` を指す。

### 20.4.2 `==` をオーバーロードしないとどうなる？

既定の `==` はクラスに対して**参照比較**（二つの変数が同じオブジェクトを指すか）を行う——内容の比較ではない。内容が同じ二つの `ベクトル(1, 2)` は等しくない。だから「値セマンティクスのクラス」はほとんど常に `==` をオーバーロードする。これは第 9 章の「オプションの中の独自クラスを直接比較できない」罠の説明にもなる：本質はそのクラスが `==` をオーバーロードしていないから。

**注意：`!=` は自動で反転にならない**。`==` だけオーバーロードして `あ != い` と書くと、コンパイラが `演算子 関数 !=` を補うよう促す（あるいは第 15 章の `@導出(ひとしい)` で完全な等価性を一発生成）。両方書く必要があるとき、`!=` の定番の書き方は `かえす !(これ == ほか)`——ロジックは一箇所だけ保守する。

## 20.5 拡張式演算子：クラスを直さず、振る舞いを外付け

演算子オーバーロードと拡張は**直交**している——組み合わせられる：`拡張` ブロックで他人のクラスに演算子を足す。これが最もよく使う姿勢：

```jc
// 拡張演算子：クラスを直さず、振る舞いを外付け
クラス 点 {
    おおやけ おく よこ: せいすう
    おおやけ おく たて: せいすう
    初期化(よこ: せいすう, たて: せいすう) {
        これ.よこ = よこ
        これ.たて = たて
    }
}

拡張 点 {
    おおやけ 演算子 関数 +(ほか: 点): 点 {
        かえす 点(これ.よこ + ほか.よこ, これ.たて + ほか.たて)
    }
    おおやけ 演算子 関数 ==(ほか: 点): しんぎ {
        かえす これ.よこ == ほか.よこ && これ.たて == ほか.たて
    }
    おおやけ 演算子 関数 !(): 点 {        // 単項演算子：原点対称
        かえす 点(-これ.よこ, -これ.たて)
    }
    おおやけ 演算子 関数 <(ほか: 点): しんぎ {   // 原点からの距離の比較（二乗）
        かえす これ.よこ * これ.よこ + これ.たて * これ.たて
               < ほか.よこ * ほか.よこ + ほか.たて * ほか.たて
    }
}

メイン() {
    おく あ = 点(1, 2)
    おく い = 点(3, 4)
    おく う = あ + い
    ひょうじ("あ + い = (${う.よこ}, ${う.たて})")
    ひょうじ("!あ = (${(!あ).よこ}, ${(!あ).たて})")
    ひょうじ("あ < い？${あ < い}")
}
```

実行結果：

```
あ + い = (4, 6)
!あ = (-1, -2)
あ < い？true
```

単項演算子の呼び出しにはかっこが要る：`(!あ).よこ`——`!` の優先順位は `.` より低いので、`!あ.よこ` は `!(あ.よこ)` と解釈されてしまう。

### 20.5.1 複合代入 `+=`：直接はオーバーロードできないが、自動展開される

`+=`、`-=`、`*=` などの複合代入は**直接オーバーロードできない**。だが良い知らせ：`+` をオーバーロードしてさえいれば、`a += b` は `a = a + b` へ自動展開される——条件は `a` が `変数` 束縛であること：

```jc
// 複合代入 +=：直接はオーバーロードできないが、+ を載せれば自動展開（a += b ⇒ a = a + b）
クラス カウンタ {
    おおやけ 変数 値: せいすう
    初期化(値: せいすう) { これ.値 = 値 }
}
拡張 カウンタ {
    おおやけ 演算子 関数 +(ほか: カウンタ): カウンタ {
        かえす カウンタ(これ.値 + ほか.値)
    }
}
メイン() {
    変数 あ = カウンタ(10)
    あ += カウンタ(5)        // あ = あ + カウンタ(5) と等価
    ひょうじ("あの値 = ${あ.値}")
}
```

実行結果：

```
あの値 = 15
```

## 20.6 添字演算子：あなたの型に `[]` を

`[]` は「添字で要素を取る」演算子。コレクションにはある（`はいれつ[0]`）——独自型にも持てる：

```jc
// 添字演算子 []：独自型に「添字の読み書き」を
クラス ペア {
    おおやけ おく あ: 文字列
    おおやけ おく い: 文字列
    初期化(あ: 文字列, い: 文字列) {
        これ.あ = あ
        これ.い = い
    }
}

拡張 ペア {
    おおやけ 演算子 関数 [](さくいん: せいすう): 文字列 {
        もし (さくいん == 0) {
            かえす これ.あ
        }
        かえす これ.い
    }
}

メイン() {
    おく チーム = ペア("アキラ", "ミク")
    ひょうじ("1 位：${チーム[0]}")
    ひょうじ("2 位：${チーム[1]}")
}
```

実行結果：

```
1 位：アキラ
2 位：ミク
```

`演算子 関数 []` の読み取り専用版だけで `チーム[0]` は成立する。本物のコンテナ（第 11 章のコレクションなど）はさらに `設定` と組み合わせて読み書き両版を提供する——だが教学上はこう覚えておこう：**まず読み取り専用版。足りて、かつ安全**。

## 20.7 演算子オーバーロードの規律：何を載せられるか、何を暴れてはいけないか

### オーバーロードできる演算子面（よく使うサブセット）

| カテゴリ | 演算子 | 引数 | 典型の戻り値 |
|---|---|---|---|
| 四則 | `+` `-` `*` `/` `%` | 1 個（右オペランド） | 新しいオブジェクト |
| 比較 | `==` `!=` `<` `>` `<=` `>=` | 1 個 | `しんぎ` |
| 単項 | `!`（論理否定/反転） | 0 個 | 同種オブジェクトか真偽 |
| 添字 | `[]` | 1 個（添字） | 要素の型 |

### 触れてはいけない一線

1. **新しい記号は作れない**：オーバーロードできるのは言語に既存の演算子だけ。`**`（冪乗）、`<>`（自作の山かっこ）は存在しない——オーバーロードは文法を増やさない；
2. **元数と優先順位は変えられない**：`+` は永遠に二項。優先順位も永遠に不変——`あ + い * う` はやはり掛け算が先；
3. **オーバーロードできない**：`=`（代入）、`&&`/`||`（短絡）、`?:`（三項。倉頡にない）、複合代入 `+=` など（自動展開される）；
4. **意味の一貫性**：`+` は交換可能であるべき（`あ + い == い + あ`）、`==` は反射的であるべき（`あ == あ`）で `!=` と相補的であるべき——`+` を「引き算」としてオーバーロードしてもコンパイラは怒らない。だがあなたのコードを読む人は発狂する；
5. **継承の体系内での上書きは慎重に**：コンパイラは「サブクラスが親クラスの演算子を再定義する」ことに厳しい制限を課す（シグネチャが完全一致かつ親が `開放` であること）。差別化した振る舞いが欲しいときは**継承の上書きより拡張を先に考える**——これも 16.9 の「組み合わせは継承に勝る」。

> **対比で覚える**：`上書き` は**継承の体系内**で親クラスの実装を変える（第 12 章）。`演算子` は**型の振る舞い面**で文法を拡張する。キーワードも場面も違う——演算子オーバーロードと `再定義` 修饰子が同時に現れると衝突エラー。混ぜるな。

## 20.8 総合ケース：分数クラス

この章の二つの鍵を合わせる：「振る舞いの完全な」分数クラス（分子/分母）。加減乗と等価比較がすべてネイティブな書き方で使える：

```jc
// 総合ケース：分数クラス（四則のうち加減乗 + 等価比較）
クラス 分数 {
    おおやけ おく 分子: せいすう
    おおやけ おく 分母: せいすう
    初期化(分子: せいすう, 分母: せいすう) {
        これ.分子 = 分子
        これ.分母 = 分母
    }
}

拡張 分数 {
    おおやけ 演算子 関数 +(ほか: 分数): 分数 {
        かえす 分数(これ.分子 * ほか.分母 + ほか.分子 * これ.分母,
                    これ.分母 * ほか.分母)
    }
    おおやけ 演算子 関数 -(ほか: 分数): 分数 {
        かえす 分数(これ.分子 * ほか.分母 - ほか.分子 * これ.分母,
                    これ.分母 * ほか.分母)
    }
    おおやけ 演算子 関数 *(ほか: 分数): 分数 {
        かえす 分数(これ.分子 * ほか.分子, これ.分母 * ほか.分母)
    }
    おおやけ 演算子 関数 ==(ほか: 分数): しんぎ {
        かえす これ.分子 * ほか.分母 == ほか.分子 * これ.分母
    }
}

メイン() {
    おく はんぶん = 分数(1, 2)
    おく さんぶんいち = 分数(1, 3)
    おく わ = はんぶん + さんぶんいち
    おく さ = はんぶん - さんぶんいち
    おく せき = はんぶん * さんぶんいち
    ひょうじ("1/2 + 1/3 = ${わ.分子}/${わ.分母}")
    ひょうじ("1/2 - 1/3 = ${さ.分子}/${さ.分母}")
    ひょうじ("1/2 × 1/3 = ${せき.分子}/${せき.分母}")
    ひょうじ("1/2 == 2/4？${はんぶん == 分数(2, 4)}")
}
```

実行結果：

```
1/2 + 1/3 = 5/6
1/2 - 1/3 = 1/6
1/2 × 1/3 = 1/6
1/2 == 2/4？true
```

注意：`==` の実装は**交差乗算**（`分子1 × 分母2 == 分子2 × 分母1`）であって、フィールドの逐一比較ではない——`1/2` と `2/4` は記憶の仕方は違うが数値として等しい。これはまさに「`==` のオーバーロードはあなたの型の等価セマンティクスを定義することだ」を物語る。

> **リアルさ**：上のすべてのコードブロックは `zhc run` で実測済み（出力は各段落のとおり）。拡張 + 演算子は「独自型の体験」の分水嶺——分数クラスをやり終えれば、あなたの型は `せいすう` や `文字列` と同じくらい自然に使える。

## 練習

1. `せいすう` を拡張して `階乗(): せいすう` メソッドを足そう（`n` の階乗 = `1 × 2 × … × n`。再帰でよい。第 17 章参照）。`5.階乗()` が 120 になるのを確かめよう；
2. 20.8 の分数クラスに割り算 `/`（逆数を掛ける）を足し、`約分()` メソッドを書こう（分子分母を最大公約数で割る。ユークリッドの互除法）。`1/2 + 1/2` が `2/4` ではなく `1/1` を出力するように；

## まとめ

- `拡張` = 型に記憶領域を足さず、振る舞いだけを足す**外付け**。`拡張 X <: インタフェース` で既存の型に事後的にインタフェース能力を持たせられる；
- `演算子 関数 +` など = 独自型にネイティブな演算子の書き方をサポートさせる。クラス内でも `拡張` ブロック内でも書ける；
- `+=` は直接オーバーロードできないが、`+` を載せれば自動展開される（`変数` 束縛が必要）。`[]` で添字の読み出しを提供；
- 規律：新しい記号を作らない。優先順位/元数を変えない。意味を一貫させる。継承の上書きが制限されるときは拡張を優先；
- 第 12 章の `上書き` との分担：`上書き` は継承の体系内のメソッド上書きを担当し、`演算子` は型の振る舞い面を担当する。
