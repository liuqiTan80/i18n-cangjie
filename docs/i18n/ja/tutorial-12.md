# 第 12 章 構造体とクラス

> **この章の学習目標**：データをまとめる二つの流儀——`構造体`（値セマンティクス）と `クラス`（参照セマンティクス）を身につけ、開放/上書き/インタフェース/多態の明示的な設計を理解し、プロパティと型テストで安全なオブジェクト指向コードを書けるようになる。
> **この章を読み終えると答えられる問い**：構造体とクラスはどこが違う？なぜ倉頡のクラスはデフォルトで継承できない？`上書き` を書き忘れるとどうなる？

---

## 導入の物語：関連するものは束ねる

1 つの点を表す：横座標 x、縦座標 y。変数を 2 個に分けると、「x と y はセット」と常に覚えていなければならない。**構造体**は関連データを 1 つのまとまりに束ねる——**健康診断票**のようなものだ。身長・体重・視力が 1 枚の票に固定されている：

```jc
構造体 点 {
    おおやけ 変数 x: せいすう
    おおやけ 変数 y: せいすう
    初期化(x: せいすう, y: せいすう) {
        これ.x = x
        これ.y = y
    }
    おおやけ 関数 距離二乗(): せいすう {
        かえす これ.x * これ.x + これ.y * これ.y
    }
}

メイン() {
    おく 原点 = 点(3, 4)
    ひょうじ("座標（${原点.x}，${原点.y}）")
    ひょうじ("原点からの距離の二乗：${原点.距離二乗()}")
}
```

- `構造体 点`：「点」という形の箱を定義する。中に x と y が入る；
- `初期化(...)`：**構築**——箱を作るときに材料を入れる；
- `これ`：「今この箱自身」を指す。`これ.x` は「自分の中の x」；
- `点(3, 4)`：設計図どおりに x=3、y=4 の点を作る（ピタゴラスの定理：3²+4²=25。出力は 25）。

**クラス**は構造体とよく似ているが、もっと強い——一番すごいのは**継承**だ。犬は動物の一種。犬は動物のすべてを「受け継ぎ」、自分の特徴を足す：

```jc
開放 クラス 動物 {
    おおやけ 変数 名前: 文字列
    初期化(名前: 文字列) {
        これ.名前 = 名前
    }
    おおやけ 開放 関数 鳴く(): 文字列 { かえす "……" }
}

クラス 犬 <: 動物 {
    初期化(名前: 文字列) {
        おや(名前)
    }
    おおやけ 上書き 関数 鳴く(): 文字列 { かえす "ワンワン" }
}

メイン() {
    おく ポチ = 犬("ポチ")
    ひょうじ("${ポチ.名前}：${ポチ.鳴く()}")
}
```

- `クラス 犬 <: 動物`：犬「小なりコロン」動物——**犬は動物の一種**。動物のものを全部引き継ぐ；
- `おや(名前)`：名前を「お父さん」の動物に預ける（親のコンストラクタを借りる）；
- `上書き`：犬は「鳴く」を「……」から「ワンワン」に変える——**上書き**（オーバーライド）。

> なぜクラスと継承が必要なのか？現実世界そのものが階層的だからだ：「動物 → 犬」「車 → 電気自動車」。プログラムを現実に沿って書けば、分かりやすく、拡張しやすい——あとで猫を増やしたくなっても、動物は触らず、`猫` クラスを新しく書くだけでいい。なぜ `動物` に `開放` を付けなければならないのか？本文 12.4 で答える。

## 12.1 定義：値セマンティクス vs 参照セマンティクス

**定義**：1 組の関連データを 1 つにまとめる方法は二通り：

| | `構造体` | `クラス` |
|---|---|---|
| セマンティクス | **値型**：代入/引数渡しは**丸ごとコピー** | **参照型**：代入/引数渡しは**参照の共有** |
| 代入のあと | コピーを変えても**元に影響しない** | 複数の変数が**同じオブジェクト**を指す。1 箇所変えればどこも変わる |
| 能力 | 継承できない。多態なし | 継承できる。多態も可能（`開放` が必要） |
| 向き | 小さく独立した安全なデータ（座標・色・金額） | 同じデータを複数箇所で使うオブジェクト（学生カルテ・銀行口座） |

**経験則：データが小さく独立なら構造体、多態/共有が必要ならクラス。**

## 12.2 構造体：値型

**日本語の書き方**：

```jc
構造体 点 {
    おおやけ 変数 x: せいすう
    おおやけ 変数 y: せいすう

    初期化(x: せいすう, y: せいすう) {
        これ.x = x
        これ.y = y
    }

    おおやけ 関数 距離二乗(): せいすう {
        かえす これ.x * これ.x + これ.y * これ.y
    }
}

メイン() {
    おく 原点 = 点(3, 4)
    ひょうじ("点の座標：(${原点.x}, ${原点.y})")
    ひょうじ("距離の二乗：${原点.距離二乗()}")   // 25

    変数 コピー = 原点                        // 値セマンティクス：丸ごとコピー
    コピー.x = 100                            // コピーだけを変える
    ひょうじ("${原点.x} ${コピー.x}")           // 3 100（原点は影響を受けない）
}
```

**注意事項**：

- `初期化` はコンストラクタ。コンストラクタの中で `これ` は現在のインスタンスを指す；
- メンバはデフォルト**非公開**。外に見せるには `おおやけ` を付ける；
- 構造体は**継承できない**。抽象メンバも持てない——「小さいデータ + 多態なし」の場面での既定の選択。

## 12.3 クラス：参照型

**日本語の書き方**：

```jc
クラス 学生 {
    おおやけ 変数 名前: 文字列
    おおやけ 変数 点数: せいすう

    初期化(名前: 文字列, 点数: せいすう) {
        これ.名前 = 名前
        これ.点数 = 点数
    }

    おおやけ 関数 評価(): 文字列 {
        もし (これ.点数 >= 90) { かえす "優秀" }
        かえす "ガンバレ"
    }
}

メイン() {
    おく 太郎 = 学生("太郎", 95)
    おく 花子 = 太郎                        // 参照セマンティクス：同じオブジェクトを指す
    花子.点数 = 70
    ひょうじ("${太郎.名前}：${太郎.評価()}")   // 太郎：ガンバレ（太郎まで変わっている！）
}
```

**注意事項**：フィールドはデフォルト非公開（クラスの外から見えない）。クラスはデフォルト**継承不可**（`開放` が必要）——どちらも明示的な安全設計。

## 12.4 開放と上書き：デフォルトで閉じた継承

**定義**：継承はカプセル化を壊す（サブクラスが親クラスの内部詳細に依存する）。そこで倉頡は継承を**明示的に申請する特権**にした——`開放` は「私は他人が私を拡張するのを許す」という宣言、`上書き` は「私は確かに親クラスのメソッドを覆している」という宣言。

**日本語の書き方**：

```jc
開放 クラス 動物 {
    おおやけ 開放 関数 鳴く(): 文字列 { かえす "……" }
}

クラス 犬 <: 動物 {
    おおやけ 上書き 関数 鳴く(): 文字列 { かえす "ワンワン" }
}

メイン() {
    おく ポチ: 動物 = 犬()       // 親クラスの型に子クラスのオブジェクトを入れる
    ひょうじ(ポチ.鳴く())        // ワンワン（動的ディスパッチ：実行時にどの実装を使うか決まる）
}
```

**三つの硬規則（公式 1.0.5 で実測）**：

| 規則 | 結果 |
|---|---|
| `開放` でないクラスを継承 | コンパイルエラー「開放でない型は継承できない」 |
| 親クラスのメソッドが `開放` なのに `上書き` しない | コンパイルエラー（上書きできない） |
| 上書きするとき `上書き` キーワードを書かない | コンパイルエラー——`上書き` は**強制宣言**。「上書きのつもりが名前を書き間違えて新メソッドになる」古典バグを防ぐ |

## 12.5 継承とおや

**定義**：「犬は動物に属する」の「属する」関係は `クラス 犬 <: 動物` で表す（`<:` は「のサブタイプ」と読む）。サブクラスは親クラスのすべてを引き継ぎ、`おや(...)` で親のコンストラクタを呼び、`おや.メソッド()` で親のロジックを再利用できる。

**日本語の書き方**：

```jc
開放 クラス 動物 {
    おおやけ 変数 名前: 文字列
    初期化(名前: 文字列) { これ.名前 = 名前 }
    おおやけ 開放 関数 紹介(): 文字列 { かえす "私は${これ.名前}" }
}

クラス 犬 <: 動物 {
    初期化(名前: 文字列) {
        おや(名前)              // 最初の文：親のコンストラクタを呼ぶ
    }
    おおやけ 上書き 関数 紹介(): 文字列 {
        かえす "${おや.紹介()}、犬です"    // 親のロジックを再利用して拡張する
    }
}

メイン() {
    ひょうじ(犬("ポチ").紹介())   // 私はポチ、犬です
}
```

**注意事項**：

- 倉頡は**単一継承**（1 つのクラスが持てる親は 1 つだけ）；
- サブクラスのコンストラクタは**最初に `おや(...)` を呼んでから**自分のフィールドを初期化する；
- フィールドとコンストラクタ引数が同名のときは**必ず `これ.` で区別する**——さもないと `名前 = 名前` は自分に自分を代入して、フィールドが未初期化になりコンパイラがエラーを出す。

## 12.6 インタフェース：能力のリスト

**定義**：メソッドのシグネチャだけを宣言し（デフォルト実装は持てる）、状態を持たない**純粋なふるまいの契約**。クラスは単一継承しかできないが、インタフェースは**複数実装できる**——インタフェースは「能力のリスト」。

**日本語の書き方**：

```jc
インタフェース 鳴く {
    関数 鳴く(): 文字列
}

クラス 犬 <: 鳴く {
    おおやけ 関数 鳴く(): 文字列 { かえす "ワンワン" }
}

クラス 猫 <: 鳴く {
    おおやけ 関数 鳴く(): 文字列 { かえす "ニャー" }
}

メイン() {
    おく ペット: 鳴く = 犬()
    おく タマ: 鳴く = 猫()
    ひょうじ(ペット.鳴く() + タマ.鳴く())   // ワンワンニャー
}
```

**注意事項**：インタフェースのメソッドはデフォルト**おおやけ**。`<:` は継承にもインタフェース実装にも使う。実装クラスは**デフォルト実装のない全メソッドを実装しなければならない**（1 つ漏れるとコンパイルエラー）。インタフェース型の変数からは、インタフェースが宣言したメソッドしか呼べない。

## 12.7 抽象と静的

**定義**：**抽象クラス** = 「未完成品」のマーク。抽象クラスは**インスタンス化できない**。継承されるためだけに存在する。抽象メソッドには関数本体がなく、サブクラスに実装を強制する。**静的メンバ** = インスタンスではなく**クラス自身**に属する。

**日本語の書き方**：

```jc
ちゅうしょう クラス 図形 {
    おおやけ 関数 面積(): じっすう        // 抽象メソッド：関数本体を書かなければよい
}

クラス 正方形 <: 図形 {
    おおやけ 変数 辺長: じっすう
    初期化(辺長: じっすう) { これ.辺長 = 辺長 }
    おおやけ 上書き 関数 面積(): じっすう { かえす これ.辺長 * これ.辺長 }
}

クラス ツール {
    静的 関数 二倍(数: せいすう): せいすう { かえす 数 * 2 }
    静的 変数 呼出回数: せいすう = 0
}

メイン() {
    ひょうじ(正方形(3.0).面積())    // 9.000000（表示は公式形式）
    ツール.呼出回数 += 1
    ひょうじ(ツール.二倍(21))        // 42
}
```

**注意事項**：抽象クラスは**自動的に開放**。サブクラスが抽象メソッドを全部実装しなければ、それも `ちゅうしょう` を付けなければならない。静的メソッドは**インスタンスフィールド/`これ` にアクセスできない**。静的変数メンバはグローバル状態（並行処理では同期が必要）。

## 12.8 プロパティとアクセサ：カプセル化のバランス点

**定義**：**プロパティ**：外からはフィールドのように読み書きでき、内側では `取得()` が制御するメンバ——「データは見えるが改ざんはできない」。**可変プロパティ**：読み書き両方できる。`取得()` と `設定(値)` が対で現れる。

**日本語の書き方**：

```jc
クラス 本 {
    非公開 変数 書名値: 文字列 = ""
    おおやけ プロパティ 書名: 文字列 {
        取得() { かえす これ.書名値 }
    }
    初期化(書名: 文字列) { これ.書名値 = 書名 }
}

クラス 温度計 {
    非公開 変数 摂氏値: じっすう = 0.0
    おおやけ 可変 プロパティ 摂氏: じっすう {
        取得() { かえす これ.摂氏値 }
        設定(値) { これ.摂氏値 = 値 }    // 引数は代入される新しい値
    }
}

メイン() {
    おく 辞書 = 本("倉頡辞書")
    ひょうじ(辞書.書名)              // 倉頡辞書
    // 辞書.書名 = "ほか"  ← コンパイルエラー：プロパティは読み取り専用。代入できない

    おく 計器 = 温度計()
    計器.摂氏 = 36.5               // 設定 を通る
    ひょうじ(計器.摂氏)              // 36.500000（取得 を通る。表示は公式形式）
}
```

**注意事項**：`プロパティ` は**読み取り専用**——`取得()` だけ定義できる。`可変 プロパティ` は `取得()` と `設定(パラメータ)` を**両方**提供しなければならない。`取得()` のかっこは**省略できない**（公式 1.0.5 の文法）。アクセサはクラス内部にいるので、非公開フィールドにアクセスできる。

## 12.9 可変：構造体のメンバ関数を変更する

**定義**：構造体は値型で、`おく` 束縛はさらに不変——もしメンバ関数がこっそりフィールドを書き換えられたら、コピーした複製が「いつの間にか変わる」。`可変` は「この関数は自分自身を変える」を**見える許可**にする。

**日本語の書き方**：

```jc
構造体 カウンタ {
    おおやけ 変数 値: せいすう
    初期化(値: せいすう) { これ.値 = 値 }
    おおやけ 可変 関数 自増() {
        これ.値 += 1           // 可変 関数だからこそ構造体自身を変更できる
    }
}

メイン() {
    変数 かず = カウンタ(1)
    かず.自増()
    ひょうじ(かず.値)               // 2
}
```

**三つの硬規則（公式 1.0.5 で実測）**：

| 規則 | 結果 |
|---|---|
| `おく` 束縛のインスタンスで `可変` 関数を呼ぶ | コンパイルエラー（`おく` は不変。`変数` が必要） |
| `可変` をクラスのメソッドに付ける | コンパイルエラー（クラスのメソッドは元からフィールドを変えられる。`可変` は禁止） |
| `可変` をパラメータ/メンバ変数/静的関数に付ける | コンパイルエラー（`可変` は**構造体/インタフェースのインスタンスメンバ関数にだけ**付けられる） |

## 12.10 型テストと変換（である / として）

**定義**：親クラス型の変数を手にして、実際にはどのサブクラスなのか知りたい——`である` は型テストでブールを返す。`として` はダウンキャストで `オプション<T>` を返す。

**日本語の書き方**：

```jc
開放 クラス 動物 {}

クラス 犬 <: 動物 {
    おおやけ 関数 しっぽ(): 文字列 { かえす "しっぽを振る" }
}

クラス 猫 <: 動物 {}

メイン() {
    おく ペット: 動物 = 犬()            // アップキャスト（子→親）：自動。常に安全
    もし (ペット である 犬) {             // `である`：型テスト。ブールを返す
        ひょうじ("犬だ")
    }
    ひょうじ(ペット である 猫)               // false（実行時出力は公式形式）

    おく ポチ = (ペット として 犬).なければれいがい()   // ダウンキャスト（親→子）：必ず として
    ひょうじ(ポチ.しっぽ())
}
```

**注意事項**：ダウンキャストは失敗しうる（動物は犬とは限らない）——`として` は **`オプション<T>`** を返す（失敗なら `なし`）。`.なければれいがい()` で開くか、`マッチ` で処理する。より確実なのは先に `である` で判定してから `として` すること。**数値の変換と型階層の変換は別物**（`せいすう(3.9)` は数値変換。第 9 章）。

## 12.11 多態と動的束縛

**定義**：インタフェース/親クラス型の変数は任意の実装/サブクラスのオブジェクトを入れられる。メソッド呼び出しは**実行時**にどのバージョンを実行するか決まる——**インタフェース向けプログラミング**：コードは「具体」ではなく「抽象」に依存する。

**日本語の書き方**：

```jc
インタフェース 鳴く {
    関数 鳴く(): 文字列
}

クラス 犬 <: 鳴く {
    おおやけ 関数 鳴く(): 文字列 { かえす "ワンワン" }
}

クラス 猫 <: 鳴く {
    おおやけ 関数 鳴く(): 文字列 { かえす "ニャー" }
}

関数 合唱(ペットたち: はいれつ<鳴く>) {
    それぞれ (ペット in ペットたち) {
        ひょうじ(ペット.鳴く())        // 動的束縛：それぞれが自分の鳴き声を出す
    }
}

メイン() {
    合唱([犬(), 猫()])
}
```

**注意事項**：多態は**参照型（クラス/インタフェース）にだけ効く**。構造体は値型なので動的束縛はない。`開放` + `上書き` + インタフェース実装がそろって多態の三種の神器。

## ✳ 設計思想

**① 値 vs 参照のセマンティクス：「データがどう共有されるか」を先に考える**。構造体は代入即コピー——「小さく、独立、安全」なデータ向き。クラスのインスタンスは参照を共有——「同じデータを複数箇所で使う」オブジェクト向き。

**② デフォルトで閉じる：安全設計が「継承」を高価で明示的なものにする**。継承はカプセル化を壊す——倉頡は `開放` が付いたものだけ継承でき、`上書き` が付いたものだけ覆せる。これで「拡張ポイント」はクラス作者の明示的な決定になる：クラスを書くときに、どの部分を後人の拡張に残すかを考え、残りはデフォルトで封じる。

**③ カプセル化の三層**：`おおやけ 変数`（全開放）→ `プロパティ`/`可変 プロパティ`（データは見えるが読み書きが制御される）→ `非公開`（完全に隠す）。まずは最も簡単なものを使い、検証/キャッシュが必要になったらプロパティへ格上げする——呼び出し側のコードは変えなくてよい。

**④ 組み合わせは継承に勝る**：構造体はクラスの中にネストできる。「持つ」関係は組み合わせで表せるなら、むやみに継承を作らないこと。継承は「属する」関係で、かつ本当に多態が必要なときに向いている。

**⑤ インタフェース向けプログラミング**：`合唱` は `鳴く` にだけ依存する。相手が犬か猫かは知らないし気にしない。「変わる部分」をインタフェースに抽象化するのが、ソフトウェアの拡張性の中核手段。

**⑥ 明示は暗黙に勝る**：`上書き` の強制宣言は名前の書き間違いを防ぎ、`可変` の見える許可は複製のこっそり変化を防ぎ、`として` の明示変換は型の取り違えを防ぐ——倉頡は「間違えやすい場所」をぜんぶ明示的なコンパイル時チェックにしている。

## まとめ

- `構造体` は値セマンティクス（代入即コピー）、`クラス` は参照セマンティクス（代入は共有）。フィールドはデフォルト非公開；
- 継承/インタフェース実装は `<:`。継承と上書きは親の `開放` + 子の `上書き` の二重明示；
- `おや(...)` で親のコンストラクタを呼ぶ（必ず最初の文）。`おや.メソッド()` で親のロジックを再利用。単一継承、インタフェースは複数実装可能；
- `プロパティ` は読み取り専用、`可変 プロパティ` は読み書き可能（`取得()`/`設定(値)` が対）。`可変` は構造体/インタフェースのインスタンスメンバ関数にだけ付けられる；
- `列挙` はデータを添えられ、マッチは網羅を強制；`である` で型をテスト、`として` でダウンキャスト（`オプション` を返す）；
- 多態 = インタフェース/親クラス変数 + 実行時の動的束縛。参照型にだけ効く。
