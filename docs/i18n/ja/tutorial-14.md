# 第 14 章 エラー処理と並行処理

> **この章の学習目標**：倉頡の**ヌルポインタ撲滅**の二つの仕組み——`オプション`（Option）の空安全パターンと `ためす`/`とらえる` の例外体系を身につけ、並行処理に入門する：`うむ` でタスクを生み、`同期` でクリティカルセクションを守り、ロックと原子操作を使う。
> **この章を読み終えると答えられる問い**：`オプション` と例外はそれぞれどの場面を担当する？存在しないキーを取るとなぜクラッシュする？複数のタスクが同じ変数を変更すると何が起きる？

---

## 14.1 定義：空安全——null のない世界

**定義**：倉頡に **`null`/ヌルポインタはない**。null 可能性は型システムに入る——`オプション<T>` は `あり(x)`（Some）か `なし`（None）のどちらか。関数が `オプション<T>` を返すとき、コンパイラは「ないかもしれない」への対処を**強制**する——ヌルポインタバグが「実行時クラッシュ」から「コンパイル時エラー」に前倒しされる。

**日本語の書き方**：

```jc
関数 名前さがし(番号: せいすう): オプション<文字列> {
    もし (番号 == 1) {
        かえす あり("太郎")        // あり = Some：値を包む
    }
    かえす なし                   // なし = None：「ない」を表す
}

メイン() {
    マッチ (名前さがし(1)) {
        場合 あり(名前) => ひょうじ("見つけた：${名前}")
        場合 なし => ひょうじ("見つからなかった")
    }
}
```

**注意事項**：

- `なし` はどんな `オプション<T>` にも代入できる（型は文脈から推論される）；
- `オプション` の値は**普通の値として使えない**：`名前さがし(1) + "!"` はコンパイルエラー——先に開かなければならない；
- `オプション` を組み立てる三つの方法：`あり(x)`、`なし`、`x.あり()`。

## 14.2 開封三兄弟：マッチ / なければきてい / なければれいがい

**定義**：`オプション` は中身を取り出せなければ無意味。よく使う取り出し方は三つ：

```jc
関数 名前さがし(番号: せいすう): オプション<文字列> {
    もし (番号 == 1) { かえす あり("太郎") }
    かえす なし
}

メイン() {
    // ① マッチ：安全な分岐（推奨。網羅性検査つき）
    マッチ (名前さがし(1)) {
        場合 あり(名前) => ひょうじ("見つけた：${名前}")
        場合 なし => ひょうじ("そんな人はいない")
    }
    // ② なければきてい：なし のとき受け皿の値（引数はラムダ）
    ひょうじ(名前さがし(1).なければきてい({ => "名無し" }))
    // ③ なければれいがい：確実に中身があるときだけ使う。なし なら例外
    ひょうじ(名前さがし(1).なければれいがい())
}
```

**対照表**：

| 取り出し方 | 意味 | なし のとき |
|---|---|---|
| `マッチ` | 二つのケースを分岐処理 | `なし` の分岐へ（一番安全） |
| `なければきてい({ => 受け皿 })` | あり なら値を取り、なし なら受け皿 | 受け皿の値を返す |
| `なければれいがい()` | 中身があると確信している | 例外を投げる（プログラム崩壊） |

**注意事項**：`なければきてい` の引数は **ラムダ**（`{ => 0 }`）であって普通の値ではない。「むしろマッチを使い、れいがい を乱用しない」——`なければれいがい` を間違って使えば、空安全をまたヌルポインタに逆戻りさせることになる。

## 14.3 予期した失敗にはオプション（公式に Result 型はない）

**定義**：公式 1.0.5 に**`結果`（Result）型はない**——「失敗しうる」は統一して `オプション<T>` で表す：成功は `あり(成功値)`、失敗は `なし`。

**日本語の書き方**：

```jc
いれる 標準変換.*
いれる 正規表現.*

関数 点数解析(テキスト: 文字列): オプション<せいすう> {
    もし (せいき("^\\d+$").ヒット(テキスト)) {   // アンカー ^...$：文字列全体が数字のときだけ通す
        かえす あり(せいすう.かいせき(テキスト))     // 数字なら → 成功
    }
    かえす なし                           // 数字でなければ → 失敗
}

メイン() {
    マッチ (点数解析("95")) {
        場合 あり(点数) => ひょうじ("点数：${点数}")
        場合 なし => ひょうじ("数字じゃない")
    }
}
```

**注意事項**：失敗が返り値の一部になり、呼び出し側は**必ず**対処する——例外より「関数型」。**「予期した失敗」**（形式エラー、該当なし、範囲外）に向く。`せいすう.かいせき` には `いれる 標準変換.*` が必要。**失敗の理由**を持たせたければ `オプション<文字列>` を返すか、`あり` の中に独自の列挙を入れる（第 13 章）。

> ⚠️ 実測の注意：`ヒット`（matches）は**包含マッチ**——`せいき("\\d+")` は `"a1"` にも真を返す（部分文字列 `1` にマッチする）！「先に判定してから解析」の書き方には必ずアンカー `^\\d+$` を付けること。さもないと `"a1"` が素通りして `せいすう.かいせき` が例外を投げる（第 10 章の考えてみよう 4、付録 C の落とし穴）。

## 14.4 例外：思いがけないエラーの自動的な上投げ

**定義**：予測できないエラー（ゼロ除算、範囲外、プロトコルエラー）は返り値で 1 段ずつ伝えるのに向かない——例外は呼び出しスタックを**自動で上へ投げられ**、処理できる者がいれば捕まえる。

**四つのキーワード**：

| キーワード | 働き |
|---|---|
| `なげる` | 自ら例外を起こす。関数は即終了 |
| `ためす` | 例外の保護区間を囲む |
| `とらえる` | 指定した型の例外を捕まえ、プログラムを続行する |
| `さいご` | 例外の有無にかかわらず実行する後始末（ファイルを閉じる、ロックを解放） |

**日本語の書き方**：

```jc
関数 わる(ひきゅうじょ: せいすう, じょすう: せいすう): せいすう {
    もし (じょすう == 0) {
        なげる れいがい("除数はゼロにできない")       // 自ら例外を起こす
    }
    かえす ひきゅうじょ / じょすう
}

メイン() {
    ためす {
        おく 結果 = わる(10, 0)
        ひょうじ("結果：${結果}")
    } とらえる (エラー: れいがい) {
        ひょうじ("エラー：${エラー.メッセージ}")   // 指定した例外を捕まえる
    } さいご {
        ひょうじ("成功でも失敗でも実行される")       // 無条件の後始末
    }
}
```

**注意事項**：

- よく使う例外のサブクラス：`算術例外`、`添字範囲例外`、`型変換例外`、`空値例外`、`引数例外`——捕まえるときに必要に応じて細分化する。`とらえる` は上から順に**最初に適合した型**にマッチする（サブクラスを親クラスの前に書く）；
- `なげる` の式の型は `なにもなし`（Nothing）——値が必要などんな場所にも置ける；
- `ためす` には `とらえる` か `さいご` のどちらかが**必須**。`さいご` は `かえす` の**後**に実行される。`さいご` の中に例外を投げうるコードを書かないこと；
- **例外を通常の制御フローに使わない**（性能も読みやすさも落ちる）——14.5 の分担を見よ。

## 14.5 オプション vs 例外：エラー処理の分担

**定義**：判断基準はただ一つ——**この失敗は「予期したもの」か「思いがけないもの」か？**

| 場面 | 選択 | 理由 |
|---|---|---|
| ユーザー入力の解析（数字でないかもしれない） | `オプション` | 入力が千差万別なのは**常態**。呼び出し側の対処が必須 |
| 表引き（キーが存在しないかもしれない） | `オプション` | 該当なしはプログラムのエラーではない |
| ゼロ除算、添字の範囲外 | 先に判定 + 例外で受け皿 | 良いコードはそこに到達すべきでない。到達したらバグ |
| ファイル破損、メモリ不足 | 例外 | 思いがけない事態。呼び出し側には通常予防できない |

**経験則**：`オプション` を返せるなら `オプション` を返す。例外は「**ここは失敗するはずがない**。失敗したらプログラムのバグ」の場面に取っておく。`なければれいがい` は「中身があると確信している。ないのはバグ」の宣言。

## 14.6 前置き検査（たしかめる と手書きチェック）

**定義**：プログラマ自身の自己点検——「ここは間違いようがない」。公式の `たしかめる`（assert）はテストマクロ（`@Test`/`@Expect`——中国語方言の `@测试`/`@期望`。第 15 章）の内部でしか使えない。普通のコードの「不変条件の検査」は手書きの `もし` + `なげる` で代用する。

**日本語の書き方**：

```jc
関数 中間値(データ: はいれつ<せいすう>): せいすう {
    もし (データ.ながさ == 0) {
        なげる れいがい("空リストに中間値はない")    // 前置き検査：先に検証してから仕事
    }
    かえす データ[データ.ながさ / 2]
}

関数 年齢検査(年齢: せいすう): せいすう {
    もし (年齢 < 0 || 年齢 > 150) {
        なげる れいがい("年齢が不適切：${年齢}")
    }
    かえす 年齢
}

メイン() {
    ひょうじ(年齢検査(30))
    ひょうじ(中間値([1, 2, 3]))
    // ひょうじ(年齢検査(-5))   // 例外を投げる
}
```

**注意事項**：前置き検査は**ロジックエラーを早く見つける**助けになる（エラーが変な現象に化けて広がるよりずっと良い）。だが**入力の検証に検査を使わない**こと——ユーザー入力は `オプション` か例外で丁寧に扱う。検査は「プログラム自身が間違えた」という合図。

## 14.7 しゅうりょう（退出 / exit）

**定義**：プロセスを即終了させる：`しゅうりょう(ステータスコード)`——0 は成功、非 0 は失敗。ステータスコードで呼び出し側（スクリプト/CI）が成否を知る。

**日本語の書き方**：

```jc
いれる 標準環境.*

メイン() {
    おく 構成 = よみこむ()
    もし (構成 == "") {
        ひょうじ("構成がない")
        しゅうりょう(1)              // 致命的エラー：プロセス終了、ステータスコード 1
    }
    ひょうじ("構成：${構成}")
}
```

**注意事項**：`しゅうりょう` は `なにもなし` を返す（決して戻らない）。終了前の `さいご` ブロックは**実行されない**（プロセスが直接終わる）——後始末が必要なら先に手で行う。`しゅうりょう` は「続行不可能」の最終手段。濫用しない。

## 14.8 並行入門：うむ

**定義**：**並行タスク**を起動する：`うむ { タスクのコード }`——「このコードを別の実行コンテキストで走らせる」を関数呼び出しのように包む。

**日本語の書き方**：

```jc
メイン() {
    うむ { ひょうじ("タスク1") }
    うむ { ひょうじ("タスク2") }
    ひょうじ("メイン")
}
```

**注意事項**：出力の順序は**不定**（三つのタスクが並行に走る。誰が先に表示してもおかしくない）。`うむ` はタスクのハンドルを返す（完了を待てる）。**並行で共有する可変データは必ず同期が必要**（14.9/14.10 参照）——これは並行バグの最大の発生源。

## 14.9 同期：クリティカルセクション

**定義**：複数のタスクが同じ `変数` データを同時に変えると**データ競合**が起きる（中途半端な値の読み取り、更新の喪失）。`同期(ロックオブジェクト) { クリティカルセクション }` がコードブロックをロックする——同時刻に 1 つの実行コンテキストしか入れない。

**日本語の書き方**：

```jc
いれる 標準同期.{ロック}

変数 かず = 0

メイン() {
    おく カギ = ロック()
    同期(カギ) {
        かず += 1        // クリティカルセクション：同時刻に 1 タスクだけが変更する
    }
    ひょうじ(かず)
}
```

**注意事項**：

- `同期` には**必ずロックオブジェクトの引数が必要**（1.0.5 実測——`同期 { }` だけではダメ）；
- **ロックは小さく**：クリティカルセクションは短いほど良い。**同期の入れ子にしない**（デッドロックの危険）；
- **不変データ（`おく`）は同期が不要**——これが「デフォルトで不変」の並行ボーナス。

## 14.10 ロックと原子操作

**定義**：もっと細かい粒度の並行プリミティブ：`アトミック整数`（AtomicInt64）、`原子参照`（AtomicReference）、`原子真偽`（AtomicBool）、`ロック`（Mutex）。原子操作はロックなしの「安全な増減」——同期ブロックより速い。

**日本語の書き方**：

```jc
いれる 標準同期.*

メイン() {
    // 原子カウント：複数タスクで安全に増減
    おく アトカウント = アトミック整数(0)
    うむ { アトカウント.たしとる(1) }        // たしとる = fetchAdd
    うむ { アトカウント.たしとる(1) }
    ひょうじ("原子カウント：${アトカウント.ロード()}")   // ロード = load（タスクの完了を待たないので値は実行ごとに変わる：0 や 1 や 2）

    // ロックの明示的な使い方：かぎ / あけ（対で現れる）
    おく カギ2 = ロック()
    カギ2.かぎ()
    カギ2.あけ()
}
```

**注意事項（1.0.5 の実測の真実）**：

- 方言のモジュールパス：`いれる 標準同期.*`；
- **整数の原子だけが算術をサポート**（`たしとる` = fetchAdd）。`原子参照`/`原子真偽` は読み書きと交換のみ（`ロード`/`ストア`/スワップ）；
- `原子参照` は**参照型しか受け付けない**（クラスオブジェクト）——`文字列` などの値型を渡すとコンパイルエラー；
- `ロック().かぎ()`/`あけ()` のあけ忘れはフリーズのもと——`ためす`/`さいご` で解放を保証する（`ためす { カギ2.かぎ(); ... } さいご { カギ2.あけ() }`）；
- 公式の `再入ロック`（ReentrantMutex）は非推奨——統一して `ロック`（Mutex。それ自体が再入可能）を使う。

## ✳ 設計思想

**① エラー処理は「設計判断」であって「文法」ではない**：まず失敗の場面ごとに分類する——予期した失敗（入力、該当なし）は `オプション`、思いがけないエラー（バグ、環境）は例外。この分類が API の形を決める——良い API は「正しい使い方は簡単に、間違った使い方は不可能に」する。

**② Fail fast（速やかに失敗する）**：`なければれいがい()` も `なげる れいがい("...")` も「間違えたらすぐ大声で言う」——エラーは早く露呈するほど直しやすい。エラーを飲み込む（`とらえる` して何もしない）のが最も危険なコード。

**③ 前置き検査：良い関数は先に検証してから仕事をする**：関数の最初の仕事は引数の妥当性チェック（防御的プログラミング）。

**④ デフォルトで不変は並行のボーナス**：`おく` で束縛したデータは並行に変更されない——ロック不要、データ競合なし。並行プログラムではどんどん `おく` を使い、本当に共有する可変状態だけに `同期`/原子操作が必要。

**⑤ クリティカルセクション最小化**：ロックの範囲が小さいほど並行度が高い。「読み取りだけの計算」をクリティカルセクションの外へ出し、本当に共有状態を変える数行だけをロックする。

## 練習

1. `オプション` で「添字から配列要素を取る」を実装しよう：範囲外なら `なし` を返す（例外にしない）；
2. `ためす`/`とらえる` で整数の割り算を包み、ゼロ除算のとき親切なメッセージを表示しよう；
3. `解析整数` 関数を書こう：正しい入力には `あり(数)` を、間違った入力には `なし` を返す（ヒント：`せいき("^\\d+$").ヒット` で判定——アンカーを忘れずに。`\\d+` 自体は包含マッチ）；
4. `うむ` で 3 つのタスクを起動し、それぞれ 1..3 を表示させて、出力の順序が決まるか観察しよう。次に `同期(カギ)` で表示を包んで順序の変化を見よう；
5. 考えよう：なぜ `オプション` の値は直接 `+ 1` できないのか？この設計はあなたを何から守っている？

## まとめ

- `オプション<T>` + `あり`/`なし` がヌルポインタを撲滅する。`マッチ` で網羅処理、`なければきてい` で受け皿、`なければれいがい` で確信の取り出し；
- 予期した失敗は `オプション`（公式に Result なし）。思いがけないエラーは `ためす`/`とらえる`/`さいご`/`なげる`。例外を制御フローに使わない；
- `しゅうりょう(ステータスコード)` がプロセスを終了（`さいご` は実行されない）。前置き検査は手書きの `もし` + `なげる`；
- 並行：`うむ` でタスクを生み、`同期(カギ)` でクリティカルセクションを守り、`アトミック整数` でロックなしのカウント。`原子参照` は参照型しか受け付けない；
- 実行時出力は公式形式のまま（`真` → `true`）。
